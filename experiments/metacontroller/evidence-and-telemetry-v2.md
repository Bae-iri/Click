# 완료 증거·실패 계측 v2 검증

기존 v1 결과 파일과 사전 프로토콜은 보존한다. v2는 같은 합성 화면 상태 기계를 사용하지만 완료 증거의 수명과 실패 계측을 변경하므로 v1과 같은 구현으로 표기하지 않는다. 실제 앱의 속도나 중장년층 효과를 검증하는 실험은 아니다.

구현과 검증 결과는 [완료 증거·실패 계측 보완 보고서](../../docs/reviews/2026-11-20-evidence-telemetry/report.md)에 보존한다.

## 요청마다 남는 실패 기록

시험 전용 파사드는 모든 POST 시도에 `request_terminal` 기록을 남긴다. JSON 규격 오류, 허용되지 않은 화면, 인증·경로 오류, 서비스 예외, 응답 전송 실패도 포함한다. 원문 목표·화면·모델 응답·오류 메시지·토큰은 저장하지 않는다.

- `request_ref`, `task_ref`: 요청과 작업 ID의 SHA256 앞 24자. 클라이언트도 같은 값을 저장해 직접 결합한다. 본문을 해석할 수 없는 경우에도 정상 형식의 해시 헤더가 있으면 연관을 유지하며, 서버가 별도 `server_ref`를 만든다.
- `http_status`, `error_code`: HTTP 결과와 고정 목록의 거절 이유. 서비스가 반환한 이유·단계·종류도 별도의 고정 코드만 보존한다.
- `service_state`: 호출 전 거절인지, 서비스가 정상 반환했는지, 호출 중 예외가 났는지 구분한다.
- `model_call_state`: `not_started`는 확인된 0회, `observed`는 기록된 모델 시도, `unknown`은 호출 여부를 확정할 수 없는 경우다. 서비스 진입 후 기록 없는 예외를 0회로 바꾸지 않는다.
- `response_delivery`: 서버가 응답을 썼는지, 클라이언트 연결이 끊겼는지 구분한다. 클라이언트가 응답을 받지 못했더라도 서버의 모델 기록은 감사에 포함한다.

현재 관찰 노드는 여전히 고정된 공개 시험 컨트롤만 허용한다. 모델이 제안한 미래 완료 라벨은 현재 관찰과 구분하고, 동일 패키지·제한된 길이·공개 텍스트·민감하지 않은 리소스 규격으로 검사한다. 새로운 미래 별칭이라는 이유만으로 거절하지 않으며, 실제 관찰의 허용 목록을 넓히지도 않는다.

## 직접 대조와 불확실성

JVM v2 에피소드는 요청별 해시·HTTP 상태·제한된 실패 이유·모델 호출 관찰 상태를 `request_traces`에 저장한다. 공급자 감사는 각 요청을 정확히 결합하며 누락·중복·고아 기록·작업 ID 불일치를 오류로 처리한다. v1 자료만 주어지면 기존의 순서 기반 감사와 한계를 그대로 유지한다.

직접 결합이 끝나도 모델 호출이 `unknown`인 요청이 있으면 총 호출 수를 확정하지 않는다. 확인된 호출은 하한으로 표시한다. 요청 결합이 성공했다는 사실과 모델 결과가 건강하다는 사실은 별개다. 모델 실패가 남은 결과로 속도·비용 우위를 승인하지 않는다.

## 검사 범위

기본 행렬은 여전히 6작업 × 3조건 × 2반복 × A/B = 72회다. 준비 검사에는 현재 메뉴 거절, 목적 상태 인정, 같은 화면 실행·변경/보호 화면 거절, 가상 시계 일치를 유지한다.

짧은 연결 검증은 아래 환경 변수로 선택할 수 있다. 부분 실행은 `preflight_subset`으로 기록하며, 전체 72회 행렬을 요구하는 성능 분석 게이트를 통과할 수 없다.

```text
CLICK_META_CLOSED_LOOP_OUTPUT=/private/tmp/<새 출력 경로>
CLICK_META_CLOSED_LOOP_MODE=live
CLICK_META_CLOSED_LOOP_ENDPOINT=http://127.0.0.1:8767/api/v1/agent/app-guide/task
CLICK_META_CLOSED_LOOP_CONDITIONS=normal
CLICK_META_CLOSED_LOOP_REPETITIONS=1
```

이는 여섯 정상 작업 × 한 반복 × A/B = 12회다. 특정 작업은 `CLICK_META_CLOSED_LOOP_TASKS=nested_advanced,open_search`처럼 선택한다. 선택되지 않은 조건의 회복 효과를 주장하지 않는다. 가상 UI 대기와 실제 모델 응답 시간은 계속 분리한다.

모델 호출 없이 서버의 403·422·500·본문 시간 초과·응답 전송 실패와 직접 결합을 검사할 수 있다. 실제 모델을 사용할 때에는 소스·설정 해시를 먼저 고정하고, 전체 원시 기록과 미해결 요청을 보존한다.
