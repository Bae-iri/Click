# 실제 공개 앱 3종 비교 — 사전 프로토콜 v1

범용성을 첫째, 속도를 둘째 목표로 한다. 실제 사전 설치 앱 세 개에서 두 목표씩, 같은 공개 탐색 도구와 공통 완료 경로를 사용하는 A와 B를 비교한다. 실행 소스는 모든 준비와 원인별 검사를 마친 뒤 모델 요청 전에 고정한다. 기존 Settings v1/v2 소스·사전 기준·원자료·보고서는 수정하지 않는다.

## 실제 관찰을 먼저 고정

후보 앱은 Settings, Clock(`com.google.android.deskclock`), Files(`com.google.android.documentsui`)다. 계정 없는 격리 에뮬레이터에서 모델 없이 실제 native 접근성 정보를 관찰한다. 설치 여부만으로 지원됐다고 표시하지 않는다. Files에 공개 탐색 경로나 독립 목적 판정이 없으면 모델 호출 전에 Chrome 대체 여부를 결정하고 그 이유를 기록한다. 목표·라벨·리소스·GUI 경로를 결과를 본 뒤 교체하지 않는다.

`MetaControllerPublicAppsExperimentTest.probePublicApps`는 각 앱의 홈을, `probeCurrentPublicApp`은 root가 직접 연 목적 화면을 관찰한다. 경로는 package와 window 해시로 범위를 구분한다. 공개 라벨·리소스·클래스·역할·가시성·실행/선택/체크 상태를 기록하되 입력값·비밀번호와 문서 목록의 항목 라벨은 저장하지 않는다. 개인 파일을 열거나 생성·삭제하지 않는다. Files에 실제 문서 항목이 보이면 해당 상태를 지원되지 않는 것으로 표시하고 내용을 검사하지 않는다.

탐색 준비는 접근성 서비스를 유지하는 동일 Session 안에서 수행한다. 서비스가 꺼진 사이 생성된 목록 행은 실제 측정 때와 native 접근성 동작이 다를 수 있다. `probeResetHome`과 신뢰된 정확 selector의 `probeNavigation64`는 이 차이를 확인하는 준비 도구이며, 변경하지 않은 생산 native 실행기만 사용한다. 기본·각 GUI 단계에서 생산 `AppTaskObservation`이 public이고 필요한 native 탐색 노드가 실제로 존재해야 한다. 독립 UI 트리의 라벨만 보고 생산 실행 가능으로 표시하지 않는다.

[카탈로그 스키마](native-public-apps-catalogue.schema.json)에 맞춰 앱별 공개 관찰 허용 범위와 탐색 selector를 고정한다. 태스크는 package, 한국어 목표, 공개 시작 복원 경로, GUI 경로, 독립 oracle 체크를 가진다. 각 앱에서 정확히 두 태스크, 전체 여섯 태스크다. task ID는 중복되지 않아야 하고 각 task package는 앱 목록에 있어야 한다. 앱별 selector는 공개 label/resource 조합이며 실제 비입력·비체크형 button/tab 탐색만 승인한다. 공개 상태를 읽는 권한이 그 상태를 바꾸는 권한은 아니다.

스크롤도 실제 `role=list`, `scrollable=true`, 비입력 노드와 카탈로그의 정확 label/resource 조합이 모두 맞을 때만 허용한다. 읽을 수 있는 목록 전체를 조작 가능으로 간주하지 않는다. 값 조절형 리소스는 탐색 selector에서 제외한다. 복구·진행 구조의 카운터는 별도 기록하며 실제 모델 호출 수로 세지 않는다.

독립 oracle은 고유한 비행동 목적 제목·공개 landmark 또는 실제 selected/checked 상태를 조합한다. 메뉴의 존재만으로 목적 상태를 판정하지 않는다. Clock의 요청된 탭 selected=true는 적법한 목적 증거이며 타이머·알람을 실제로 시작하거나 저장하지 않는다. oracle과 GUI 정답 경로는 연구용 준비·평가에만 사용하며 플래너에 전달하지 않는다. 생산 실행 코드에 앱별 성공 규칙을 추가하지 않는다.

## 공통 개선과 B2 차이

두 팔 모두 현재 native 화면에서 안전하게 일치하는 읽기 전용 완료 후보를 재검증하고, 완료의 두 프레임은 같은 native window와 단조 시계의 350ms 간격을 만족해야 한다. 오래된 조작·계획은 재사용하지 않는다. 초기 명시적 요청과 로컬 완료 검증은 즉시 처리하고, 화면 전환 뒤 자동 유료 재계획만 짧게 병합한다. 두 새 프레임의 조작 대상·상태·좌표가 250ms 안정되는지 보며 최초 대기부터 1,000ms를 넘겨 이벤트 폭주로 미루지 않는다. 실행 승인은 기존 전체 지문·창·대상 검사를 유지한다.

A는 CURRENT다. B2는 `mc_v1`이며 실제 native 조작 대상·상태의 안정된 전환을 두 새 프레임에서 관찰하면 최신 화면으로 재관찰한다. 이 전환은 단계나 목표의 검증이 아니며 진행 비트를 올리지 않는다. 미검증 subgoal별 전환 재관찰은 최대 두 번이고 순환을 제한한다. 수락됐지만 효과가 불확실하면 로컬 관찰을 기존 절대 상한 8초까지 유지하며, native 검증은 그 전에 바로 통과할 수 있다. 진짜 무반응에서는 기존 5초보다 기다림이 늘어날 수 있다.

진전 없는 같은 의미 경로·미검증 subgoal에서 실패 복구용 요청은 한 번만 허용한다. 반복 이벤트나 오래된 응답 폐기로 이 상한을 우회하지 못하게 실제 요청 전송 직전에 예약하며, 작업 전체 실패 복구 요청 상한은 세 번이다. 읽기 전용 완료 증거 발견은 이 조작 복구 예산과 분리한다. 탭·입력·뒤로가기·토글을 자동 재실행하는 국소 수리는 추가하지 않는다. 전환 재관찰과 실패 복구의 이유·정책을 실제 공급자 시도와 연결해 집계한다.

비용은 확인된 API 시도와 공급자가 보고한 입력·출력·추론·총 토큰을 각각 집계한다. 토큰 정보가 없는 timeout은 0토큰으로 바꾸지 않는다. 관측 합계·정보가 있는 시도 수·미확인 시도 수를 함께 공개한다. 단가·캐시 청구를 연동하지 않으므로 이를 금액으로 표현하지 않는다.

## 배정과 준비 gate

세 앱 × 두 목표 × 정상/첫 유효 TAP 수락 후 무효/첫 유효 TAP native dispatch 5,500ms 지연 × A/B 한 번 = **36회·18쌍**이다. 쌍별 A/B 순서를 교차 배치하고 전체 일정을 먼저 고정한다. 정상 12회는 전체 36회에 그대로 포함하며 재선택하거나 중복 실행하지 않는다.

각 태스크는 시작 복원 뒤 알려진 음성 상태와 실제 GUI 경로를 거친 양성 상태를 통과해야 한다. 지원되는 공개 목적 Intent는 준비의 추가 양성 대조에만 쓸 수 있으며 측정 중 직행 도구로 제공하지 않는다. 이미 목표인 탭이 재실행 때 남을 수 있으므로 task의 `start_path`로 항상 같은 비목적 상태를 복원한다. 시작 상태의 의미 지문과 측정 context를 A/B 쌍별로 비교한다.

공개 화면 native 실행 수락·다른 화면/창의 오래된 조작 거절·보호 입력 화면 거절을 모델 없이 확인한다. 보호용 test APK는 네 번째 평가 앱으로 세지 않는다. 설정값과 fixture 입력/카운터 불변도 확인한다. 준비 실패·불명확 판정을 false나 성공으로 바꾸지 않는다.

## 공통 관찰·시간 기준

기존 v2와 같은 실제 30,000ms 관찰 창, 목적 상태 700ms 안정, 조작 후 750ms 대기, 현재 검증·미처리 native 조작 없음의 공동 성공을 사용한다. 첫 안정 도달·첫 현재 검증·공동 성공 시각을 분리한다. 실제 접근성 이벤트만 전달하고 독립 poll을 화면 이벤트로 만들지 않는다. terminal 표시 상태가 되어도 공동 성공 전에는 독립 관찰을 예산까지 유지한다.

불명확 oracle 관찰은 안정 확인을 끊고 알려진 음성으로 바꾸지 않는다. 예산 안에 끝난 poll의 총/알려짐/불명확 횟수와 마지막 시각을 기록한다. 공동 성공만 예산 전에 종료할 수 있다. 이후 native/provider 정리는 별도 기록하며 `goal_present_after_cleanup`를 최초 도달 시각이나 예산 내 성공으로 사용하지 않는다.

무효·지연은 실제로 적격인 첫 native TAP에만 적용한다. 미도달로 장애를 주입하지 못한 시행도 배정 분모에 남긴다. 지연 예약 뒤 native 검사가 거절되면 실제 지연 노출로 세지 않는다. 이미 처리 중인 조작이 남아 있을 때 추가 native 승인을 막는다. A/B의 실제 복구 정책 차이는 source freeze에 명시하며 계측 중 변경하지 않는다.

주 지표는 예산 내 독립 목적 안정·현재 `verified` 제시·미처리 native 조작 없음이 함께 성립한 비율이다. 단순 도달·과거 검증 제시·복구 활성화는 각각 보조 지표다. 실패 포함 시간은 성공 시 공동 시각, 나머지는 30초로 한다. 모델/공급자 실패와 허용되지 않는 제안도 성능 결과로 보존한다. 예정·실행·평가 가능·미확인 분모를 모두 보고한다.

## 실행 경계와 동결 순서

격리 application ID는 `com.click.metaexperiment.publicapps`, loopback facade는 port 8769, 로컬 토큰은 `local-meta-public-apps-experiment`, app 출력은 `files/public-apps-meta-v1`이다. schema는 `click.native-public-apps.v1`, evidence mode는 `live_native_public_apps`, 측정 개정은 `equal_independent_observation_window_public_apps_v1`이다. guard schema는 `click.native-public-apps-guard-readiness.v1`이다. 앱별 공개 읽기 범위와 실제 탐색 capability를 서버에서 모델 호출 전에 적용하며 독립 완료 증거용 공개 상태는 보존한다.

**소스 commit/tree·코드 해시·APK 해시·환경·카탈로그·준비/guard·전체 manifest의 동결 기록을 모두 완성한 다음에만 `--allow-live` facade를 시작한다.** 동결 helper는 모델 서비스 import에 의존하지 않는 순수 파일 해시 수집을 우선한다. 파일 조립이 실패하면 정상 측정 실행으로 진행하지 않는다. 기록 완료와 실제 시각을 확인하며 terminal 0건을 진행 중인 모델 요청 0건의 근거로 삼지 않는다.

정상 12회가 끝나면 같은 시작·oracle·시간·안전·직접 요청 결합을 감사한 뒤 장애 24회를 같은 일정에 추가한다. 알려진 성능 실패만으로 자료를 버리지 않는다. 안전 사건이나 계측 문제가 있으면 중단 이유와 미실행 배정을 남긴다. 클라이언트와 서버를 요청·작업 해시로 직접 결합하며 서비스 전 0회·확인된 시도·unknown을 구분한다. HTTP 거절 이후에 이미 발생한 모델 시도도 비용에 포함한다.

## 해석

앱별 결과와 전체 결과를 함께 보고해 한 앱의 성공으로 다른 앱의 실패를 숨기지 않는다. 실제 두 팔 모두 장애에 노출된 쌍을 별도로 비교한다. 세 앱은 단일 Settings보다 넓은 기술 범위이지만 미관측 앱 전체의 일반성·통계적 우월·중장년층 사용성을 입증하지 않는다. 이전 cohort와의 변화는 공통 코드·정책·앱 구성·공급자 응답이 함께 바뀐 기술 비교이며 특정 구성 요소의 인과 효과로 배분하지 않는다.

다음 반복 검증으로의 기술 GO는 전체 36회·안전·계측·호출 수가 평가 가능하고, B가 전체와 각 앱에서 공동 성공을 줄이지 않으며, 실패 포함 평균 시간과 API 시도가 A보다 늘지 않고, 세 지표 중 하나는 엄격히 개선된 경우에만 검토한다. 실제 양팔 장애 노출에서 B 단독 공동 성공도 최소 한 쌍 필요하다. 충족하지 못하면 비용·시간·성공의 상충을 공개하고 개선을 보류하거나 원인을 좁힌다. 어느 결과에서도 이 한 번의 기술 실험만으로 B 기본 적용이나 중장년층 효과를 GO로 선언하지 않는다.
