# CLICK 범용성·속도·실패 처리 평가 설계

평가 소스는 `5dd53e6274cd9dbffd715d0c1c2c38e6f5db1841`이다. 아래 조건을 새 측정 전에 정했다.

| 실험 | 배정 | 독립 판정 및 시간 |
| --- | --- | --- |
| 승인된 그래프의 실행 가능 범위 | 저장소 카탈로그 전체 | 빈 로컬 DB에 정식 릴리스를 로드한 뒤 각 항목의 앱·목표·슬롯으로 제품의 선택기를 호출한다. 그래프를 고를 수 있다는 것과 실제 기기에서 끝까지 성공했다는 것을 구별한다. |
| 한국어 요청과 공개 화면 | 가상 앱 4종 × 명시적 표현과 일상어 × 2회. 같은 계약에 실제 목표 상태와 비슷한 오답 상태를 각각 제시한다. | 결과 확인 API가 요청한 모든 근거를 반환한 경우를 정답으로 센다. 오답 화면에서의 완료 제안, 준비 실패, 응답 시간과 외부 호출을 별도로 기록한다. |
| 갤럭시 설정 | 디스플레이·소리 및 진동·알림 × 정상 도착·중간 예측 오류 후 도착·5.8초 지연 도착·제자리·다른 화면·실행 거절 = 18회 | Android의 실제 전경 Activity를 정답으로 삼는다. 컨트롤러 승인부터 기기 완료 판정 또는 첫 사용자 인계까지 재고, 실행기 호출과 사용자 최종 확인도 센다. 전 화면 이동은 시험기가 통제한다. |
| 갤럭시 시계 | 세계시각 → 스톱워치 2회. 한 번은 승인 후 설정 앱으로 전환했다가 뒤로 돌아온다. | 중단 중 완료 제시, 복귀 후 확인 시간, 중복 탭과 재실행을 확인한다. 기존 기기 시험의 원래 시계 탭 복원 절차를 사용한다. |

한국어 실험은 서재의 책갈피 탭, 교통 시간표, 날씨 강수 알림 끄기, 팟캐스트 보관함 열기와 자동 다운로드 끄기다. 오답은 다른 탭이 선택됨, 목적지 이름이 메뉴에만 있음, 다른 알림만 꺼짐, 복합 목표의 스위치만 미충족인 상태다. 입력 문장·화면·기대 증거는 [실행 코드](probe.py)에 고정한다. 순서 효과를 줄이기 위해 두 번째 블록에서 표현 순서를 뒤집고 목표 화면과 오답 화면의 순서도 교차한다.

로컬 FastAPI 앱의 정식 `/api/v1/agent/app-guide/task` 경로를 사용한다. 요청마다 10초 예산을 부여하고 실제 OpenRouter Qwen에 전송하는 재료는 합성한 문장과 공개 UI뿐이다. 인증·DB 왕복·단말 전송·오버레이 렌더링은 이 시간에서 빠진다. 서비스에 완료 조건 준비를 요청한 후 같은 작업에서 화면을 하나씩 독립적으로 심사한다. 준비 실패는 원래 배정에 남기고 후속 화면은 미실행으로 기록한다. 시간은 단조시계를 사용하며 외부 호출의 시간과 개수를 따로 기록한다. 결과 확인은 단말의 최종 검증 전 단계다.

갤럭시 시험에는 독립 패키지와 저장소의 `GoalOutcomeDeviceTest`를 사용한다. 설정값을 바꾸지 않는 세 화면의 도착 검증에 집중한다. 기기와 서버 실험은 성공률 분모를 공유하지 않는다. 표본은 의도적으로 고른 소규모 사례이며 사용자 모집단의 성공률 추정에 사용하지 않는다.

### 시계의 추가 진단

원래 시험에서 ‘뒤로’ 한 번으로 스톱워치가 돌아오지 않은 후, 같은 시험의 전경 Activity를 외부에서 관측하는 진단을 추가했다. 이어 별도 조건에서는 ‘뒤로’를 누르는 자리에 Android 런처 인텐트로 기존 시계 작업을 앞으로 가져온다. 목적 탭을 다시 누르지 않는다. 동일한 공개 스톱워치 탭이 4초 안에 돌아오는지, 그 뒤 3.5초 안에 컨트롤러가 완료를 확인하는지, 실행 탭이 여전히 1회인지 검사한다. 정상·중단 각 1회를 새로 배정한다. 두 진단은 원래 시행 수와 분리한다.
