# 후속 비교와 실패 원인 수정 (2026-11-23 새벽, Windows 재개)

Galaxy Note20 1대, 로컬 격리 서버, 실제 Jev, `run_compare.py` 하네스(75초, 요청부터 판별 가능 화면까지). 값은 모두 **자동 수집한 판별 가능 후보(`judgment_ready_candidate`)** 기준이며, 후속·수정 라운드의 화면 PNG 검토는 아직 하지 않았다(`screen-review.json` 없음). 본 비교 78회와 합산하지 않는다.

## 1. 후속 비교 (protocol.md의 `followup/`, 16과제 × 2정책 = 32회)

develop `32636ab7` 그대로, 친구 Codex가 설계한 조건. APK는 `apk-sha256.txt`.

| 정책 | 판별 가능 후보 | 실패 |
|---|---:|---|
| 기존 정책 (baseline) | 10/16 | 도움 요청 5, 시간 초과 1 |
| guarded_v2 | 11/16 | 도움 요청 4, 시간 초과 1 |

벨소리는 친구의 소리 선택기 판정 수정으로 두 정책 모두 성공했다(본 비교에서는 시간 초과). 정책 간 차이는 Wi-Fi 1건뿐이다.

## 2. 실패 원인 (기기 로그와 진단 로그)

| 원인 | 영향 과제 | 근거 |
|---|---|---|
| Jev 페이지 확신도 부족 | 밝기, 화면 크기, 편안하게 화면 보기, 글자 크기 | 대상 지지 0.91–0.96인데 page 0.66–0.78. 페이지 선택지가 `예상 페이지 + unknown_page` 2개면 정규화로 0.86 → 0.72가 된다. One UI 설정 홈은 스크롤하면 큰 '설정' 제목이 접혀 이름 근거가 사라진다. |
| 자동 탭 가림 판정 순환 | 알림 소리, 화면 크기 | 행 [0,1658,1080,1884]의 중앙을 접힌 안내창 [315,1741,1046,1922]이 덮음 → 창 접기 → 100ms 재확인이 새 관찰 때문에 stale → 같은 안내는 중복 표시로 걸러져 다시 시도하지 않음 → 75초 초과. 이 탭은 실제로는 접근성 클릭이라 오버레이에 막히지 않는다. |
| 설정 목록 첫 스크롤 방향 | 첫 화면 아래 메뉴 전반 | 삼성은 맨 위에서도 backward 가능으로 보고해 위쪽부터 2턴을 쓴다. 아래쪽 접근성 스크롤은 실제로 움직였다(앞선 '안 내려감' 진단은 위쪽 시도였다). |
| 기기 동작 기록 미확인 | 밝기 ± | '디스플레이' 탭이 서버 검증 SUCCESS를 받지 못해 `issued`로 남고, 다음 드래그에서 `화면이 바뀌었는지 확인해 주세요.` 도움 요청. **안전 장치 영역이라 고치지 않음.** |
| Jev 후보 선택 확신도 | 방해 금지, 청각 보조(최종 라운드 1회) | `both_below_minimum`. 정책 영역이라 고치지 않음. |

## 3. 수정 (브랜치 `fix/settings-list-scroll`, 정책·임계값 변경 없음)

- `Backend/app/services/jev_screen_judgments.py`: Android 설정 페이지 선택지에 그래프의 `optional_keywords`를 `page_keywords`로, 설정 홈에 접히는 제목 설명을 `meaning`으로 넣는다. 최소 신뢰도 0.8과 정규화 식은 그대로다.
- `ClickOverlayService`: 접근성 클릭이 가능한 대상은 중앙 가림 사전검사를 건너뛴다. 좌표 제스처 대체 경로는 `ClickAccessibilityService`에서 계속 가림을 검사한다. 가림 재확인이 stale이면 표시 중복 기록을 지우고 새 관찰을 요청한다.
- `NativeScrollExecutor`: 접근성 스크롤 뒤 보이는 행이 그대로면 같은 목록을 한 번 스와이프한다.
- 진단 빌드(`CLICK_CANDIDATE_DIAGNOSTICS`)에서만 자동 조작 생략 사유를 로그로 남긴다.

검증: Android 단위 테스트 전체 통과, Backend Jev·설정 테스트 220개 통과(넓은 범위 1,940개 통과. 49개 error는 Windows `pytest-of-leezo` 임시 폴더 권한 문제로, 변경 전에도 동일).

## 4. 수정 라운드 (모두 기존 정책 baseline)

| 폴더 | 내용 | 결과 |
|---|---|---|
| `scrollfix/` | 스크롤 보정만 | 13과제 중 5. 실패 과제 개선 없음 |
| `diag/`, `diag2/` | 진단 로그 | 원인 특정용, 성공률로 쓰지 않음 |
| `pagefix/` | + 페이지 근거 | 8과제 중 4. **글자 키우기·편안하게 화면 보기 첫 성공**, page 확신도 0.88–0.98 |
| `fix3/` | + stale 재시도 | 6과제 중 2. 알림 소리·화면 크기는 가림 순환 계속 |
| `fix4/` | + 접근성 클릭 가림 예외 | **4/4** (알림 소리, 화면 크기, 벨소리, 편안하게 화면 보기) |
| `final/` | 최종 빌드, 후속과 같은 16과제 | **11/15** (블루투스 1건은 시작 전 설정 홈 확인 실패로 도구 제외) |

후속 baseline과 같은 16과제 비교: 10/16 → 11/15. 화면 크기·알림 소리·Wi-Fi가 새로 성공했고 청각 보조 1건이 Jev 선택 확신도로 실패했다. 한 과제 1회씩이라 차이는 작은 표본이다. 같은 기기라도 날짜·모델 확률 변동이 섞인다.
