# 2026-11-23 설정 재질문 정책 실기기 비교

## 목적과 판정

제품의 자동 완료 선언 대신 **목표 화면/값에 도착하고, 사용자가 확인할 공개 제목/조절기가 가리지 않은 상태로 1초 유지되는 시점**을 측정한다. `passed`는 구 하네스 필드이며 새 성공 지표로 사용하지 않는다. 네이티브 목표와 `judgment_ready_candidate`를 자동 수집하고, 첫/마지막 공개 영역 PNG를 따로 검토한다. 값 변경은 OS 값 증가/감소도 요구한다. 검토가 끝나기 전 `judgment_ready_success`는 null이다.

## 사전 진단과 본 비교를 분리

- `pilot`: 초기 4건. 기존 앱 완료 신호를 사용하지 않는 하네스 확인.
- `dispatch-pilot`: 6건. 탭 방법 및 실행 후 변화 진단.
- `geometry-pilot`: 3건. 공개 설정 제목과 실제 안내창 좌표 진단.
- 위 13건은 수정 전 도구/앱 조건이며 본 비교에 합산하지 않는다. 특히 삼성 벨소리는 별도 시스템 앱 `com.samsung.android.secsoundpicker`가 열리는 것을 분리 터치로 확인했다. 초기 판정기는 이를 누락했으므로 실패 원인에 평가 도구의 누락 가능성을 기록한다. 과거 기록을 성공으로 소급 변경하지 않는다.

## 본 비교: 26과제 × 3정책 = 78시행

- B retry: `origin/feat/settings-scroll-jev-retry`, `4fca0099`의 원래 실험 정책.

- 시행 제한 75초. 명시적 도움 요청이 2초 유지되면 실패. 실패/제외/시간 초과도 모두 보존한다.
- 시행마다 격리 계정을 새로 쓰고 삭제한다. 시스템 글자/밝기/미디어 음량은 원래 값으로 복구한다. 공개 메뉴 제목/좌표와 진단 hash/수치만 저장하며 전체 화면/개인 목록은 저장하지 않는다.

## 하네스 사전조건 보정

최초 본 비교 시도는 4건 모두 요청 전 `INITIAL_TOP_NOT_CONFIRMED`로 중단됐다. 목록 맨 위에서도 Android가 backward action을 true로 반환해 이를 경계 도착으로 사용할 수 없었다. `precondition-rejected/`에 보존하며 실제 과제 시행/성공률 분모에서 제외한다. 중단된 다음 1건은 결과 파일이 없어 미시행으로 기록한다. 이후 Settings 프로세스를 새로 시작하는 사전조건으로 교체했다.

## 실행 기반 시설 중단

원래 retry 정책의 notification_sound 시행에서 instrumentation이400초 동안 최종 결과를 돌려주지 않았다. 당시 진단 프로세스의 종료 사유는 후속 cleanup instrumentation의 force-stop이며, 별도 crash/ANR 근거는 확인되지 않았다. 결과 미확정 시도로 infrastructure/에 보존하고 동일 APK/정책 조건으로 재실행한다. 호스트 watchdog만180초로 단축했다(과제 제한75초는 동일). 완료된 시행과 불확정 시도 수를 따로 공개한다.

## 후속 수정안 비교 (본 비교 완료 후 별도 실행)

- `followup/`: 실패가 알려진14과제 + screen_timeout/volume.decrease =16과제 × 기존 정책/guarded_v2 =32시행. `followup-tasks.txt` 목록. 같은 문구 인덱스0, 같은 요청/승인/판별 조건과75초 제한이다. 두 정책의 순서를 과제마다 번갈아 실행한다.
- 두 정책 모두 새 Android 수정 APK를 사용한다. 명시적 재관찰이 목록 스크롤로 새는 우회를 막고, 요청한 시스템 벨소리/알림 소리 선택기의 공개 제목을 확인하면 그 화면을 유지한다. unrelated OS 값 변경만으로 tap 관찰 증거를 만들지 않도록 보완했다.
- guarded_v2는 본 비교 C1과 동일한 제한 정책이다. 실험 그래프의 OPEN_PAGE는 화면 열기여도 completes_task=false이므로 이미 재관찰 대상이었다. 범위 확대가 필요하다는 초기 추정을 철회하고, Android 수정과 telemetry 보완만 후속 조건에 반영한다. 아직 측정하지 않았던 후속 서버도 동일 정책으로 다시 고정했다.
- v2 정책은 별도 source tree/port와 provenance로 고정한다. 본 비교와 후속 비교의 성공률을 합산하지 않는다. 본 비교 A와 후속 A의 차이는 앱 수정 외 시간·모델 확률 변동도 포함하므로 엄밀한 단독 효과 추정으로 표현하지 않는다.
- 별도 ringtone component probe는 제품 처리율에 포함하지 않는다. product overlay/recovery가 없는 상황에서 native click의 실제 도착 여부를 확인하며, 필요하면 동일 native target을 재검증한 공개 제목의 physical control과 대조한다. 소리 목록/선택 항목은 저장·변경하지 않는다.

## 첫 안내 지표 해석 제한

기존 `first_action_correct`는 manifest의 여러 OEM에 허용된 첫 메뉴명과 일치하는지 검사한다. Galaxy Note20에서 각 경로가 최적인지를 독립 검증한 정답표와 같지 않다. 따라서 본 보고서에서는 이를 **허용 첫 메뉴명 일치**로 표시하고, 제품 전체 첫 동작 정확도로 포장하지 않는다. 첫 안내 표시율과 실제 목표 도착/판별 가능률을 함께 제시한다.

후속 하네스는 task panel뿐 아니라 실제 floating bubble bounds도 가림 검사에 포함한다. 본 비교 guarded font_size.increase의 첫 crop에 버블이 조절기 오른쪽을 가린 것을 육안 확인해 자동 candidate를 성공으로 승인하지 않았다. 원시 결과는 보존하고 screen-review에서 명시적으로 제외했다.

본 비교 volume.decrease 3건의 baseline은 모두0이었다. strict decrease로는 달성 불가능한 경계값 사례이므로 원시 전체26과제 표와 별도로, 변화 가능한25과제 집합의 결과도 제시한다. 경계값을 성공으로 소급 변경하지 않는다. 후속 volume.decrease는 trial baseline1을 설정/확인하고, 종료 시 원래0으로 복구한다.
