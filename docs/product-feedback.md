# 클릭에 대한 불만·칭찬 수집

말·글 입력은 `/api/v1/interactions/classify`에서 작업과 클릭에 대한 긍정/부정 피드백을 구분한다. 설정 작업을 실행하기 위한 분류나 승인을 대신하지 않는다. 음성 원본·화면·사용자 ID는 분류 모델에 보내지 않는다. 기존 요청 최소화 필터를 통과한 텍스트만 사용하며, 해당 필터가 완전한 익명화를 보장하지는 않는다.

- “야 이상한 색기야”: 사과와 함께 불편했던 내용을 적는 창을 연다.
- “고마워”: 감사 인사와 함께 선택적으로 좋았던 점을 남기는 창을 연다.
- “고마워, 와이파이 켜줘”: 실제 요청을 우선한다. 기존 FIFO 작업 흐름으로 전달한다.
- 작업 결과 질문의 “좋아요”, 실행 확인의 “네”, 중지·취소는 기존 제어 흐름을 유지한다. 감사나 욕설을 작업 완료·승인 신호로 사용하지 않는다.
- 다른 사람의 말·인용·다른 앱 리뷰는 클릭 피드백으로 분류하지 않는다. Jev의 신뢰도가 낮거나 응답 형식이 잘못되면 기존 목표 확인으로 전달한다. 명확한 공통 피드백 문장만 정확히 일치하는 규칙으로 보완한다.

Jev의 초기 작업 분류 선택지에도 `negative_feedback`와 `positive_feedback`를 추가한다. 피드백 수집은 실행 가능한 작업을 만들지 않으며 현재 세션·결과 질문·대기열을 변경하지 않는다. 상세 의견은 해당 입력창의 전송 버튼으로만 수집하고 모델에 다시 보내지 않는다. 저장 실패 시 내용을 유지하고 같은 피드백 ID로 재시도한다. 다른 피드백이 들어와도 작성 중인 내용을 덮어쓰지 않는다.

## 저장과 조회

`product_feedback`에 최초 발언, 긍정/부정 분류, 상세 의견, 생성/수정 시각을 저장한다. 최초 발언과 상세 의견은 기존 `EncryptedText`로 암호화하고 키 회전 대상에 포함한다. 같은 분류 요청 ID를 재전송하면 같은 기록을 반환한다. 진행 중인 작업이 없어도 수집할 수 있다. 사용자를 삭제하면 함께 삭제하며, 연결된 작업 기록만 삭제하는 경우 피드백은 유지하고 세션 연결을 해제한다.

- `POST /api/v1/interactions/classify`: `{ "id": "UUID", "text": "고마워", "session_id": null }`. 인증된 사용자의 입력을 분류하고 피드백이면 최초 발언을 저장한다.
- `POST /api/v1/feedback/{id}/detail`: `{ "detail": "설정 메뉴를 찾는 안내가 편했어요" }`. 본인 기록에 최대 2,000자의 상세 의견을 저장한다.
- `GET /api/v1/feedback/{id}`: 본인 기록 확인.
- `GET /api/v1/ops/feedback?limit=20&sentiment=negative`: 운영자 검토. 기존 `OPS_TOKEN`(32자 이상)을 Bearer 인증에 사용한다. 일반 사용자 토큰으로 조회할 수 없다. `next_cursor`를 다음 호출의 `before`로 전달한다. 사용자 ID와 화면은 응답에 포함하지 않는다.

배포 전 `alembic upgrade head`로 `20261111_19`를 적용하고 기존 데이터 암호화 키를 유지한다. Android와 서버를 함께 배포해야 입력 분류·상세 저장까지 작동한다. 이 저장은 모델의 ZDR과 별개로 클릭 서버에서 명시적으로 수행한다.

## 2026-11-11 검증 기록

Android 전체 단위 테스트 659개, 피드백·Jev 프로토콜·암호화·마이그레이션 관련 백엔드 검사 88개가 통과했다. 로컬 실행 상태 변경과 병합한 사본에서도 Android 서비스 216개, 관련 백엔드 75개 및 검증 환경 6개가 통과했다. 서버 재시작 후 기록 유지, 재전송 중복 방지, 계정/세션 삭제 관계, 작성 중인 의견 보존과 저장 실패 재시도를 확인했다. 실제 Jev API 자격 증명이 로컬에 없어 모델 호출 경계는 제어된 응답으로 검증했다.

전체 백엔드 실행은 최초 2,364개 통과·14개 실패였다. 새 마이그레이션 버전 기대값 1개를 갱신하고 관련 검사를 재실행해 통과했다. 나머지 13개(민감 화면 안내 6, 설정 복구 상태 6, VPN 후보 진단 1)는 변경 전 `272d3d3`에서도 같은 실패가 재현됐다. 전체 백엔드가 모두 통과했다고 보고하지 않는다.
