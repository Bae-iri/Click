# 쿠팡 상품 탐색 초기 범위

## 실기기 로그와 자동 후보 개선

앱이 서버에 보낸 탐색 요청은 `runtime_events.kind=browse`에 암호화해 7일 보관한다. 화면 해시·공개 페이지 종류·Jev 선택과 보류 이유·연결된 실제 탭·다음 화면 전이가 근거다. 원본 화면 이미지, 상품명, 검색어, 좌표는 AI2 근거 로그에 저장하지 않는다. 서버까지 도착하지 않은 요청이나 사용자가 확인하지 않은 모든 화면을 기록하는 기능은 아니다.

최신 `model_training` 동의 이후 로그만 AI2가 사용한다. 성공·취소·차단 및 `unknown` 응답 뒤 별도 작업으로 분석하고, 기본 60초 주기 작업이 진행 중 세션의 미처리 로그도 다시 확인한다. 후보와 근거는 암호화된 `runtime_event_consumptions`에 저장되며 가장 이른 근거 만료·동의 철회·세션 삭제와 함께 제거된다.

성공한 실제 전이는 경로 초안으로 만들고, 실패·미확인 로그에서는 후보 없음·Jev 보류·반복 화면에 맞는 개선 후보를 자동 생성한다. 실제 탭 뒤 화면 변화를 확인하지 못한 경우는 `unconfirmed_routes`로 구분한다. 개선 후보는 현재 목표·페이지·후보와 맞을 때 다음 Jev 판단에 자동 반영하며, 같은 세션의 최신 분석이 이전 후보를 대체한다. 이후 성공이 확인되면 그 세션의 재관측 요청은 해제한다. 실패 로그만으로 새 UI 식별자를 만들거나 운영 graph를 자동 승인하지 않는다.

Backend 폴더에서 아래 명령으로 현재 후보를 확인한다. 사용자 원문과 세션 ID는 출력하지 않는다.

```powershell
python -X utf8 scripts/agent2.py learn-browse --limit 100
python -X utf8 scripts/agent2.py list-browse-improvements --limit 100
python -X utf8 scripts/agent2.py list-browse-graphs --limit 100
```

앱의 탐색 로그 전송과 서버 배포가 모두 적용되어야 실제 테스트가 이 흐름에 들어온다. 이 자동 개선은 쿠팡 상품 검색·상세 탐색 범위다. 후보의 자동 갱신은 실기기 성공률 검증이나 애플리케이션 소스코드 자동 수정과는 별도다.

`CLICK_COUPANG_BROWSE_ENABLED=1`과 앱의 `device_context.capabilities.coupang_browse=true`가 모두 있을 때 쿠팡 상품 검색·상품 상세 보기를 별도 탐색 모드로 제공한다. 이전 앱과 기능을 끈 서버는 기존 그래프 실행 동작을 유지한다. 이 탐색 모드는 기존 작업의 승인 범위를 확장하지 않는다. 주문·결제·옵션 선택·장바구니·계정 변경은 이 모드에 포함되지 않는다.

## 사용자 흐름

앱 진입 시 읽을 수 있는 공개 화면이 생기면 첫 Jev 판단을 한 번 요청한다. 로딩 중 빈 화면은 이 기회를 소모하지 않는다. 이후 화면 확인은 사용자 버튼으로 진행하며, 일시정지·종료 중에는 진입 판단도 보내지 않는다.

AI2가 생성한 관측 경로 초안은 다음 Jev 판단의 참고 정보로 사용한다. 현재 목표·페이지·실제 후보의 action/resource가 일치하는 전이만 전달하며, 근거 trace 수를 함께 제공한다. 최신 학습 동의·만료·본문 해시를 매번 확인하고, 근거가 없거나 저장소가 실패하면 기존 Jev 판단으로 진행한다. 초안을 실행 그래프로 승인하거나 후보를 추가하지 않는다. 이 연결은 상품 검색·상세 탐색 모드에 적용되며 기존 71개 commerce 목표 전체의 경로 학습을 의미하지 않는다.

`assess-browse`는 `route_blockers`로 화면 미인식·후보 없음·반복 화면·모델 보류를 구분하고 `ai2_hint_steps`로 참고 경로 사용 횟수를 집계한다. 기록만으로 성공률 향상을 주장하지 않으며, 비교는 실기기 측정으로 확인한다.

쿠팡 상품 검색/상세 요청 → 상품 이름 확인 → 시작 확인 → 쿠팡 열기 → 첫 공개 화면 판단 → Jev가 고른 공개 검색창/상품/목록을 안내한다. 검색어 입력·탭·스크롤은 사용자가 직접 한다. 첫 진입 이후에는 화면 확인 버튼을 눌렀을 때 새 요청을 보내며 자동 화면 polling이나 자동 조작은 없다. 일시정지는 기기에서 안내를 멈추며, 중지와 앱 종료는 기존 요청 대기열의 취소로 진행 중 응답을 무효화한다. 재접속은 목표를 재분류하지 않고 서버의 탐색 세션을 복원하며 새 화면 확인이 필요하다.

탐색에는 task graph나 가짜 graph hash를 만들지 않는다. 기존 설정 실행과 별도의 `POST /api/v1/agent/browse/commands`, `coupang-browse.v1` 계약을 쓴다. 두 경로는 같은 사용자 소유권·요청 대기열·세션 version·요청 ID·짧은 lease 경계를 공유한다. 중지 후 늦게 온 결과나 이전 version의 안내는 다시 적용하지 않는다.

## 화면·행동 경계

### 실제 네이티브 화면 읽기

홈/앱 목록에 쿠팡 아이콘이 실제로 보이면 로컬 접근성 정보로 아이콘을 표시한다. 같은 이름의 대상이 여러 개이거나 보이지 않으면 쿠팡 열기 버튼으로 이어간다. 알려진 쿠팡 로딩 오류는 로컬에서 원인을 안내하고 실제 재시도 버튼을 표시한다. 네트워크 오류를 일반적인 대상 찾기 실패로 바꾸거나 반복 모델 호출로 처리하지 않는다. 오류가 사라지면 태스크 그래프 실행은 같은 요청으로 재개하고, 탐색 모드는 현재 화면 확인 버튼으로 이어간다.

실기기에서 확인한 `rds_search_bar`와 `edit_text` 검색 입력을 지원한다. 일반 `edit_text`는 공개 검색 화면 표식과 검색창 조상 구조가 함께 있어야 검색 입력으로 인정하며 원문은 전송하지 않는다. 최근 검색어 영역은 메뉴 후보에서 제외한다. `쿠팡 홈`·`전체 카테고리` 같은 실제 접근성 문구는 검수된 메뉴 이름으로 정규화하고 실제 native resource ID와 좌표는 보존한다.

`coupang-native-network.json`은 실제 기기 접근성 구조에서 검수된 고정 UI 문구만 남긴 회귀 fixture다. 기기 진단은 `CoupangNativeScreenDeviceTest`로 쿠팡의 실제 정보를 읽으며 입력·구매·권한 선택은 하지 않는다. 이 검사는 쿠팡 설치와 USB 연결이 필요하며, 앱 자체의 네트워크 연결 성공을 보장하지 않는다.

공통 원본은 `AI-Agent/goal_catalog/coupang_browse_policy.json`이다. Python과 Android 생성 코드가 같은 정책을 읽는다. 화면 경로는 정의하지 않으며 쿠팡 package의 공개 검색·상품 UI 식별자와 민감 영역을 정의한다. 알 수 없는 식별자를 임의의 탐색 버튼으로 승격하지 않는다. 로그인·배송지·계정·주문·결제 화면, 다른 앱, 비밀번호, 공개 검색창 이외의 입력창은 전송하지 않는다. 추천·최근 내역·개인 영역의 하위 노드도 제외한다. 이 초기 정책은 허용한 native resource ID에 한정되며 WebView나 앱 버전에 따라 안내를 보류할 수 있다.

Android는 검색 입력의 원문을 snapshot에 남기기 전에 로컬 해시를 계산한다. 검색어 원문은 사용자가 확인한 목표에만 있으며 화면 입력 내용은 전송하지 않는다. 공개 항목은 구조·식별자·짧은 표시 문구만 필터링하고, Jev에는 실제 node ID·좌표·계정/세션 ID 없이 한 번의 Choice 요청으로 전달한다. Jev는 후보를 고르거나 보류할 수 있고 행동·좌표·완료를 생성하지 않는다. 서버도 package·식별자·개인정보 패턴·관측 시각·크기를 재검사한다. 문구 필터링은 완전 익명화를 보장하지 않는다.

검색 완료는 요청한 검색어의 해시·검색 결과 화면·공개 상품 후보가 함께 관측되어야 한다. 상세 완료는 원래 안내와 실제 native 탭·이후 상세 화면·동일 상품 제목을 연결해야 한다. 화면 방문만으로 선택 성공을 추정하지 않는다. 사용자의 “원하는 상품을 확인했어요”는 `user_reported`로 분리한다. 후보 부재·저신뢰·동일 화면 반복은 `unknown`, 민감 화면·탐색 예산 소진은 `blocked`로 남긴다.

## AI2 기록과 지연

`runtime_events.kind=browse`, `browse-event.v1`로 관측 해시·페이지 종류·실제 행동 연결·선택 수·보류·결과·정책 해시·Jev 모델/응답 시간을 저장한다. 검색어·상품명·원본 화면·결제정보를 이 분석 기록에 넣지 않는다. 기존 암호화·세션 삭제 연계·7일 보존을 적용한다. 분석은 온라인 응답과 별개다.

Backend에서 `python scripts/agent2.py assess-browse --limit 100`을 실행하면 최신 `model_training` 동의 이후·미만료 기록의 verified navigation·사용자 보고·중단·차단·판정 불가를 구분해 집계한다. 그래프용 기존 AI2 process/assessment/route priority proposal과 탐색 분석은 별도 계약을 사용한다.

## AI2 신규 그래프 자동 생성

탐색 완료 응답을 보낸 뒤 AI2가 기록을 읽고 새 그래프 초안을 `graph_proposals`에 암호화 저장한다. `CLICK_AI2_BROWSE_GRAPH_ENABLED=1`이 기본값이며 서버 수명주기의 별도 worker가 60초마다 저장되지 못한 완료 기록을 재처리한다. 온라인 Jev 요청이나 화면 안내 중에 그래프를 생성하지 않으며 추가 모델 호출도 없다. 중복 HTTP 요청·재시작·반복 분석은 같은 근거에서 초안을 중복 생성하지 않는다.

대상은 현재 허용된 쿠팡 상품 검색·상품 상세 보기다. 최초 관측부터 마지막 완료 관측까지 sequence와 정책/코드 hash가 일치하고, 각 화면 변화가 실제 안내·조작·전후 관측으로 연결되어야 한다. 검색 완료 화면만 관측한 경우, 사용자 완료 보고, 미연결 이동, 누락/만료된 기록, 다른 앱/결제 영역으로는 새 경로를 만들지 않는다. 현재 native scroll 결과를 독립적으로 연결하지 못하므로 scroll이 필요한 경로는 데이터 부족으로 남긴다.

새 본문은 `browse-task-graph.v1`이다. 실제 관측한 화면 상태, 시작/종료 상태, 공개 resource selector를 쓰는 전이, 사용자 직접 조작 조건, 현재 확인된 목표에 결합된 완료 predicate를 가진다. selector는 기존 `browse_policy.resource()`와 같은 `normalized_browse_resource.v1` 규칙의 resource key를 사용하며, 정규화된 이름으로 원래의 native ID를 지어내지 않는다. 검색어·상품 이름·좌표·사용자/세션 ID를 본문에 넣지 않고 검색어는 `confirmed_request.query` 입력으로 매개변수화한다. 상품 selector는 새 화면의 공개 후보를 다시 판별해야 하며 저장된 상품이나 첫 번째 상품으로 고정하지 않는다.

기존 graphless 실행이 끝난 뒤 만드는 **신규 그래프 초안**이며, 실행 중 참조한 graph hash로 소급 표시하지 않는다. `GraphProposal.proposal_type=new_browse_task_graph`, `base_graph_version=graphless`, `requires_human_review=true`로 저장한다. trace completeness 값은 제품 성공률이나 독립 기기 평가 점수가 아니다. 일반 설정 실행용 `runtime-task-graph.v1` 승인 테이블에 자동 등록·활성화하지 않는다. 별도 기기 검증·검토 없이 다음 사용자에게 실행 경로로 배포하지 않는다.

후보는 원천 event에 연결된 만료 receipt를 참조한다. 최신 동의 이전 기록을 사용하지 않으며, 새 동의 경계·철회·탈퇴·세션 삭제·가장 이른 근거의 7일 보존 만료에 맞춰 초안과 평가도 삭제된다. migration `20261117_20`을 서버 코드와 함께 적용해야 한다. 앱/API 요청 계약 변경은 없다.

```sh
cd Backend
python scripts/agent2.py learn-browse --limit 100
python scripts/agent2.py list-browse-graphs --limit 100
python scripts/agent2.py process --limit 100
```

첫 명령은 보존된 근거로 초안을 생성하고, 두 번째는 원문 없이 후보 ID·목표·상태/전이 수·만료 시각을 확인한다. `process`도 기존 그래프 분석과 신규 탐색 그래프 생성을 함께 실행한다. `NEEDS_DATA`는 성공 경로를 추측해 채웠다는 뜻이 아니라 초안을 만들 근거가 부족하다는 뜻이다.

## 검증 한계

인증된 HTTP 계약과 제어된 Jev 응답, Android 화면 필터·컨트롤러·설정 회귀를 자동 검사한다. 실제 Jev의 한국어 선택 품질과 현재 쿠팡 앱 버전의 native UI 지원은 별도 실기기 확인 대상이다. 연결 테스트폰의 쿠팡 미설치 상태에서 실기기 E2E 성공을 주장하지 않는다. 서버 코드·새 APK를 함께 배포해야 사용할 수 있다.
