# 자동 클릭·슬라이더가 실행되지 않던 조건 수정

## 확인한 코드 원인

1. 서버가 선택한 클릭 행의 설명 문구를 메뉴 이름으로 비교하고 있었다. 실제 메뉴 제목이 자식 TextView에 있고 행에는 “밝기와 화면 설정” 같은 contentDescription이 있으면 정상 항목도 차단됐다. 설명 부제목이 있는 행과 비클릭 컨테이너도 지나치게 거부했다.
2. 그래프가 지원하는 “글꼴 크기” 같은 별칭이 클라이언트 허용 목록에 빠져 있었다.
3. 슬라이더를 정확히 `android.widget.SeekBar` 클래스와 `ACTION_SCROLL_FORWARD/BACKWARD` 조합으로만 실행했다. 커스텀 SeekBar나 `ACTION_SET_PROGRESS`만 노출하는 컨트롤은 실행되지 않았다.
4. 새 서버의 `automatable_setting` 표시가 없는 응답은 기존 typed_goal에 font_size가 있어도 자동 조절하지 않았다.
5. 전체 화면 revision 비교와 350ms 한 번의 결과 확인 때문에 무관한 갱신 또는 늦은 값 반영을 처리하기 어려웠다.
6. 자동화 ON에서도 마지막 글자 크기 변경 확인 단계는 수동으로 남아 있었다.

## 수정한 실행 경로

- 클릭 대상 행 또는 자식의 공개 메뉴 제목을 확인하고, 실제 부모 관계를 따라 클릭 행을 찾는다. 설명과 부제목이 있어도 허용한다. 위험 문구·민감 입력·다른 조절 컨트롤·다른 앱은 계속 제외한다.
- 기본 클릭을 먼저 실행한다. 클릭 API가 거절되거나 클릭 플래그가 없는 컨트롤은 최신 접근성 대상·창·좌표·설정 ON을 재확인한 뒤 **원래 안내 대상 내부를 실제 탭**한다. OCR 좌표로 확대하지 않는다.
- 슬라이더는 **값 설정 → 기본 증감 → 검증된 가로 슬라이더 내부 드래그** 순서로 지원한다. 정수 범위는 한 단계, 연속 범위는 범위의 1/10을 제한적으로 조절한다. 범위 밖 조작은 하지 않는다.
- 제네릭 View라도 Android가 범위와 값 설정 동작을 제공하면 slider 역할을 보존한다. Backend/런타임도 유효한 범위를 동반한 명시적 slider 역할을 전달·인식한다.
- font_size 작업임이 기존 typed_goal로 확인되면 새 render_policy 필드가 없어도 자동 조절한다.
- 자동화 ON + 사용자가 작업 내용을 확인하고 시작 + 실제 글자 크기 슬라이더 + 서버의 drag 승인 요청인 경우 마지막 변경 확인도 자동 응답한다. 비전 접근 허용·임의 확인창·다른 설정에는 적용하지 않는다.
- 화면 전체의 무관한 갱신 대신 선택 대상과 자식·위치·값을 비교한다. 대상 없는 안내와 비전 안내는 기존의 엄격한 화면 검증을 유지한다.
- 조작 결과는 최대 약 2초 동안 여러 번 관측한다. 같은 안내의 결과 대기 응답이 도착해도 원래 동작 연결을 유지해 늦은 값 변경을 원래 시도에 연결한다. 실제 값이 바뀐 근거가 있어야 조절 이벤트를 전달한다.

## 적용과 검증

새 APK를 설치해야 클라이언트 수정이 반영된다. 제네릭 slider 역할 지원에는 Backend 수정도 함께 반영해야 한다. 설정의 **지원 작업 전체 자동화**는 ON이어야 한다.

기기별 구조를 재현한 테스트로 제목+설명 행, 비클릭 컨트롤 탭, 글꼴 별칭, 커스텀 slider의 SET_PROGRESS 인자, 물리 드래그, 지연된 값 관측, 마지막 확인부터 실제 조절 호출까지의 경로를 검증한다.

현재 `adb devices`에 연결된 기기는 없다. 따라서 이 변경으로 연결 기기의 실제 터치가 성공했다고 주장하지 않는다. 디버그 APK는 `Frontend/app/build/outputs/apk/debug/app-debug.apk`다.

최종 검증: Android 전체 테스트 222개, AI-Agent 전체 테스트 214개, Backend 전체 테스트 1,016개 통과. 디버그 APK 빌드 성공.
