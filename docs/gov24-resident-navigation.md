# 정부24 주민등록등본 화면 탐색과 AI2 모니터

목표는 **주민등록등본 발급 안내·신청 진입 화면 도착**이다. 화면의 공개 제목과
발급하기/신청하기 버튼을 함께 관측하면 완료한다. 버튼을 눌러 신청서를 열거나,
신청서 작성·발급 신청·문서 출력까지 수행하는 기능은 아니다.

## 실행

새 Backend와 Android 빌드를 함께 사용한다. `CLICK_GOV24_GUIDE_ENABLED=1`이 필요하고,
클라이언트는 서버 OpenAPI가 지원할 때만 `gov24_civil` capability를 보낸다.
"정부24 주민등록등본 발급 화면 찾아줘"를 요청하고 안내 시작을 확인한다.
기존 로그인 안내와 쿠팡 안내도 유지된다.

별도 검증 인스턴스를 만들 때는 Backend에서:

```powershell
.\click\Scripts\python.exe -X utf8 scripts/validation.py --instance instance/gov24 prepare --gov24 --port 8003
.\click\Scripts\python.exe -X utf8 scripts/validation.py --instance instance/gov24 serve
```

앱은 해당 인스턴스와 짝지어 빌드한다. 별도 PowerShell에서:

```powershell
cd C:\click_server\Click\Frontend
.\scripts\validation.ps1 -Instance gov24
```

이 인스턴스는 기본 앱 ID에 `.gov24.validation`을 붙여 별도 앱으로 빌드한다.
기기 설치가 필요한 경우 위 도우미의 `-Install` 옵션을 명시해서 사용한다.
실시간 모니터는 다른 터미널에서 실행한다:

```powershell
cd C:\click_server\Click\Backend
.\click\Scripts\python.exe -X utf8 scripts/agent2_monitor.py --target gov24 --env-file instance/gov24/.env
```

기존 서버를 테스트한다면 그 서버의 환경 파일을 지정한다. 기본 2초 간격으로
변경된 내용만 출력한다. `--once`, `--json`, `--interval 5`도 지원한다. 종료는 `Ctrl+C`다.

## 관측과 경로 선택

사전 작업 그래프를 추가하지 않는다. 기기에서 실제로 보이는 허용된 공개 메뉴만
정규화하며, 좌표는 현재 화면에서 강조할 버튼에만 결합한다. 메뉴 이름과 동의된
실제 이동 결과로 출발 화면별 경로 후보가 만들어진다.

1. 같은 화면에 후보가 여러 개이고 충분한 성공 기록이 없으면 사용자가 이동할 메뉴를 고른다.
   후보가 하나이면 그 실제 메뉴를 안내한다. 화면에 없는 메뉴는 생성하지 않는다.
2. 사용자가 표시한 메뉴를 누른 뒤 **현재 화면 확인**을 누른다. 서버는 guide·관측·노드·시간이
   일치하는 행동과 다음 화면을 연결한다. 화면을 관측하기만 한 기록은 경로 성공으로 세지 않는다.
3. 주민등록등본 메뉴 뒤 목표 진입 화면 도착, 서비스 메뉴 뒤 서비스 화면 도착은 단계 성공이다.
   다른 알려진 메뉴 화면으로 이동하면 실패, 같은 화면·미인식 결과는 미확인이다.
   반복 관측은 같은 attempt를 중복 집계하지 않고, 나중에 확인된 결과가 미확인을 대체한다.
4. 동의 이후 생성된 미만료 전체 기록과 현재 코드·정책이 일치하는 최근 최대 100개 세션을 집계한다.
   사용자별 기록은 기존 암호화된 `runtime_events`에 보관된다. 별도 테이블이나 그래프 게시가 필요 없다.
5. 동일 출발 화면에서 현재 보이는 유일한 메뉴 후보들 중 최소 3회·성공률 70% 조건을 충족한 후보를
   Wilson 95% 하한, 성공률, 시도 수로 비교한다. 동점이면 선택을 보류한다.
   다음 요청부터 즉시 반영하며, 쿠팡용 60초 작업자를 기다리지 않는다.

모니터는 경로별 성공·실패·미확인, 성공률, Wilson 하한, 직전 출력 대비 pp 변화를 표시한다.
`STAT_LEADER`는 전체 통계상 후보이며, 현재 화면의 실제 후보 사이에서는 다른 결과가 나올 수 있다.
`ai2_selected`가 실제 AI2 선택이다. `user_selected`, `single_visible_option`, `verified_navigation`과
각 관측의 `successes`/`failures`/`unknown`도 함께 출력한다.

성공률은 **화면 이동 단계의 성공률**이다. 로그인 성공률·등본 발급 완료율이나 개선 효과의
인과 증명을 의미하지 않는다. 종료/만료/동의 철회와 조회 범위 변경으로 집계가 줄어들 수 있다.
최근 관측 100개를 출력하며 조회 간격 사이에 대량 관측이 쌓이면 일부 이벤트는 표시 범위 밖으로 밀린다.

## 적용 범위와 검증 상태

개인정보 입력·인증·동의 화면은 기존 기기 필터에서 빈 handoff 관측으로 바뀐다.
모든 입력 필드는 보수적으로 중단하므로 검색 입력칸이 있는 공개 화면에서도 직접 진행이 필요할 수 있다.
회원 이름·주소·인증 정보·화면 원문은 경로 후보와 모니터에 포함하지 않는다.
발급하기/신청하기는 도착 확인용 경계이며 자동 선택할 후보가 아니다.

허용 문구는 `gov24_login_policy.json`의 `civil_navigation`에 정의한다.
실제 앱의 문구나 접근성 트리가 다르면 메뉴를 인식하지 못할 수 있다. 현재 민원 경로 테스트는
합성 화면을 통한 HTTP·기기 필터 검사이며, 이 확장으로 실제 정부24 등본 발급 화면까지 이동한
실기기 E2E 검증을 완료했다는 뜻은 아니다. 기존 로그인 화면의 실기기 검증과 구분한다.
