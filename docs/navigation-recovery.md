# 잘못 이동한 화면에서 작업으로 복귀하기

## 설정 앱으로 직접 복귀

플로팅 복구 화면에는 ‘돌아가기’, ‘뒤로가기’, ‘홈으로 이동’ 버튼을 만들지 않는다. 다른 앱·최근 앱·잘못된 설정 페이지 등에서 작업을 이어갈 때는 기존 ‘설정 열기’ 하나를 제공한다. 사용자가 누르면 Android Settings.ACTION_SETTINGS를 실제 실행한다. 전역 뒤로가기·홈 동작을 버튼에 연결하지 않으며 해당 경유를 복구 필수 단계로 만들지 않는다.

명령 실행 전에 작업 ID·generation·화면 표시 토큰을 확인한다. 현재 화면의 전체 fingerprint가 조금 바뀌었다거나 서버가 응답 중이라는 이유로 사용자의 설정 열기 요청을 무시하지 않는다. 요청 직후에는 이동 성공으로 표시하지 않고 새 접근성 화면을 확인한다. 1.2초 뒤에도 설정 화면을 관측하지 못하면 확인 실패와 다시 열기 방법을 보여 준다. 설정 Activity를 실행할 수 없으면 동작하지 않는 버튼 대신 직접 열기 안내를 제공한다. 중복 누름은 같은 설정 열기를 다시 실행하지 않는다.

설정 열기는 목표·세션·에피소드를 바꾸지 않으며 설정값을 조작할 권한도 만들지 않는다. 이전 안내·비전 승인·자동 조작 대기는 지우고 실제 새 화면에 대한 안내와 승인을 받는다. 잠금·민감 정보·시스템 권한창·사용자가 직접 진행 중인 외부 선택기에는 기존 보호 경계를 적용한다.

## 사용자가 직접 누른 홈·뒤로가기

휴대폰의 실제 홈·뒤로가기 버튼과 제스처는 계속 사용할 수 있다. 해당 요청만으로 이동 성공을 선언하지 않고 새 네이티브 화면과 연결한다. 런처에 복귀하거나 관측했던 작업 화면으로 돌아온 근거가 있을 때 같은 목표로 안내를 이어간다. 캘린더 내부 문구만 달라졌다면 작업 복귀로 간주하지 않는다. 그런 경우에 새로운 홈 이동 버튼을 추가하지 않는다.

오래된 세션·에피소드·중복 이벤트는 재적용하지 않는다. 복귀 때문에 실행·탐색 예산을 초기화하거나 검증되지 않은 설정 변경을 성공으로 바꾸지 않는다.

## Agent 2와 시간 기록

- 아무 버튼이나 누른 시간을 기록하던 연결을 제거하고, 안내 대상에 일치한 실제 수동 탭만 기록한다.
- 잘못 누름·복구·앱 이탈 시 현재 시간 측정을 폐기한다. 새 안내가 표시되면 새 구간을 시작한다.
- 자동 조작은 사람의 응답 시간으로 기록하지 않는다.
- 홈·뒤로가기 맥락은 동의가 있는 경우 `navigation_recovery`로 기록한다. 이해도 점수·증거 수·화면 난이도에 반영하지 않는다.
- 실행 기록에도 `user_home_navigation`/`user_back_navigation` 이유와 `count_attempt=false`를 남긴다. Agent 2의 오프라인 레이블은 `navigation_recovery`이며 성공·실패 학습 사례로 쓰지 않는다.

## 자동화 설정

Click 메뉴의 **지원 작업 전체 자동화** 스위치로 기기 로컬 설정을 저장한다. 기본 OFF다.

- ON: 현재 지원하는 설정 앱 찾기, 앱 열기, 설정 메뉴 이동, 자동 스크롤, 글자 크기 변경 확인과 슬라이더 조절.
- OFF: 위의 자율 실행을 끄고 위치·방향을 안내한다. 사용자가 명시적으로 누르는 복구/스크롤 버튼은 사용할 수 있다.
- 복구의 홈·뒤로가기는 ON이어도 사용자가 선택한다. 결제·전화·메시지·임의 앱 실행은 자동화 범위에 포함하지 않는다.

지원하는 task graph의 자동화 범위를 뜻하며 모든 앱의 모든 작업을 지원한다는 의미는 아니다. 자동 조작 전에는 기존 화면·창·대상 검증과 중복/횟수 제한을 계속 적용한다.

앱과 Backend를 함께 반영해야 새 `home_navigated` 이벤트와 복구 맥락을 처리할 수 있다.

검증: Android 전체 단위 테스트 209개와 디버그 APK 빌드 통과. AI-Agent 전체 테스트 212개 통과. Backend 전체 회귀 테스트 1,014개 통과 후 홈 이동 API·개인화 테스트 7개도 확인했다. 한 번의 뒤로가기 제안/실패 전환, 중복 클릭 방지, OFF 상태의 자율 동작 차단, 경로 초기화·목표 보존, Agent 2 중립 기록을 포함한다. 실기기 검증은 남아 있다.

자동 클릭·슬라이더의 실제 실행 경로 보완은 [후속 수정 문서](automation-touch-fixes-2026-10-30.md)를 따른다.

## 중간 화면 인식과 조작 연결 보완 (2026-11-01)

- 클릭 행의 실제 자식 제목을 대상의 이름으로 사용한다. 설명 문구 변경으로 대상 식별자가 바뀌거나, 다른 창의 자식 문구가 합쳐지지 않도록 한다. 화면 분류와 대상 선택은 같은 그래프 별칭을 사용한다.
- 관측한 화면이 예상 화면보다 뒤에 있어도, 승인 그래프의 저위험 메뉴 이동만으로 도달할 수 있으면 그 화면에서 이어간다. 건너뛴 조작을 성공으로 집계하지 않으며 설정 변경·승인·완료 조건을 건너뛰지 않는다.
- 화면을 규칙으로 구분하지 못할 때 기존 `SELF_HOSTED_LLM_URL`, `SELF_HOSTED_LLM_TOKEN`, `SELF_HOSTED_LLM_MODEL` 설정으로 의미 해석을 보조한다. 전송 내용은 그래프에 등록된 공개 메뉴 어휘, 임시 노드 번호, 상태 후보이며 화면 원문·이미지·사용자 식별자는 보내지 않는다. 실제 대상이 확인된 상태만 후보가 되고, 모델이 반환한 근거 노드를 다시 검사한다. 설정 누락·시간 초과·잘못된 응답은 기존 복구 흐름으로 이어진다. 추론 요청의 timeout은 최대 1.5초로 설정한다.
- Android 클릭 이벤트는 실제 부모 관계가 확인된 자식 텍스트 또는 승인된 클릭 부모에서 원래 안내 대상으로 연결한다. 노드 이름의 접두사만으로 부모 관계를 추측하지 않는다.
- 슬라이더 조작 후 일시적인 빈 화면에서도 최대 약 5초까지 재관측한다. 창이 다시 만들어졌다면 유일한 동일 리소스·범위의 글자 크기 컨트롤과 실제 `FONT_SCALE` 변화가 함께 있어야 원래 조작에 연결한다. 서버도 빈 관측 동안 원래 안내·변경 전 값·시도 식별자를 제한된 시간 동안 유지한다.
- 무관한 화면 문구나 revision 변화로 동일한 메뉴 안내를 버리지 않는다. 대상의 리소스, 패키지, 창, 범위 등은 화면 fingerprint와 최신 대상 검증에 포함한다.

LLM 출력으로 기술적 설정 변경 성공을 선언하지 않는다. 실제 기기 및 실제 모델 서버에서의 성능 평가는 재현 테스트와 별도로 수행한다.

검증: AI-Agent 259개, Backend 1,091개, Android 단위 테스트 344개 통과. Android는 JDK 17로 검증하고 디버그 APK를 빌드했다. 소스 파일이 일시적으로 빈 내용으로 읽히는 작업 폴더 문제를 피하기 위해 내용이 확인된 로컬 복사본에서도 검증했다. 실제 LLM 호출, 폰 설치 및 서버 배포는 수행하지 않았다.


## 목록 탐색과 설정 아이콘 판정 보완 (2026-11-09)

설정 목록과 런처 탐색은 페이지 수 4회/8회로 중단하지 않는다. 네이티브 컬렉션의 항목 위치,
이동 가능 방향, 화면 내용 변화와 반복을 이용한다. 중간에서 열린 설정 목록은 먼저 시작 쪽으로
탐색한 뒤 시작점부터 앞으로 훑는다. 런처는 기본적으로 다음 페이지를 찾되, 실제 컨테이너의
가로/세로 축을 따른다. 큰 주 목록을 선택하고 슬라이더를 스크롤 대상으로 사용하지 않는다.

이동 요청이 거절됐다는 사실만으로 목록 끝이라고 판단하지 않는다. 동일 화면은 한 번 더
재관측한 뒤 반대 방향을 확인하고, 양쪽에서도 진행되지 않거나 같은 페이지 순환이 확인되면
도움 안내로 전환한다. 새 내용이 계속 나타나면 고정 페이지 수로 포기하지 않는다.
설정값 변경·탭의 중복 방지 및 실행 제한은 별도 계약을 따른다.

런처에서 `설정, 앱`/`Settings, App` 같은 접근성 설명과 자식의 `설정` 제목을 같은 앱으로
판정한다. 이름 없는 장식 ImageView가 클릭 가능하다는 이유로 설정 아이콘 전체를 거절하지
않으며, 별도 이름을 가진 다른 클릭 컨트롤은 계속 모호한 대상으로 처리한다.

컬렉션 위치와 방향, 탐색 fingerprint는 기기 내부 메타데이터다. 서버로 직렬화하는 화면
JSON에는 추가하지 않는다. 이 변경은 Android APK를 갱신하면 적용되며 서버 변경은 필요 없다.

검증: 최신 develop 기준 Android JVM 전체 531개와 최종 정리 후 관련 회귀 테스트가 통과했다.
중간 위치에서 위쪽 탐색, 100개 새 페이지 탐색 유지, 런처 순환/양 끝 탐색, 슬라이더 제외,
Settings 접근성 설명 일치, 로컬 메타데이터의 JSON 제외를 포함한다. 실기기 테스트는
`NativeNavigationTest`의 `liveScroll=true`로 실행할 수 있다. 이번 검증 시 ADB 기기가 연결되지
않아 실기기 실행과 설치는 수행하지 않았다.

2026-11-09 실기기 후속 검증: Samsung SM-N981N에 APK를 설치하고 테스트 시작 전 설치 파일
SHA256을 대조했다. 실제 런처의 설정 아이콘 판정과, 디스플레이 행을 찾은 후 아래쪽으로
이동해 숨긴 상태에서 위쪽으로 다시 찾아오는 2개 테스트가 통과했다. 큰 시스템 글자
크기에서 디스플레이가 첫 화면에 보이지 않을 수 있어 테스트 준비에도 공통 탐색기를 쓴다.
계측의 기존 접근성 서비스 재시작은 서비스 목록과 전역 스위치의 원래 ON 상태를 함께
복원한다. 신규 서비스 승인은 추가하지 않는다. 앱 화면 실행은 백그라운드 Activity 제한을
피하도록 계측 셸로 실행한다. 다른 검증 작업과 충돌하지 않도록 테스트 패키지를 별도로
빌드해 실행했으며 실제 설정값은 바꾸지 않았다. 검증 직후 다른 작업의 최신 프로젝트
APK가 설치됐으며 이 빌드에도 이번 내비게이션 클래스가 포함된 것을 확인했다.
현재 설치된 최신 프로젝트 빌드에서도 동일한 두 실기기 테스트를 다시 실행해 통과했고,
실행 전후 APK 해시가 동일했다. 계측 종료 후 기존 접근성 승인 상태를 복원하고 실제
Click 서비스가 bound 상태로 돌아온 것까지 확인했다.

## 설정 하위 화면에서 복구

다른 설정 항목에 들어가 뒤로가기 버튼이 보이면 설정 앱을 다시 열지 않고 이전 페이지로 돌아가도록 안내한다. 기록된 경로가 없거나 여러 번 이동했어도 같은 방식으로 한 페이지씩 돌아갈 수 있다. 사용자가 뒤로가기를 실행한 뒤에는 새 화면을 다시 읽어 기존 목표로 안내를 이어간다. 창 ID가 바뀌거나 잠깐 빈 화면이 관측되어도 홈 이동으로 전환하지 않는다.
