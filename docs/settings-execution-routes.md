# Android 설정 89개 실행 안내

카탈로그 2.3.2. 기존 89개 목표 모두 입력 계약과 승인 그래프를 연결했다. 별도의 읽기 전용 화면 열기 21개를 합하면 설정 그래프는 110개다. `approved`는 실행 안내를 시작할 수 있다는 뜻이며, 자동 조작 또는 실기기 검증 완료를 뜻하지 않는다.

- 변경 상태 확인 경로 56개: 기존 글자 크기·밝기·미디어 음량·화면 요소 크기 8개, Wi-Fi 2개, 네이티브 스위치 42개, 소리 모드 선택 4개.
- 직접 진행 안내 33개: 안전한 설정 화면까지 이동하고, 선택·입력·최종 변경은 사용자가 진행한다.
- 신규 확장 목표의 제조사별 실제 조작 검증은 아직 완료하지 않았다. 공개 Android API로 설정을 강제 변경하는 구현이 아니다.

화면 요소 크기 확대·축소는 기본 디스플레이의 `Configuration.densityDpi`와 네이티브 슬라이더 이동을 함께 검증한다. 화면 재생성 후에도 동일 리소스·대상 키·사용자 조작·새 관찰이 필요하다. 설정이 아닌 다른 화면이나 중복 슬라이더는 조작 대상으로 선택하지 않는다.

공개 중간 메뉴를 보완한 11개 작업은 정확한 최종 안내 화면까지 이동한다. 예를 들어 저장된 Wi-Fi는 Wi-Fi → 고급 설정 → 네트워크 관리, VPN·프라이빗 DNS는 연결 → 기타 연결 설정을 거친다. 기기별 중간 메뉴 생략도 허용한다. 알림 기록은 고급 설정에서 직접 진행으로 넘기며 기록 내용 화면의 전송 차단은 유지한다.

## 변경 상태 확인

슬라이더는 실제 적용 값과 방향을, Wi-Fi는 네이티브 체크 상태와 `WifiManager` 상태를 함께 확인한다. 나머지 스위치는 해당 항목의 독립 화면 제목·정확한 라벨·네이티브 `checkable`/`checked`를 확인한다. 이 42개에서 확인하는 것은 스위치 상태이며, 네트워크 접속·기능 효과까지 확인했다는 뜻은 아니다.

변경에는 사용자 확인과 원래 대상에 연결된 조작 이벤트가 필요하다. 같은 대상·창에서 조작 이후 새 관찰의 체크 상태가 원하는 방향으로 달라져야 `CHANGED`다. 이미 원하는 상태면 `ALREADY_SET`로 기록하고 반대로 누르지 않는다. OCR, `selected`, 누락된 체크 값, 다른 대상·창, 오래된 이벤트는 변경 증거로 쓰지 않는다. Jev가 판단을 보류하면 규칙으로 조작을 대신 선택하지 않는다.

OEM이 라디오·버튼을 사용하거나 제목·라벨·대상이 모호하면 스위치 변경을 안내하지 않는다. 다크 모드의 모드 선택, TalkBack의 제스처·허용 창 등은 실제 기기별 검증이 필요하다. 확대 바로가기 활성화를 실제 확대 켜기로 오인하지 않는다.

모바일 데이터·비행기 모드·데이터 로밍·핫스팟 등은 연결 상태에 영향을 줄 수 있다. 모든 통신 경로를 끄면 서버가 이후 상태를 확인하지 못할 수 있다.

## 직접 진행과 개인정보

직접 진행 단계는 안전한 화면의 독립 제목을 확인한 뒤 구체적인 안내를 표시한다. 이후 Android 앱은 화면 업로드와 자동 조작을 멈추고, 완료 확인 버튼을 제공한다. 결과 요청은 접근성 트리를 포함하지 않는다. 비밀번호, SSID, 연결 기기 이름, 계정, 앱 선택 목록, 알림 내용 등은 새 전송 허용 목록에 추가하지 않았다.

앱 삭제·앱 데이터 삭제·전체 초기화의 최종 버튼은 그래프에서 대상으로 삼지 않는다. 안전한 상위 화면에서 데이터 삭제 가능성을 알리고 사용자가 기기의 경고·인증을 보고 직접 결정하게 한다. 이 단계에서 화면을 연 것만으로 작업을 완료하지 않는다.

기술 결과는 `UNVERIFIABLE / manual_result_required`로 남긴다. 사용자가 완료했다고 답하면 `USER_REPORTED_RESOLVED`로 기록한다. 검증된 변경인 `ACHIEVED`와 구분한다.

## 배포와 검증

백엔드와 APK를 함께 업데이트해야 한다. 실행 중인 기존 세션은 기존 그래프 해시를 유지한다. 예전 초안은 기존 DB에 남을 수 있지만 새 승인 버전이 별도 등록된다. 이 문서와 생성 카탈로그의 숫자는 실제 기기 호환율을 뜻하지 않는다.

원본 계약: `AI-Agent/goal_catalog/settings_execution.json`, 백엔드 경로: `Backend/app/task_graphs/settings_actions.py`.

## 2026-11-08 입력 연결 수정과 배포 조건

사용자가 입력한 “다크모드 키고 싶어”는 기존 키워드 `켜`와 일치하지 않아 입력 재질문으로 빠졌다. 동일한 문제를 막기 위해 켜기/끄기 목표의 공통 데이터에 `키고`, `키는`, `킬`, `켤`, `끄고`, `끄는`, `끌` 표현을 추가했다. Android 카탈로그와 Backend 카탈로그를 같은 값으로 유지한다. 입력을 해석한 것만으로 실행하지 않으며 목표 및 변경 동의는 유지한다.

새 회귀 검사는 사용자 문장으로 HTTP 목표 준비를 시작해 52개 켜기/끄기 목표의 실제 승인 그래프를 선택한다. 다크 모드는 `다크모드 키고 싶어`, `다크 모드를 켜고 싶어`, `다크모드 켜줘` 각각이 같은 그래프 해시로 `start_task`까지 이어지고 변경 동의를 기다리는지 검사한다. 부정 문장은 실행 목표나 그래프를 만들지 않는다. 화면과 모델 응답을 통제한 검사이며 실제 기기에서 다크 모드 변경 성공을 증명하지 않는다.

문제 확인 시 공개 서버 `/version`은 `3893b4616da27f255e4179a18b60a4125a4416f2`였고, 설치 APK는 앞선 6개 슬라이더 검증 APK와 같은 해시였다. 두 버전 모두 다크 모드는 `catalog_only`이고 입력 계약/승인 그래프가 없었다. 이 서버 소스로 “키고 싶어”는 일반 재질문, “켜줘”는 미지원 응답을 재현했다. `4bf3470` 역시 확장 코드가 없는 슬라이더 안정화 커밋이므로 그 커밋만 재배포하면 확장 기능이 활성화되지 않는다.

배포 시 이 확장 코드가 포함된 Backend와 AI-Agent를 함께 반영하고 공개 `/version.source_revision`이 실제 배포 커밋인지 확인해야 한다. 그다음 카탈로그 2.3.0과 확장 관측 계약을 포함한 앱을 업데이트한다. OpenAPI의 목표 enum이나 로컬 목록만으로 실제 승인 그래프가 서버에 배포됐다고 판단하지 않는다. 기존 세션을 임의 변경하지 말고 새 요청에서 확인한다.

- 전송한 조작 이벤트는 응답이 유실돼도 원래 ID·guide·시간을 보존한다. 일시적인 연결/서버 오류에는 작업을 즉시 실패 종료하지 않고 하나의 복구 화면에서 명시적 재시도를 기다린다. 재시도는 서버 상태를 먼저 동기화하며 기기 조작을 다시 실행하지 않는다.
- 관측 요청 도중 늦게 도착한 조작 증거가 있으면, 화면 없는 결과 확인 요청보다 원래 증거와 새 관측을 먼저 보낸다. 값이 바뀐 사실만으로 조작 증거를 만들어 내지 않는다.
- 완료 검증이 끝나지 않아도 `no_correlated_action`, 대상/적용값 관측 불가 등의 실제 이유를 보존한다. 두 개의 안정된 관측에서 요청과 반대 방향으로 바뀐 경우는 무변경과 별도로 기록한다. 기술 검증과 사용자 만족 보고는 계속 구분한다.
- 재연결용 `graph_id`가 빠진 승인 항목 81개를 실제 등록 그래프와 연결했다. 110개 승인 목표 모두 정확한 서버 그래프 ID에서 같은 목표로 복원되는지 검사한다. 목표 의미나 승인 상태를 바꾸지 않는다.

Backend 전체 1,745개, AI-Agent 전체 410개, Android 전체 513개가 통과했다. 전송 유실과 늦은 증거 두 서비스 회귀 사례는 수정 전에 실패하고 수정 후 통과했다. 갱신 APK 설치와 실행을 확인했으며 앱 데이터를 지우지 않았다. 변경 후 110개 전체의 실제 기기 동작이나 운영 서버 배포 완료를 의미하지 않는다. 원래의 밝기 사건은 원인 증거가 충분하지 않아 확인 불가로 보존했다. 자동 밝기가 켜진 상태는 관측했지만 원인으로 단정하지 않는다.

구체적인 범위·한계는 공통 신뢰성 검증 기록에 남겼다.


## 2026-11-09 Samsung 다크 모드 카드형 선택

이 기기에서 기록한 디스플레이 화면은 `라이트`/`다크` 카드이며, 클릭 가능한 컨테이너가 `checkable=false`다. 기존 다크 모드 그래프가 스위치만 대상으로 삼아 이 제어가 후보에서 빠졌다. 1.1.0 경로는 두 카드의 정확한 이름·리소스·독립 제목과 사용자 확인을 요구한다. 기존 스위치 경로도 유지한다.

카드 변경 완료는 원래 카드에 연결된 탭과 새 관찰, `UiModeManager.getNightMode()`의 명시적 모드 값 변경을 함께 확인해야 한다. 선택 장식만으로 성공을 만들지 않는다. 자동/예약 모드 값은 명시적 켜짐·꺼짐으로 간주하지 않는다. 이 경로는 선택 안내이며, 일반 자동 내비게이션 탭 목록에 카드 조작을 추가하지 않았다.

Backend 배포와 새 앱이 모두 필요하다. 기존 작업의 그래프를 바꾸지 않으며, 배포 후 앱을 다시 열고 새 요청으로 시작한다. 수정 앱의 시스템 모드 읽기는 실기기에서 확인했지만, 실제 카드 선택부터 완료까지는 아직 실측하지 않았다. 수정 범위와 한계.

## 소리 모드 확장 (2026-11-10)

무음 켜기·끄기와 진동 켜기·끄기를 단순 직접 진행에서 확인·대상 안내·실제 값 검증 경로로
전환했다. 무음 끄기와 진동 끄기의 목적지는 소리 모드다. 진동을 무음으로 취급하지 않는다.
Samsung의 소리·진동·무음 항목이 같은 Settings 창에 각각 하나씩 있고, 승인된 네이티브
리소스와 독립 화면 제목, 겹치지 않는 영역을 확인한 경우에만 대상 후보를 만든다.

변경 완료는 원래 안내 대상의 확인된 탭과 새 관측을 연결하고, `AudioManager.getRingerMode`의
실제 값이 요청한 모드로 바뀐 경우에만 판정한다. 이미 해당 모드면 새 탭을 안내하지 않는다.
시스템 값 누락·다른 모드·다른 대상·이전 관측·선택 표시만 있는 경우는 성공 증거가 아니다.
네트워크로 내보내는 모드 값은 해당 무음·진동 작업에서만 허용한다.

새 1.1.0 graph를 사용하며 실행 중인 기존 1.0.0 직접 진행 graph를 덮어쓰지 않는다.
이 경로도 기존 확인과 직접 탭 안내 계약을 따르며, 일반 메뉴 자동 클릭 허용 목록에
모드 버튼을 추가하지 않는다. 이 확장은 서버와 APK가 모두 갱신돼야 사용할 수 있다.
