# Agent 1-1 종료와 Agent 1 수동 안내 — 후속 구현 제안

3사이클 상태 관리, 실패 원인 분류, 재캡처 전략, Agent 1 수동 안내 반환을 구현했다.
공통 어휘와 화면 변경 감지도 적용되어 있다. 관측 복구 기본값 3회/5초는 AX 복구
예산이며 Vision/OCR 사이클 예산과 별개다. 실제 OCR 성능은 실기기에서 아직 검증하지 않았다.

현재 구현은 1회차 전체 화면, 2회차 최대 1.5배 확대(폭 상한 2048px), 3회차 AX 메뉴
container crop 또는 겹치는 두 영역 OCR을 사용한다. 매 캡처에 전체 화면 안전 검사를
먼저 수행하고, 마스킹 후 영역을 분석해 좌표를 전체 화면 px로 복원한다. 캡처·OCR
전체 작업 timeout은 10초다. 매 사이클 새 일회성 동의를 받는다.

세 번의 목표 미발견 후 `llm_fallback.status=not_configured`만 반환한다. 실제 LLM 호출과
자동 스크롤은 추가하지 않았다. `accessibility_tree_empty`와 `target_not_found`는 별도로
기록하며, 실제 화면 부재를 확정하지 않으므로 `absence_confirmed=false`를 유지한다.

2026-10-28 결정: **새 화면 캡처 → 기기 내 OCR → 허용 어휘·좌표 검사 → 목표 매칭**을
한 사이클로 정의한다. 같은 단계에서 이 사이클이 **3번 연속 실패하면** 최종 실패를
Agent 1에 반환한다. 1·2회 실패는 1-1 내부의 재시도 상태이며 최종 실패가 아니다.

## 권장 흐름

1. AI1이 AX로 다음 메뉴를 찾고, 기존 Vision 진입 조건에 해당하면 1-1로 관측을
   위임한다. 빈 AX의 즉시 Vision 요청 경로도 유지한다. 단순 AX 재관측을 Vision
   사이클 실패로 세지 않는다.
2. 1-1은 새 화면을 캡처하고 OCR·허용 어휘·좌표·목표 매칭까지 수행한다. 글자를
   읽었다는 것만으로 성공이 아니다. 현재 단계의 목표와 유효한 안내 좌표를 충분한
   신뢰도로 찾으면 즉시 `used`로 반환한다. 설정 변경 완료를 뜻하지는 않는다.
3. 재시도 가능한 실패가 1·2회 발생하면 해당 bitmap과 좌표를 폐기하고 같은 단계에서
   새 캡처부터 다시 시작한다. 3회째 실패에서 `failed / cycle_budget_exhausted`와
   마지막 실패 원인을 Agent 1에 반환한다. 기존에 제안했던 15초 상한으로 3회보다
   먼저 실패시키지 않는다. 캡처/OCR 각 작업에는 timeout을 두며 timeout은 해당
   사이클의 실패로 한 번만 센다. 동의 대기·사용자 조작 대기·pause는 실패가 아니다.
4. AI1이 graph에서 확실히 아는 저위험 메뉴 이름으로 “설정에서 ‘디스플레이’를 찾아
   눌러 주세요. 이동한 뒤 ‘다시 확인’을 눌러 주세요.”처럼 안내한다. 좌표·highlight·
   자동 tap을 만들지 않는다. 현재 단계/앱이 불명확하면 메뉴를 추측하지 않고 설정
   첫 화면으로 돌아가는 안내와 재확인을 제공한다.
5. 사용자가 ‘다시 확인’을 누르면 새 AX로 현재 상태를 분류해 AI1을 재개한다. 버튼을
   눌렀다는 이유만으로 단계 성공을 만들지 않는다. 계속 못 찾으면 graph 재선택 또는
   사용자 중단을 제시하며 같은 동의창/수동 문장을 반복하지 않는다.

## 실패 분류와 카운터

| 상황 | 처리 |
| --- | --- |
| 일시적 캡처 실패·OCR 오류·작업 timeout | 사이클 실패 +1, 3회 미만이면 재시도 |
| 허용된 글자 없음·목표 없음·저신뢰·복수 후보 모호성 | 사이클 실패 +1. 임계값을 낮추거나 임의 후보를 고르지 않고 재시도 |
| 목표와 좌표를 유효하게 찾음 | 즉시 성공 반환, 해당 단계의 연속 실패 카운터 종료 |
| 화면 변경·오래된 관측·취소된 결과 | 해당 결과 폐기, 실패 횟수는 증가시키지 않음. 새 AX로 AI1이 같은 단계인지 다시 확인 |
| 사용자가 화면 분석을 거절 | `declined`로 즉시 종료. 실패 횟수로 세거나 남은 횟수를 자동 실행하지 않음 |
| 민감 화면·마스킹 실패 | `blocked`로 즉시 종료. 횟수를 채우려고 다시 캡처하지 않음 |
| 미지원 OS·앱·어휘 또는 캡처 capability 부재 | `unsupported`로 즉시 종료. 일시적 캡처 오류와 구분 |
| 사용자 취소·세션 교체·만료 | 종료, 진행 중/늦게 도착한 결과 폐기 |

카운터는 `session_id + episode_id + task_id + step_id` 범위에 저장한다. 매 캡처의
`screen_revision`/`observation_id`가 바뀌었다는 이유만으로 카운터를 0으로 만들지
않는다. 같은 HTTP 요청 재전송·콜백 중복은 `cycle_id`로 중복 제거하고 한 번만 센다.
화면이 바뀌어 재관측하더라도 AI1이 같은 단계라고 판정하면 기존 카운터를 이어간다.
단계 진행·새 작업에서 새 예산을 시작하고, 실패 반환 후 일반 observe가 온 것만으로
같은 단계에 3회를 자동 재부여하지 않는다. 재분석은 명시적인 새 요청으로 시작한다.

화면이 계속 바뀌어 유효한 사이클을 못 만드는 경우에는 무한 재캡처하지 않는다.
`waiting_for_stable_screen`으로 멈춰 새 AX와 사용자의 재확인을 기다린다. 이는
“OCR이 3회 실패했다”는 반환과 구분한다.

## 재시도 방법과 동의

아래 재시도 전략을 구현했다. 동일 입력 반복만으로 성공률이 높아진다고 가정하지 않으며
전처리별 인식 개선 효과는 별도 비교 평가해야 한다.

1. 1회차: 안정된 새 캡처의 전체 화면 OCR.
2. 2회차: 화면 안정화를 기다린 새 캡처. 작은 글자 실패라면 확대 입력을 비교한다.
3. 3회차: 새 캡처에서 AX로 근거가 있는 메뉴 영역을 crop해 OCR한다. 근거 있는 영역이
   없으면 임의로 잘라내지 않고 전체 화면 대체 전처리를 평가한다.

확대/crop은 기기 안에서 개인정보 마스킹 **이후** 수행한다. crop offset과 scale을
역변환해 전체 화면 물리 px 좌표를 복원한다. 이전 캡처의 후보를 새 캡처 좌표로
합치거나, 3회 실패를 피하려고 confidence 기준을 낮추지 않는다. ML Kit도 입력의
글자 픽셀 크기와 품질이 인식에 영향을 준다고 설명한다.
([공식 입력 가이드](https://developers.google.com/ml-kit/vision/text-recognition/v2/android#input-image-guidelines))

현재 동의 계약은 `single_analysis`다. 따라서 계약을 유지한 구현에서는 각 캡처 전에
새 일회성 동의를 받아야 한다. HTTP 재시도나 과거 boolean 동의로 재캡처하지 않는다.
확인창 한 번으로 3사이클을 허용하려면 별도의 제한된 묶음 동의 계약이 필요하다.
그 경우 “현재 단계에서 최대 3회 분석”을 명시하고 BE에서 batch ID·남은 횟수·만료·
세션/단계 범위를 검증해야 한다. 현 계약이 묶음 동의를 이미 지원한다고 간주하지 않는다.

## 반환 정보

1-1은 독립 상시 프로세스가 아닌 관측 fallback이므로 “종료”는 해당 분석 호출을
끝내고 결과를 AI1에 돌려주는 의미다. 반환 계약은 다음 항목으로 제안한다.

- 중간 상태 `status`: `retrying`, `waiting_for_stable_screen` — 최종 실패 반환 아님
- 최종 `status`: `used`, `failed`, `declined`, `blocked`, `unsupported`, `cancelled`
- `reason`: 캡처·OCR·마스킹·화면 변경 등의 제한된 코드
- `failed_cycles`, `max_failed_cycles=3`, `last_cycle_reason`: 예산과 마지막 원인
- `return_to`: `agent1`
- `next_action`: `match`, `manual_navigation`, `fresh_observation`, `stop`

`no_signal`, `target_not_found`, `low_confidence`, `ambiguous_target` 등은 개별 사이클의
원인으로 기록한다. 첫 `no_signal`을 곧바로 최종 실패나 수동 안내로 처리하지 않는다.

사용자에게 보여줄 메뉴 이름/문장은 AI1이 승인된 graph에서 만든다. 1-1이 OCR 글자로
새 단계를 생성하지 않는다. 이미지를 버린 후 유효한 OCR 결과 또는 실패 코드만
반환하며, 취소된 분석 결과는 기존처럼 폐기한다.

## 경계와 다음 구현 순서

- 사용자의 명시적인 목표 취소는 전체 안내 종료다. 분석 거절과 같은 처리로 묶지 않는다.
- 민감 화면·안전 차단은 조작을 유도하는 수동 안내로 우회하지 않는다. 화면을 벗어나는
  안내만 제공한다. slider/설정값/완료 판정에는 기존 AX 증거와 승인 정책을 유지한다.
- 먼저 1-1의 3사이클 상태/중복 제거와 재시도 가능한 오류 분류를 구현한다. FE의
  캡처·OCR 실패 보고와 BE의 `rejected = BLOCKED` 일괄 처리를 분리해야 한다. 현재
  `recovery.py`의 `vision_failed` 즉시 사용자 대기 처리도 1·2회에서 실행되지 않아야 한다.
- 다음으로 재캡처 전략·좌표 역변환을 추가하고 동의 계약을 연결한다. 최종 반환과
  AI1 수동 대기 상태를 연결한 뒤 FE의 ‘다시 확인’ UI를 연결한다.
- 1회 성공, 1실패 후 성공, 2실패 후 성공, 3연속 실패, 사이클 중 timeout, 같은 요청
  중복, 관측 변경 후 카운터 유지, 새 단계 초기화, 동의 거절, 안전 차단, 취소·교체 중
  늦은 결과를 host/HTTP/JVM 테스트로 검증한다.
- 모델 품질 평가는 1회차 성공률뿐 아니라 2·3회차가 추가로 구한 비율, 잘못된 목표
  안내율, 좌표 오차, 최종 포기율, 전체 지연을 분리한다. 현재 4개 OCR-element fixture는
  이미지 인식·전처리 품질을 검증하지 못하므로 화면 자료/합성 이미지 사례를 추가한다.
