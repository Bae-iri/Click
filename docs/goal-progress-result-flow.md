# Click 목표·진행·결과 확인 변경 기록

## 추가 확인·음성·설정 경로 수정 (2026-10-29)

재확인: 진행 안내뿐 아니라 추가 질문·행동 승인·결과 질문도 줄이면 말풍선으로 유지한다. 펼칠 때 숨기기 전 버튼 표시 상태를 복원한다. 입력창 때문에 끊긴 음성 또는 입력 중 도착한 안내는 창을 닫을 때 현재 대화의 문장 하나만 다시 읽는다. 반복 관측에 따른 자동 재생 차단은 유지한다.

복원 수정 검증: JVM 54개와 실제 오버레이·결과 카드·튜토리얼 UI 13개 통과. 입력 창 왕복 중 음성 중단/재개, 최신 안내 한 번 재생, 결과 질문의 축소/확대 및 답변 버튼 복원을 확인했다. Samsung 휴대폰에 APK를 덮어쓰고 앱 실행 및 접근성 서비스 연결을 확인했다.

실서버 슬라이더 회귀를 `LiveFontGuideTest`로 재현했다. `https://click-db.onrender.com`은 MVP-01 `1.0.0`(`670fb0ef…`)을 반환했고 삼성 통합 글자 화면을 `S3_FONT_MENU`로 분류하여 `TARGET_AMBIGUOUS`, 대상 없음으로 응답했다. 로컬 APK 설치만으로 이 서버 오류는 고쳐지지 않는다. 원격 최신 `d07b4f1`에 서버 수정만 합친 `cf976d5`를 `/private/tmp/click-font-deploy-review`에 준비했다. 삼성 슬라이더·결과 확인·설정 복구 155개와 최신 vision/배포 회귀 69개가 통과했다. 2026-10-30 사용자가 pull·push를 요청하여 최신 develop과 앱·서버 수정을 병합했다. 병합 후 Android 단위 테스트 232개, 에이전트 테스트 227개, 서버·Android 요청 연동 테스트 1,002개가 통과했다. Android 앱·테스트 APK 빌드와 서버 스모크·부하 검사도 통과했다. 운영 서버 반영 여부는 푸시 후 CI·배포 및 실서버 응답으로 별도 확인한다. 이전 develop CI에는 Android SDK의 tools 패키지 설치 오류와 PostgreSQL JSON/JSONB 스키마 불일치가 확인되었다.

추가 질문의 “추가로 확인할게요” 제목을 제거하고, 요청 라벨은 굵은 16sp, 요청 본문은 16sp로 표시한다. 수정 입력은 “내용 수정”으로 펼치며 창은 선택지와 버튼의 실제 높이에 맞춘다. 화면 질문과 TTS는 같은 `GoalPreparationState.guidance()`를 사용한다.

튜토리얼·권한 화면·플로팅 서비스는 프로세스 전체에서 하나의 한국어 TTS 엔진을 공유하며, 마지막 사용 화면/서비스가 닫힐 때 엔진을 종료한다. 화면 안내가 서비스보다 우선하고 화면을 떠나면 해당 화면의 발화를 취소한다. 220ms 이내 연속 갱신은 마지막 안내만 읽고, 이전 발화의 늦은 콜백은 현재 재생에 영향을 주지 않는다. 같은 작업 단계의 반복 관측은 문구·노드 위치가 바뀌어도 재생을 다시 시작하지 않는다. 다시 듣기와 작업 재개는 사용자가 명시적으로 요청한 재생으로 처리한다.

새 질문을 요청하거나 입력·녹음으로 전환하면 현재 발화를 취소하지만 다음 단계의 음성 안내는 계속 허용한다. ‘줄이기’는 읽던 음성을 끊지 않는다. 자동 스크롤의 중간 상태는 말하지 않으며, 최종 화면 안내만 발화한다. 미디어 무음·오디오 포커스 실패·TTS 오류나 응답 지연은 안내문으로 전환하고 같은 안내의 자동 재시도를 막는다. `ClickNarration` 로그에는 발화 ID, 상태와 문자 수만 기록한다.

TTS 수정 검증: JVM 52개(발화 관리자 13개·서비스 39개), 입력/튜토리얼 UI 3개 통과. 연결된 Samsung SM-N981N의 `com.samsung.SMT`에서 고정 한국어 문장 재생과 서비스→화면 전환 테스트 2개 통과. 로그에서 취소한 이전 안내는 시작되지 않고 현재 문장은 각각 한 번 시작해 정상 완료되는 것을 확인했다. APK는 사용자 데이터를 유지하는 덮어쓰기로 설치했다. 이 검증은 음성 재생과 화면 흐름을 대상으로 하며 실제 사용자 요청의 전체 서버 실행이나 음성 인식 정확도 검증은 포함하지 않는다.

글자 크기 graph 1.0.1은 디스플레이 항목이 안 보인다는 이유로 접근성을 선택하지 않는다. 설정의 다른 하위 화면임을 제목과 뒤로 버튼으로 확인하면 `SETTINGS_OFF_PATH`/`navigate_back`을 반환한다. 앱은 최신 화면과 설정 window가 같은지 확인한 뒤 한 단계 돌아가며, 같은 화면에서 반복하지 않고 연속 복귀 횟수도 제한한다.

조절 승인 때도 슬라이더 위치를 먼저 강조한다. 정상 조작은 기존의 실제 행동·값·FONT_SCALE 검증을 유지한다. 처음부터 끝값인 경우에는 해당 슬라이더와 최대·최소 상태를 표시하고 사용자 요청 전에는 결과 질문을 띄우지 않는다. 앱은 글자 크기 조절 전에 “결과 확인하기” 버튼을 노출하지 않는다.

## 실행 계약

Click은 **실행 전에 사용자 요구를 확인**한다. 대상·범위·방향 확인 상태는 내부에서 관리하며 화면에는 체크리스트를 표시하지 않는다. 글자 크기 요청에서는 대상 앱, 적용 범위, 변경 방향을 확인한다. 입력에 있는 정보는 먼저 채우고 누락된 정보만 질문한다. 휴대폰 기본 글자와 특정 앱 안의 글자를 구분하며, “전체”라는 말만으로 휴대폰 전체 설정을 선택하지 않는다. 사용자가 “이 내용으로 시작”을 누르거나 명시적으로 동의한 뒤에만 `start_task`를 보낸다. 빠른 도움 카드에도 같은 확인을 적용한다.

서버가 `goal-inputs.v1`을 지원하면 앱은 음성·텍스트·빠른 도움 요청을 모두 실제 `resolve_goal` API에 보낸다. 키워드와 자체 LLM이 요청의 작업 종류와 명시된 입력값을 해석하고, 서버가 task graph 입력 조건에서 빠진 항목을 찾아 질문한다. `RequirementReview`의 로컬 질문은 해당 계약을 지원하지 않는 구버전 서버와 튜토리얼용으로 유지한다. 새 서버의 질문은 `GoalPreparationState`와 `TaskFlowOverlayView.preparation`에서 표시한다.

“글자 크기 키워줘”는 방향만 확인된 요청이다. 설정 화면을 보고 있어도 서버는 적용 범위를 추측하지 않고 다음 두 선택지를 반환한다.

- 휴대폰 설정에서 기본 글자 크기 변경
- 특정 앱 안에서만 변경

특정 앱을 고르면 앱 이름을 추가로 받는다. 현재 카카오톡 등 앱 내부의 글자 변경에는 승인된 그래프가 없으므로 미지원 상태를 반환하며 시작 버튼을 표시하지 않는다. 휴대폰 설정을 고르면 입력 조건을 검증한 뒤 실제 승인 그래프를 선정하고, 사용자의 최종 확인을 기다린다.

사용자가 확인한 요구는 실행 중에도 내부에 유지된다. Agent의 Graph 경로 및 화면 관측은 실행/검증 근거로만 쓴다. 요청은 콜아웃으로 보여주고, 질문과 다음 행동은 음성으로 안내한다. 다시 듣기·음성 멈춤·글로 보기를 제공하며 TTS 오류·음성 지원 불가·미디어 음량 0에서는 안내문을 펼친다.

최종 설정 변경은 세션/episode, guide/attempt, 동일 대상, 실제 tap/drag, 기준 관측 ID·시각·값, 행동 시각, 새 관측 ID·시각·값을 연결한다. Android에서는 슬라이더 변화와 `Settings.System.FONT_SCALE`의 동일 방향 변화가 함께 있어야 `CHANGED`가 된다. OCR, 다른 대상, 중복 이벤트, 오래된 관측, 값 불변, 관측 누락으로 성공 처리하지 않는다. 끝값에서는 조작을 중단하고 이유를 저장한다.

`FONT_SCALE`은 Android가 저장한 글자 배율 환경설정이다. 앱별 렌더링이나 시각적 편안함을 증명하지 않으므로 사용자 확인이 별도로 필요하다. Android 14 이후에는 글자 확대가 비선형일 수 있다.

- [Android Settings.System](https://developer.android.com/reference/android/provider/Settings.System#FONT_SCALE)
- [Android 14 글자 확대](https://developer.android.com/about/versions/14/features#non-linear-font-scaling)

## 그래프 입력 조건과 답변 계약

입력 정의는 `Backend/app/task_graphs/input_requirements.json`에 있다. 각 작업 종류에 필드 ID·라벨·질문·선택지·텍스트 제한·조건부 필수 항목을 정의한다. 예를 들어 `app_name`은 `scope=app`일 때만 필요하다. 새 필드를 추가하면 서버가 빠진 값의 질문을 만들고 앱이 해당 질문을 표시한다. 앱에 글자 크기 전용 버튼 분기를 추가할 필요가 없다.

`goal_slot`은 입력값을 카탈로그의 실행 슬롯과 연결한다. `routes`는 적용 범위와 실행 대상 앱을 연결한다. 질문에 답했다고 새로운 앱이나 행동이 지원되는 것은 아니다. 앱별 작업을 늘리려면 입력 조건과 함께 typed goal·승인 그래프·실행 검증기를 등록해야 한다.

첫 요청은 다음 필드를 기존 v0.3 `resolve_goal`에 추가한다.

```json
{"preparation_version":"goal-inputs.v1","source_text":"글자 크기 키워줘"}
```

서버 응답의 `preparation`에는 확인 ID, 입력값, 필수/누락 필드, 현재 질문, 만료 시각이 들어간다. 모든 필수 값이 모이고 실제 그래프를 찾았을 때만 `goal`과 `graph_reference`가 반환된다. 그 전에는 실행할 목표를 반환하지 않는다.

```json
{
  "goal_resolution_id":"응답의 preparation.id",
  "clarification_answer":{"question_id":"응답의 question.id","value":"system"}
}
```

답변은 원래 사용자 발화에 문자열로 덧붙이지 않는다. 현재 질문 ID와 값으로 전달하며 서버는 필드별 허용 값을 검증한다. 시작 요청은 `preparation_version`, 최신 `goal_resolution_id`, 응답의 `goal`을 함께 전송한다. 서버가 확인한 목표와 요청 목표가 다르거나 필수값이 빠졌거나 선정 그래프가 바뀌었으면 실행하지 않는다. 확인 절차에 들어온 세션은 클라이언트가 버전 필드를 생략해도 확인 ID 없이 시작할 수 없다.

질문·답변은 `agent_goal_resolutions`에 사용자·세션별로 저장한다. 같은 발화로 재접속하면 답변을 복원하고, 동일 요청 ID의 재전송은 같은 응답을 돌려준다. 답변 변경·초기화는 이전 확인 결과를 무효화한다. 만료된 질문, 취소된 큐 요청, 다른 사용자·세션의 ID는 거절한다. 확인 결과의 유효 시간은 10분이며 실제 저장 정리는 기존 maintenance 보존기간 설정에 따른다. 실행 승인은 복원하거나 다른 실행에 재사용하지 않는다.

## 자체 LLM과 서버 적용

자체 LLM의 URL·모델·인증 설정은 [추론 서버 실행 문서](../Backend/inference/README.md)를 따른다. 모델은 작업 종류와 입력값을 제안하며, 질문 목록·필수값·실행 가능 여부는 서버의 입력 계약과 승인 그래프로 검증한다. LLM이 임의로 반환한 `scope=system`은 누락된 적용 범위를 채우는 근거로 사용하지 않는다. 모델이 없어도 키워드로 파악한 작업에는 실제 입력 조건에 따른 질문을 제공한다.

이 브랜치의 DB 마이그레이션 순서는 `20261009_10` 결과 응답 → `20261009_11` 이름 → `20261011_12` 목표 확인·결과 기록이다. 기존 미반영 파일의 중복 revision을 제거했다. `develop`의 별도 `20261010_11` 마이그레이션 이력과 병합할 때는 배포 DB의 현재 revision을 확인하고 이력을 먼저 통합해야 한다. 운영 DB에 이미 적용한 revision을 임의로 다시 지정하지 않는다.

이번 연결은 실제 API·DB·승인 그래프·Android 계약 테스트로 검증한다. 모델 응답 테스트에는 대역을 사용하며, 실제 LLM 추론 품질과 휴대폰에서의 최종 동작은 별도 검증 대상이다.

## 입력 전 자동 음성 안내 방지

오버레이 서비스 생성 시 서버의 이전 요청을 자동 claim하지 않는다. 앱 실행과 음성 입력창 열기는 녹음이나 TTS를 시작하지 않는다. 글·음성 요청을 실제로 제출하거나 빠른 도움을 선택한 뒤 음성 안내를 허용한다. 단순히 입력창을 여는 동작은 발화를 허용하지 않는다. 명시적인 다시 듣기도 음성을 재생한다. 또한 입력 모드 전환·새 녹음 시작·중지는 대기 중인 TTS도 지운다. 늦게 도착한 안내가 녹음을 끊거나 입력 전에 말하지 않도록 `speak`에서 음성 답변 허용 상태를 검사한다.

## 두 결과 축과 세션

기술 결과 `CHANGED / NOT_ACHIEVED / UNVERIFIABLE`과 사용자 답변 `satisfied / needs_help / stopped / no_response`를 `task_outcome`에 별도 보관한다. 기술 검증 시각과 사용자 응답 시각도 별도다.

기술 검증 후 `WAITING_RESULT`에서 질문을 받는다. 긍정 답변이 있어도 기술 값은 덮어쓰지 않는다. 기술 검증 불가 + 긍정은 `USER_REPORTED_RESOLVED`로 저장된다. 불편하면 `WAITING_ADJUSTMENT`에서 원인을 확인하고 추가 조정은 새 episode로 시작한다. 이전 결과는 `outcome_history`에 보관된다. 최대/최소에서는 같은 방향을 다시 제안하지 않는다.

결과 질문은 180초 후에도 무응답을 별도로 기록한다. pause/resume은 결과 대기 상태와 질문 ID·내용을 보존하며, 재개 시 답변 기한을 재개 시각부터 180초로 갱신한다. 같은 재개 요청의 재전송은 기존 응답을 복원하고 답변 기한을 다시 늘리지 않는다. HTTP 응답·queue 콜백·완료 화면 콜백은 실행 세대와 세션 버전으로 구분해 취소 후 늦은 응답이 작업을 되살리지 못하게 한다.

Agent 2에는 `graph_proposal/outcomes.py`의 오프라인 요약 함수를 추가했다. 두 결과 축과 검증 근거를 별도로 집계한다. 자동 학습·Graph 자동 수정·배포는 추가하지 않았다.

## 앱 통합과 가입

`design-preview`는 독립 APK에서 Android UI 라이브러리로 전환했다. 설치 앱은 `com.click`, 이름은 `Click` 하나다. 새 스플래시·온보딩·가입 화면과 실제 인증/접근성/오버레이가 같은 APK에 들어간다. `ClickHost`는 UI 모듈과 앱 기능을 연결하며 테스트용 가짜 회원가입을 제거했다.

온보딩은 3페이지이고 마지막 버튼은 회원가입/로그인이다. 가입 첫 단계에서 이메일을 재확인한 뒤 나이·직업으로 이동한다. 직업은 큰 단일 선택 카드가 있는 하단 창으로 표시한다. DB 중복(409)이면 이메일을 유지해 로그인으로 이동할 수 있다. 비밀번호 가입·로그인·변경·재설정의 서버 최소 조건은 8자다. 이메일 확인 창은 주소 재확인이며 이메일 발송 완료나 소유권 인증을 의미하지 않는다.

접근성의 “나중에 설정하기”는 필요 이유·설정 이동·앱 닫기 안내 화면에 연결된다. 허용하면 예전 모의 튜토리얼 대신 같은 앱의 접근성 준비 화면을 연다. 터치로 시작할 수 있고 마이크는 선택적으로 요청한다.

## 검증과 한계

로컬 자동 테스트와 에뮬레이터 UI 검증은 실기기 설정 변경 성공과 구분한다. Android/OEM마다 실제 touch/drag 이벤트 및 RangeInfo 노출이 달라질 수 있으므로 지원 휴대폰에서 별도 확인이 필요하다. 읽을 수 없는 경우 기술 결과는 검증 불가다.

운영 서버 `https://click-db.onrender.com/openapi.json`을 2026-10-09에 읽기 전용 조회한 결과 비밀번호 최소값은 아직 12이고 `resolve_goal`은 없다. 이번 로컬 수정만으로 운영 서버가 갱신되지는 않는다. 서버 코드·migration·Agent runtime을 함께 배포해야 새 앱의 8자 가입과 새 작업 API가 동작한다. 운영 DB 변경이나 서버 배포는 수행하지 않았다.


### 서버 입력 확인 연결 검증 (2026-10-11)

- 요청 준비·범위/앱 이름/방향 질문·실제 그래프 선정·결과 확인·STT→LLM 연결 API 테스트: 최종 46개 통과. 실제 모델 응답은 테스트 대역을 사용했다.
- Android 앱 JVM 테스트: 100개 통과. `assembleDebug` 성공. 현재 서버 스키마를 테스트 fixture로 사용한다.
- 새 SQLite DB에 `20261011_12`까지 migration 적용 성공. 운영 PostgreSQL과 `develop`의 다른 migration 이력 통합은 별도다.
- 전체 Backend 소스 스냅샷: 778개 중 771개 통과, 7개 실패. 그중 자체 LLM HTTPS 정책에 맞지 않던 STT 연계 테스트 설정을 수정했고 위 46개 검사에서 재검증했다. 전체 검사를 다시 실행한 수치로 합산하지 않는다.
- 남은 회귀 실패 6개: `test_new_agent_commands`의 기존 결과 응답 2개는 `COMPLETED` 기대와 실제 결과 확인 대기 흐름이 다르다. `test_vision_consent`의 4개는 `WAITING_RESULT` 기대와 실제 `BLOCKED` 응답이 다르다. 성공 조건을 완화하거나 개인정보 검사 실패를 성공으로 바꾸지 않았다. 결과/화면 복구 계약을 통합할 때 정리해야 한다.

설치 파일은 `Frontend/app/build/outputs/apk/agent-goal-inputs/click-agent-goal-inputs-debug.apk`다. 같은 디렉터리의 `verification.json`에 APK 해시, 테스트 결과와 제한을 기록했다. 전체 검사 중 다른 작업의 수정이 확인되어 고정된 소스 복사본에서 빌드·검사했다. 실제 LLM/STT 서버 추론, 운영 배포, 휴대폰에서의 질문 선택→설정 변경 검증은 수행하지 않았다.

### 요구 확인·자동 발화 수정 검증 (2026-10-09)

Android JVM 66개, 요구 확인/튜토리얼/실제 오버레이 UI 8개가 통과했다. 음성 입력 전에는 TTS를 실행하거나 지연 재생용으로 저장하지 않는지, 입력창 열기만으로 녹음하지 않는지, 모드 전환 시 대기 음성을 지우는지 확인했다. 명시적으로 확인한 휴대폰 기본 글자 목표의 실제 서버 start_task → ai_agent.runtime 안내 → cancel_task 연결 테스트도 통과했다. 서버 연결 검증은 합성 설정 화면을 사용했으며 기기의 글자 크기를 실제로 변경하지 않았다.

### 플로팅 크기·음성 중심 안내 (2026-10-10)

기존 말로 시작/글로 입력 메뉴의 크기는 유지한다. 요청 안내창 폭은 같은 최대 344dp를 사용하고, 높이는 내용에 맞춰 측정하되 표시 가능한 화면 영역을 넘지 않는다. 긴 요청은 접어 두고 펼칠 수 있으며 본문은 내부 스크롤을 사용한다. 시작·중지 버튼은 본문 밖에 유지하고 요청 수정 키보드가 뜨면 안내창 높이를 가용 영역에 맞춘다. 제목은 공통 ClickUi.title의 Pretendard 스타일을 사용한다. 확인 질문을 상시 본문에서 제거하고, 요청 콜아웃 안에 수정 버튼과 해석한 요청 요약을 배치했다.

검증: Android JVM 67개, 플로팅 카드·실제 오버레이·튜토리얼 UI 9개 통과. 키보드 포커스와 투명한 IME 도구막대 영역을 확인하고 카드가 높이 0으로 줄어들지 않도록 수정했다. 연결된 Samsung 휴대폰에 최종 debug APK를 업데이트했다.

### 실제 체험 튜토리얼과 가입 안내

- 튜토리얼은 실제 `ClickOverlayLayout`과 `TaskFlowOverlayView`를 공유하며 9단계로 진행한다. 요청 범위 선택과 확인, 음성 인식 결과 확인, 요청 중지, 접기, 실제 이동, 휴지통에 숨기기, 다시 보기를 수행해야 해당 단계를 완료한다.
- 음성 입력은 버튼을 누를 때만 `DeviceSpeechInput`의 온디바이스 인식을 실행한다. 튜토리얼은 실제 녹음 없이 고정 예시로 진행한다. 화면 이탈·취소 시 인식과 지연 콜백을 취소한다.
- `TutorialNarrator`가 단계 안내를 읽으며 다시 듣기·음성 멈춤을 지원한다. 마이크를 시작하기 전에 안내 음성을 멈춘다. TTS 완료 후 자동 녹음은 없다.
- 홈·실제 오버레이·튜토리얼 모두 꾹 누르면 휴지통을 표시하고, 휴지통에 놓아야 숨긴다. 제자리에서 놓거나 취소하면 버튼을 유지한다.
- 이메일 확인창과 직업 단일 선택 목록은 Pretendard, Click 버튼·색상·모서리를 사용한다. 직업 표시 원은 텍스트와 별개로 중앙 정렬한다.
- 접근성 서비스 이름은 `click 화면 안내`, 안내 경로는 `설치된 앱 → click 화면 안내 → 허용하기`다. 화면 글자를 읽어준다는 기능 카드는 제거했다.
- 요청 콜아웃의 ‘내 요청’은 16sp, 본문은 18sp로 확대하고 ‘내용 수정’을 제목 오른쪽에 정렬했다.

검증: JVM 67개와 관련 UI 회귀 14개 통과. 가입·직업·권한·요청 확인·휴지통 화면은 에뮬레이터 캡처로 검토했다. STT UI 테스트는 주입한 음성 결과 콜백으로 수행했으며 실제 사람의 발화 인식 품질은 자동 검증 범위에 포함하지 않았다.

튜토리얼 하이라이트 위치 보정: 부모 캔버스의 좌표 계산은 플로팅 창의 translation과 화면 갱신 시점에 따라 어긋났다. 각 대상 버튼의 `ViewOverlay`에 테두리를 붙여 이동·스크롤·키보드 레이아웃과 함께 그리도록 변경했다. 완료한 동작의 강조와 배경 그림의 강조를 제거했다. 튜토리얼 UI 2개가 통과했으며 메뉴 이동 전후, 키보드 위 전송, 마이크, 요청 중지, 접기의 위·왼쪽 테두리 픽셀을 검증했다.

튜토리얼 음성 입력 수정: 실제 Samsung 휴대폰의 인증은 유효했지만 합성 WAV를 보낸 STT 서버가 HTTP 503을 반환했다. 튜토리얼은 기기 한국어 음성 인식을 우선 사용하고 준비 상태·중간 결과를 표시하도록 변경했다. 서버 STT는 명시적 재시도에서만 사용한다. 서버 처리 제한보다 짧았던 음성 요청의 읽기 타임아웃을 15초에서 40초로 늘리고 오류를 권한·인증·서버·무음으로 구분한다. 서버의 503 자체가 해결된 것은 아니다. `TutorialNarrationText`로 예시 줄을 음성 안내와 다시 듣기에서 제외한다. 강조색은 주황색을 제거하고 흰색·짙은 중립색 테두리로 변경했다. JVM 69개, 튜토리얼 UI 2개 통과. 서버 진단은 소리 재생이나 사용자 녹음 없이 합성 파일로 수행했다.

최종 튜토리얼 강조는 다시 Click 파란색으로 통일했다. 대상 버튼의 테두리는 1.2초마다 천천히 밝아졌다 돌아오며 항상 보이는 밝기를 유지한다. 포커스를 잃거나 대상이 사라지면 애니메이션을 멈추고 시스템의 애니메이션 사용 설정을 따른다. 첫 안내와 TTS는 ‘아래 클릭 버튼을 눌러보세요’로 변경했다. 변경 후 튜토리얼 UI 2개 통과.
