# 안내 복구 버튼과 지연 점검

## 확인한 원인과 수정

- 정상 진행·정부24 입력 질문·일시정지·4초 대기에서 `이유·다시 확인`을 표시하던 조건을 제거했다. 실패·화면 읽기 복구·서비스 오류 화면에서만 표시한다. 기다림이나 사용자 입력 요청은 실패로 취급하지 않는다.
- 줄이기에서 숨길 섹션 목록에 도움 버튼이 빠져 있어 본문과 실행 버튼이 사라진 상태에서도 도움 버튼만 남았다. 도움 버튼도 함께 접고, 펼치면 재시도 등 이전 화면의 버튼을 복구한다. 새 정상 화면으로 전환할 때는 이전 도움 버튼의 표시 상태를 복원하지 않는다.
- 도움창은 열면서 실행을 일시정지하는데, 그 동작으로 실행 세대 번호가 바뀐다. 클릭 핸들러가 열기 전 번호와 비교해 재시도·수정·평가를 무시하던 결함을 고쳤다. 현재 도움창 객체와 세션으로 소유권을 확인하고, 같은 작업의 명시적 재시도는 진행한다. 다른 세션으로 바뀌거나 닫힌 도움창의 콜백은 거절한다.
- 도움창의 다시 확인은 실제 `resume_task` 요청으로 연결한다. 일시정지 응답 전 클릭도 기존 제어 큐를 거쳐 순서대로 처리하며 고정 250ms 지연을 제거한다.
- 종료된 작업에는 사용할 수 없는 다시 확인 버튼을 숨긴다. 서버가 진행 중 요청 수정 API를 제공하지 않을 때는 비활성 수정 버튼 대신 `수정한 요청 보내기`로 새 요청을 명시적으로 큐에 추가한다. 기존 작업을 수정했다고 주장하지 않는다.

## 속도 관련 변경

- 공개 서버 기능 계약만 60초 캐시한다. 사용자 세션·인증 토큰·현재 화면은 캐시하지 않는다. 만료·계약 충돌 시 다시 읽으며, 조회 실패·미지원 계약을 캐시하거나 만료된 계약으로 진행하지 않는다. 전체 계획 생성과 분류·큐 왕복은 계속 필요하므로 첫 안내 전체가 2초 빨라졌다는 주장은 하지 않는다.
- 공통 앱 안내의 15초 요청 예산을 실행 큐에 넣은 시점부터 계산한다. 이미 큐에서 예산을 다 쓴 요청이 또 12초 HTTP 대기를 시작하지 않는다.
- 공통 앱 안내 로그에 `queue_ms`, `work_ms`, `total_ms`를 추가하고, 학습·앱 안내·큐 완료·재개 조회의 HTTP 경로를 구분한다. 동적 세션·요청 ID는 자리표시자로 바꾼다. 입력문·화면 내용·키는 기록하지 않는다.

## 검증

초기 집중 회귀 18개와 최종 관련 UI·네트워크·실행 회귀 625개를 통과했다. 마지막 중단 상태 보호까지 반영한 도움창 서비스 검사 3개를 다시 통과했다. 정상 진행·입력·대기·일시정지에서 도움 버튼 숨김, 실패 시 재시도 클릭 전달, 줄이기/펼치기에서 버튼 복원, 일시정지 중 실제 재개 요청, 세션 교체·작업 중단 후 옛 클릭 거절, 서버 계약 재사용·만료·실패와 전송 전 예산 소진을 검사했다.

최종 Debug·Release APK 빌드와 두 변형의 전체 Lint를 통과했다(Lint 오류 0개). 전달용 APK는 새 시간 로그를 확인할 수 있는 Debug 테스트 빌드이며 기존 개발 키로 서명되어 있다. 기기 연결이 없어 이번 수정의 실기기 클릭·응답 시간 검사는 수행하지 못했다.

병행 반영된 `0c5f509`의 벨소리·설정 변경 증거 보존 수정까지 통합한 최종 관련 회귀 630개와 Debug·Release APK·전체 Lint를 다시 통과했다.
