## settings_sound

T는 3번 모두 제목 "소리 및 진동"을 묶었다. 모델 없는 화면 덤프에서 이 제목이 실제 목적 화면의 제목임을 확인했다. 하네스 정답은 이 화면에 없는 "소리 모드" 라벨을 찾으므로 두 팔 모두 "미도달 + 거짓 완료"로 집계됐다(B 2, C 3). 정답 조건을 고친 뒤 다시 확인해야 하지만, T의 판정이 틀렸다는 근거는 없다. 이 과제에서도 C의 호출은 7회에서 3회로 줄었다.

## 1차 실행이 무효인 이유

1차에서는 T 응답에 `goal_first` 계약의 `goal_assessment`가 없어 기기가 응답을 거부했다(C에서만 `IOException` 2회). [묶음 실험](../2026-11-21-paper-ideas/report.md)의 C 자체 인정 부족과 `IOException`도 같은 원인이었다. 서버를 고친 뒤 같은 APK·과제·일정으로 2차를 실행했고, `IOException`은 0이 됐다.

## 운영 반영 전 남은 일

1. **settings_sound 정답 조건 수정**(하네스 카탈로그). "소리 모드" 대신 목적 화면에만 있는 증거로 바꾼다.
2. **시계형 탭(button + selected=true)**: 삼성 시계는 탭이 `button`으로 나와 T와 기기 인정이 모두 작동하지 않는다. 별도로 정해야 한다.
3. **일반어 제외 목록 검토**: 지금은 "설정, 화면, 메뉴, 앱, 홈, 탭, 더보기, 검색, 목록"과 앱 이름을 뺀다. Chrome 설정처럼 제목이 "설정"인 화면에서는 T가 작동하지 않고 기존 모델 경로를 쓴다.
4. 운영 반영 방식: `step(completion_triage=...)` 기본값을 켜거나, API 경로에서 켠다. 친구가 관리하는 `goal_first` 계약과 맞물리므로 같이 검토한다.
