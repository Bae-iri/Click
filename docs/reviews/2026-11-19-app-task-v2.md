# 앱 공통 작업 엔진 v2

2026-11-20 갱신: 이 문서는 11월 19일의 단독 v2 검증 기록이다. 이후 구현한 AI-Agent 2 경험 기억 연결의 현재 상태는 [새 연결 문서](./2026-11-20-ai2-app-task-memory.md)를 따른다.

정부24·설정 외 앱에서도 같은 화면 해석과 조작 도구를 사용하도록 `app-task.v2`를 추가했다. 기존 설정 실행기·정부24 안내와 `app-guide.v1` HTTP 계약은 유지한다. 이 변경은 임의 앱의 모든 업무가 성공한다는 보장이 아니다. 공개 접근성 정보로 대상을 확인할 수 있는 작업부터 적용한다.

## 반영한 네 가지

| 요구 | 구현 | 성공 판단 |
| --- | --- | --- |
| 공통 화면 표현 | 버튼·검색 입력란·목록·탭·토글·제목을 동일 구조로 변환한다. 패키지 허용 목록을 두지 않는다. | 앱·대상 ID·영역·선택 상태·입력 여부·목록 영역 해시로 현재 화면을 비교한다. |
| 단계별 작업 기억 | 최대 8개 하위 목표, 최근 8회 시도, 현재 단계와 작업 ID를 보관한다. 사용자별 암호화 저장소에서 24시간 내 이어간다. | 모델 응답으로 기존 계획이나 완료 상태를 덮어쓸 수 없다. |
| 실행 뒤 검증·복구 | 사용자 확인 → 현재 대상 재검사 → 네이티브 실행 → 실제 상태 확인 순서로 진행한다. | 입력값은 기기 내 정확한 값 해시, 탭·토글은 선택 상태, 이동은 새 목표 항목·화면 변화, 앱 열기는 실제 패키지로 확인한다. |
| 공통 도구와 경로 재사용 | 누르기, 공개 검색어 입력, 위·아래 스크롤, 뒤로, 직접 선택한 앱 열기를 제공한다. | 독립된 두 작업에서 검증하고 사용자가 결과를 확인한 동일 경로만 재사용한다. 재사용도 단계마다 승인과 검증을 거친다. |

## 사용 흐름

1. 일반 요청에서 현재 앱의 단계별 안내를 시작한다.
2. 원하는 앱을 직접 열거나 **다른 동작 → 앱 열기**에서 선택한다. 앱 목록은 기기에서 표시하고 선택한 앱 하나만 요청에 포함한다.
3. **이 단계 실행**을 누르면 해당 동작 하나를 수행한다. 검색어는 안내창에서 사용자가 직접 입력하고 별도의 버튼으로 확인한다. 검색어 입력은 검색 제출을 수행하지 않는다.
4. 실행 결과를 확인한 뒤 다음 단계를 제안한다. 변화가 없으면 5초 안에 확인 실패로 남기고, 같은 화면·동작·대상의 실패를 두 번 이상 반복하지 않는다.
5. 실제 결과가 맞으면 **결과 확인 · 안내 끝내기**로 종료한다. 모델의 완료 응답이나 버튼 실행 성공만으로 전체 요청을 완료 처리하지 않는다.

일시정지·취소·새 요청 뒤에 도착한 응답과 오래된 버튼 확인은 다음 작업을 실행할 수 없다. 자동 실행은 한 번의 확인당 하나의 도구 호출로 한정한다. 작업당 동작 64회, 원격 계획 요청 32회, 저장 경로 32단계 미만으로 제한한다.

## OCR 보완 범위

**화면 글자 추가로 읽기**를 별도로 선택하면 Android 11 이상에서 기기 내 OCR을 한 번 수행한다. 이름 없는 네이티브 버튼 중 작은 영역 최대 12개만 검은 배경에 복사한다. 이미지는 서버로 보내거나 저장하지 않는다. 기존 접근성 버튼 영역 안의 신뢰도 0.65 이상 글자만 이름에 보완하고, OCR 좌표로 새 누르기 대상을 만들지 않는다. OCR로 이름을 보완한 항목은 직접 누르도록 안내한다. 12초 지연 시 안내창을 복구한다.

따라서 접근성 노드가 없는 캔버스 전체, 아이콘 의미 추론, 임의 이미지 이해까지 지원하는 비전 에이전트는 아니다. 금융·인증·보호 화면에는 기존 비전 보호 정책도 적용한다.

## 상태와 개인정보

- 입력 내용은 공통 화면과 모델 요청에 포함하지 않는다. 공개 검색창도 `has_value`만 전송한다. 정확한 입력 확인용 해시는 기기 메모리에서 사용하고 검사 뒤 버린다.
- 비밀번호·일반 개인정보 입력란이 있거나 가림 영역 확인이 불가능하면 화면 전체 관측을 보호 상태로 전환한다. 개인정보 리소스와 상위 노드 하위 내용도 제외한다.
- 결제·송금·구매 확정·전송·제출·삭제·로그인·권한 승인 버튼은 공통 실행 대상에서 제외한다.
- 기존 `EncryptedSharedPreferences`에 사용자별 체크포인트와 의미 기반 경로를 저장한다. 로그아웃하거나 사용자가 바뀌면 기존 작업 저장소를 읽고 쓰지 않는다.
- 재사용 경로에는 앱·리소스·공개 이름·기대 상태만 저장한다. 입력값·좌표·화면 이미지는 저장하지 않는다. 앱 버전·Android API·프로토콜이 일치하고 7일 이내인 경로만 사용하며, 재사용에 실패하면 해당 경로를 폐기한다.

## 서버 계약과 지연

인증된 `POST /api/v1/agent/app-guide/task`를 추가했다. 요청에는 현재 관측과 제한된 작업 상태를 넣고, 응답에는 기존 네이티브 대상에 연결된 동작 하나와 기대 결과를 넣는다. 모델은 좌표, 입력값, 스크린샷, 기기의 전체 앱 목록을 받지 않는다. 기존 OpenAPI의 경로와 스키마 내용은 변경하지 않았다.

명시한 버튼 이름, 뒤로, 스크롤, 검색어 입력과 검증된 경로는 기기에서 처리한다. 복합 작업의 새 계획만 Gemini를 호출한다. 같은 관측으로 자동 재요청하지 않으며, 모델 연결 제한은 2초, 읽기 제한은 8초로 설정하고 응답 크기와 스트림 시간도 제한한다. 호출 실패·타임아웃은 사용자에게 다음 방법을 선택하도록 돌려준다.

로컬 환경의 실제 Gemini 연결을 가상 공개 버튼 두 개로 한 차례 검사했다. `gemini-3.8-flash`가 유효한 `tap` 제안을 3,099ms에 반환했다. 이는 단일 연결 확인이며, 실제 사용자 작업의 성공률이나 평균·상위 지연 지표를 뜻하지 않는다.

## 배포 구분

기기 내 공통 도구·단계 기억·결과 검증·제한된 OCR은 APK에 포함한다. 서버가 새 경로를 광고하지 않으면 이 기능만 사용하고 새 API를 호출하지 않는다. Gemini를 통한 복합 작업 계획은 새 백엔드가 배포된 뒤 사용할 수 있다. 기존에 확인한 GitHub Actions 결제·지출 한도에 따른 서버 배포 차단을 이 변경이 해결하지는 않는다.

## AI-Agent 2와의 관계

이번 변경은 앱 공통 관측·안내·실행 계층의 확장이다. 기존 AI-Agent 2의 실행 기록 분석·경로 개선 후보 생성 파이프라인을 호출하지 않는다. 새 `AppTaskService`는 Gemini로 단계와 다음 동작을 제안하고, 기기 내 경로 저장소는 동일 사용자의 반복 확인 경로만 재사용한다. 이를 AI-Agent 2 학습이나 범용 모델 개선 완료로 해석하지 않는다.

새 작업 기록을 개인정보 제한에 맞게 AI-Agent 2에 연결하고, 독립 검수·평가를 거쳐 개선 후보를 배포하는 과정은 별도 후속 작업이다. 기기 내 실행 검증 결과를 그대로 학습 정답으로 승격하지 않는다.

## 검증 기록

- Android 전체 단위 테스트: 1,100개 통과. 가상 Spotify·Firefox·YouTube 패키지에서 동일한 두 단계 흐름, 입력값 비전송, 오래된 승인 차단을 검사했다. 이 가상 검사는 실제 앱 사용 성공률과 구분한다.
- 최종 독립 checkout에서 Android 관련 회귀 테스트 325개 통과. v2 관련 36개에는 목록의 깊은 하위 항목 변화, 대상 이동, 실제 `ACTION_SET_TEXT` 인자와 미제출 검사가 포함된다.
- 최종 Debug·Release 전체 Lint: 오류 0개. 새 `AppTask` 클래스 관련 경고도 0개다. 저장소의 다른 기존 경고는 남아 있다.
- 백엔드 전체 테스트: 3,295개 통과, 1개 건너뜀. 독립 checkout에서 v2·v1 안내와 Gemini 진단 관련 75개도 통과했다.
- SM-N981N / Android API 33 실기기 테스트 4개 통과. 설정·Chrome·YouTube에서 공통 앱 열기·공개 화면 읽기·뒤로가기를 확인했고, 설정 디스플레이 화면에서 네이티브 스크롤과 ‘상위 메뉴로 이동’ 버튼 누르기의 실제 상태 변화를 검증했다. 설정값은 변경하지 않았다.
- 같은 기기에서 기본·1.5배 글자 크기의 단계 목록과 실행 버튼, 검색어 로컬 입력·확인 버튼, 검증 중 실행 차단, OCR 항목 직접 누르기 UI를 검사했다. OCR 인식 자체는 합성 요소의 기존 버튼 영역 연결·개인정보·신뢰도 검사를 통과했으며 실기기 인식 품질 평가로 간주하지 않는다.
- 실제 Gemini 연결: 공개 가상 화면 한 건, 유효한 네이티브 대상 제안, 사용자 확인 필수 확인.

주요 코드: `AppTaskObservation`, `AppTaskMemory`, `AppTaskController`, `AppTaskPolicy`, `AppTaskExecutor`, `AppTaskVerifier`, `AppTaskVision`, `AppTaskStore`, Backend `app/services/app_task.py`.
