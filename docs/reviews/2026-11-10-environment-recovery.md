# 작업 환경을 독립적으로 인식하는 실패 복구

2026-11-10. 실패 분류와 구현 계약은 [상세 문서](../failure-recovery-contract.md), 검증 기록은 [evidence JSON](evidence/2026-11-10-environment-recovery.json)에 있다.

## 문제와 원인

글자 크기를 조절하다가 캘린더에 들어간 경우와, 설정 앱을 열었지만 첫 페이지가 아니라 VPN 화면인 경우가 일반적인 ‘다시 시도하기 → 사과’ 흐름으로 합쳐졌다. 목표별 어휘 필터·작업 그래프는 현재 작업에 필요한 경로와 대상을 찾는 기능이다. 모든 전경 앱과 화면 종류를 구별하는 환경 인식기로 사용하면, 다른 앱과 그래프 밖 하위 페이지는 둘 다 UNKNOWN으로 사라진다.

기존 설정 페이지 복구도 두 화면이 같은 Settings 패키지이고 서로 다른 독립 제목을 갖는 경우만 처리했다. 따라서 다른 앱으로 이탈하거나 처음부터 VPN 하위 Activity를 연 경우는 다루지 못했다. 복구 상태의 기존 재관측 제한과 오래된 응답이 겹치면 이미 이동한 화면에 이전 대기를 반복했다.

## 결과 동작

- 실제 패키지·창·네이티브 구조로 전경 환경을 먼저 판정하고, 그다음 목표 경로를 검사한다. 25개 공통 환경 사례를 Android와 서버에서 실행한다. 42개 실패 코드는 원인별 복구 의미와 안내 문구를 공유한다.
- 캘린더·브라우저 등 다른 앱은 Android에서 먼저 구분한다. 내용을 서버로 보내지 않고 돌아가기를 제안한다. VPN 등 작업 범위 밖 설정 하위 페이지는 첫 관측부터 뒤로가기 복구를 제안한다.
- 정상 화면에 복귀하면 목표·episode·누적 예산을 유지한 채 최신 화면으로 재안내한다. 이전 하이라이트·승인·자동 실행 대기는 폐기한다. 명시적인 일시정지·수동 결과 대기·결과 질문은 임의 재개하지 않는다.
- 실제 팝업·키보드·최근 앱·잠금·접근성 끊김은 각각 다른 복구로 처리한다. 작업에 필요한 선택창은 유지한다. 시스템 권한 선택은 사용자에게 맡긴다.
- 배경화면·벨소리 등 등록된 외부 선택기는 해당 목표에 한해 수동 선택으로 연결한다. 사진·기기명·입력값의 전송 범위를 넓히지 않는다.
- AOSP SystemUI 밝기 조절창은 정확한 컨테이너·슬라이더·부모 구조·유일성·범위를 확인한 경우에만 밝기 작업에서 허용한다. 다른 SystemUI 내용과 알림은 제외한다. 원본 부모 정보가 없는 정규화 노드나 모델 응답만으로 예외를 허용하지 않는다.
- 관측 부족, 대상 부재, 모델의 선택 보류, 네트워크 장애, 결과 미확인은 서로 다른 안내와 처리로 나눈다. 결과가 불명확하면 같은 조작을 다시 실행하기 전에 결과를 확인한다.
- 서버도 모델 호출 전에 환경 복구를 수행한다. 목표가 없는 새 복구 세션에 기존 목표를 저장하여, 복귀 뒤 `GOAL_REQUIRED`가 되지 않게 한다. 환경 이탈·복귀가 실패 횟수나 실행·탐색 예산을 환불하지 않는다.

## 검증

- Android 전체 단위 검사: 740개 통과. 이후 추가한 물리 뒤로가기 보호 조건까지 포함한 최종 서비스 회귀 검사 195개 통과. 두 숫자는 서로 중복되는 범위다.
- AI-Agent 전체: 396개 통과.
- Backend 전체 실행: 2,354개 중 2,353개 통과. 기존 결과 질문 검사 1개가 재개 시 갱신되는 만료 시각을 이전 시각과 비교하여 초 경계에서 실패했다. 실행 코드는 그대로 두고, 테스트에 가짜 시계를 주입해 일시정지·재개 사이 시간을 실제로 전진시키고 질문 유지와 기존 180초 응답 기한 갱신을 함께 검사하도록 수정했다. 이후 해당 검사와 환경·수동 안내 검사 97개가 모두 통과했다. 마지막 테스트 수정 후 전체 실행은 반복하지 않았다.
- 모델 선택·프라이버시·밝기·환경 관련 별도 서버 검사: 101개 통과. 실제 외부 모델 호출 없이 합성 응답으로 검증했다.
- 공통 실행 계약 exporter `--check`, OpenAPI 재생성, `git diff --check` 통과.
- APK `assembleDebug` 통과. 빌드에 사용한 소스 복사본과 최종 앱·정책 원본을 바이트 단위로 대조했다. 기존 로컬 앱 설정으로 빌드했으며, 단위 검사 때의 Kakao 빈 값 override는 APK 빌드에 사용하지 않았다.

검사에는 캘린더 이탈·복귀, 첫 VPN 진입, 제목이 ‘설정’인 하위 Activity, 최근 앱과 홈 구분, 실제 Dialog와 정상 선택창 구분, 민감 화면 우선 차단, 이전 응답 폐기, 명시적 재개 지연, 캘린더 문구 변경과 물리 뒤로가기, 등록된 외부 선택기, SystemUI 슬라이더의 허용 범위와 알림 제외, 블루투스 빈 목록, VPN 연결·해제의 목적별 안내가 포함된다.
