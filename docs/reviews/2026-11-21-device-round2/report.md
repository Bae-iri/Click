# 실기기 2차: 공급자, 시간 초과 재시도, 기억·다단계 계획

[프로토콜](protocol.md) · [소스 해시](source-freeze.json) · [집계](summary.json) · [집계 스크립트](summarize.py) · [실행 스크립트](run_all.sh)

SM-N981N / Android 13, C 구성(`SpeedOptions.PRODUCTION`, 서버 triage 켬), 총 54회.

## 요약

1. **E1 공급자:** GPT(gpt-6.2-sol)가 Gemini보다 과제당 약 1.2초 빨랐다. 판정기가 정상인 과제에서 두 공급자 모두 6/6 도달, 6/6 검증이었다.
2. **E3 재시도:** 첫 호출 시간 초과를 주입했을 때 재시도를 켠 군은 6/6을 회복했다. 끈 군은 0/6이었다.
3. **E2 기억·다단계 계획:** 비교가 성립하지 않았다. 대신 **서버 completion triage의 실제 거짓 완료(12/12)**를 발견했다.

- GPT는 약 2.7배 비싸다(추정).
- **소리 과제 (두 군 3/3 verified, 판정기 0/3):** 판정기 랜드마크를 "벨소리"로 고쳤는데도 실험 중에는 찾지 못했다.
  - 실험 뒤 소리 화면을 직접 열면 "벨소리"는 클릭 불가 TextView로 정확히 한 번 보인다.
  - 기기의 완료 확인은 보관된 미래 전용 후보 "소리 및 진동"이 클릭 불가 화면 제목으로 보일 때만 성립한다. 설정 첫 화면에서는 같은 글자가 클릭 가능한 행 안에 있어 성립할 수 없다.
  - 그래서 실제 도착이었을 가능성이 높지만, 판정기로 증명하지 못해 이번에도 집계에서 뺐다.
  - 원인은 확정하지 못했다(예: 소리 모드에 따라 행이 숨겨짐).

| | 재시도 끔 (`PRODUCTION_NO_RETRY`) | 재시도 켬 (`PRODUCTION`) |
|---|---:|---:|
| 목표 도달 / verified | **0/6** / 0/6 | **6/6** / 6/6 |
| 실패 포함 평균 소요 | 25,069ms (예산 소진) | 14,963ms |
| verified 시각 | — | 13.0~15.9초 |
| 모델 호출 (주입 제외) | 0 | 6 |

- 재시도가 없으면 시간 초과 한 번으로 회기가 끝난다.
- 재시도를 켜면 같은 화면에서 한 번 더 물어 회복한다.
- 시간 초과로 잃는 8.6초는 남는다.

## E2 기억 우선 + 다단계 계획: 무효, 그리고 triage 거짓 완료

**앱 알림(2단계) 12/12 거짓 완료. 서버 completion triage(`c5e0298`)의 결함이다.**

- 목표는 "앱 알림 화면을 열어줘"다. 첫 탭("알림") 뒤 알림 첫 화면에서, triage가 그 화면 제목 **"알림"**을 완료 근거로 확정했다(`reason_code: completion_triage`, 근거 `('알림', text)`).
- 목표 문장에 "알림"이 포함된다는 이유로, 한 단계 덜 간 화면을 목적지로 본 것이다.
- 알림 첫 화면에서 "앱 알림"은 클릭 가능한 행 안의 메뉴다(실제 접근성 트리 확인).
- 독립 판정기("전체", 앱 알림 화면에만 있음)는 12회 모두 미도달로 판정했다.
- B·C 군 모두, 학습·평가 모두에서 같은 결과였다. triage를 켠 모든 구성에 해당한다.
- 1차 실험(디스플레이·알림·소리)은 목표 문장과 화면 제목이 정확히 같은 1단계 과제라서 이 문제가 드러나지 않았다.

**글자 크기와 스타일(2단계) 12/12 예산 소진.**
- 첫 탭("디스플레이")은 정상이었다.
- 두 번째 탭("글자 크기와 스타일")의 네이티브 실행이 거부(`native_rejections` 1)된 뒤 `needs_input`으로 멈췄다. 원인은 추적하지 못했다.
- 이 실패로 기억과 다단계 계획의 효과는 평가할 수 없다. C군에서 다단계 계획 제안은 3회(앱 알림 학습 회기)뿐이었다.

## 다음 조치

1. **(서버, 이가현) triage 목표 일치 조건 강화.** 목표가 "앱 알림"인데 화면 제목 "알림"이 일치로 처리됐다.
   - 제목이 목표의 대상 명사구 전체와 같을 때만 확정한다.
   - 현재 화면에 목표 문구와 정확히 같은 클릭 가능 항목이 있으면 확정하지 않는다.
   - 수정 전까지 2단계 이상 과제에서는 triage를 끄는 것이 안전하다(`APP_TASK_COMPLETION_TRIAGE=0`).
2. 글자 크기와 스타일 두 번째 탭의 네이티브 거부 원인을 조사한다.
3. 소리 판정기는 실험 중 화면 기록을 남겨 확정한다.
4. 2단계 과제에서 기억과 다단계 계획을 다시 비교한다. 1번 수정 후 또는 triage를 끈 상태에서 돌린다.
