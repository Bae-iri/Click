# AI-Agent 판단 불안정 조사 — 2026-11-09

## 결론과 확인 범위

사용자는 ‘어제 가능했던 글자 크기 조절이 오늘은 설정 앱에서 미지원 앱이라고 안내됨’을 보고했다. 두 개의 공통 불안정 경로를 로컬 재현으로 확인하고 수정했다. 다만 사용자에게 발생한 오류 순간의 설정 화면을 포착하지 못했다. USB 재연결 후 회수한 앞선 진단은 런처 화면이었으며, 수정 APK 설치 후 설정 홈·디스플레이를 별도로 확인했다. 아래 원인 재현을 그 실행의 확정된 추적으로 표현하지 않는다.

공개 서버의 `source_sha256`와 화면 정책·어휘 해시는 이전 로컬 진단 기록과 같았다. 공개 런타임 설정은 Jev 1.14.0, 신뢰도 기준 0.8이다. 이는 공개 코드·정책의 동일성 확인이며, 현재 휴대폰 APK·활성 DB graph·해당 세션의 전체 입력이 같았다는 증명은 아니다.

## 원인 1: 관찰 실패를 미지원 앱과 영구 중단으로 확대

기존 경로:

1. 접근성 창 전환 중 실제 root가 일시적으로 없거나 패키지를 읽지 못한다.
2. `ClickAccessibilityService.readCurrentScreen()`은 마지막 창 이벤트의 패키지를 현재 앱으로 사용한다. 마지막 이벤트가 System UI여도 빈 관찰을 생성한다.
3. 전송 경계는 허용하지 않은 패키지 또는 혼합된 패키지를 `UNSUPPORTED_APP`으로 차단한다.
4. `AgentTurnGateway.needsFreshObservation()`은 이를 일시 관찰 실패로 처리하지 않는다.
5. 서비스는 `showStoppedTask()` → `haltLocalExecution()`로 진입해 일시정지하고 동작·재시도 상태를 지운다. 이후 정상 설정 화면이 관찰되어도 자동으로 이어가지 못한다.

수정:

- 실제 root·패키지 근거가 없으면 현재 앱을 추정하지 않고 관찰 불가를 반환한다.
- 미지원·혼합 프레임은 기기 밖으로 보내지 않고 기존의 제한된 새 관찰 절차로 처리한다.
- 로컬 전송 단계의 미지원 오류에도 확정된 목표와 동작 증거를 보존한다.
- 재시도 예산은 단지 새 화면을 읽었다는 이유로 초기화하지 않고, 요청이 실제로 수락된 뒤 초기화한다. 연속 거절이 무한 재시도로 이어지지 않는다.
- 실제 비밀번호·인증·입력 보호 차단은 기존대로 유지한다. 다른 앱·시스템 대화상자를 건너뛰어 배경의 설정을 읽거나 조작하지 않는다.

검사 근거:

- 수정 전: root 없음·패키지 없음에 오래된 앱 정보가 사용되는 검사, 미지원 재관찰 검사, 일시 미지원 뒤 작업 유지 검사가 실패했다.
- 수정 후: 위 검사와 연속 거절의 제한·개인정보 차단·기존 전경 창 선택 검사가 통과했다.

## 원인 2: 무관한 설정값 변화가 기존 AI 선택을 폐기

기존 `ScreenSnapshot.fingerprint`는 화면 노드와 함께 글자 배율·밝기·음량 등 모든 적용값을 포함한다. 따라서 글자 크기 메뉴를 찾는 중 대상·창·위치가 그대로여도 밝기 값 100→101만으로 같은 메뉴라는 판단이 깨지고 Jev를 다시 호출했다.

통제된 재현에서 첫 응답은 선택, 두 번째 응답의 신뢰도는 0.79로 설정했다. 기존 코드에서는 `tap → observe_only / low_confidence`로 바뀌었다. 외부 모델에 실기기 화면을 보내 수행한 검사는 아니다. 모델이 바뀔 수 있는 조건을 고정해 불필요한 재호출의 영향을 확인한 검사다.

수정:

- 기존 전체 fingerprint는 그대로 유지해 조작 동의·설정값·결과 검증에 사용한다.
- 정규화된 전체 화면 노드의 별도 `native_fingerprint`를 기록한다. 새 원문·이미지를 보관하는 기능은 추가하지 않는다.
- **실행 전의 저위험 메뉴 이동**, `state_reached` 전환, 동의가 필요하지 않고 완료 동작이 아닌 경우에만 이미 수락한 Jev 선택을 유지할 수 있다.
- 대상의 창·ID·리소스·위치·상태·네이티브 구조가 바뀌거나 실행 증거가 들어오면 재사용하지 않는다.
- 슬라이더·토글 조작, 동의, 결과 검증에는 이 완화를 적용하지 않는다. 과거 checkpoint에 새 fingerprint가 없으면 기존의 엄격한 비교를 사용한다.
- 모델의 새 보류·낮은 신뢰도를 로컬 규칙으로 덮어쓰거나 신뢰도 기준을 낮추지 않는다.

검사 근거:

- 수정 전: 글자 크기·밝기·음량의 증가·감소와 checkpoint 복원을 조합한 12개 검사가 실패했다.
- 수정 후: 같은 사례의 불필요한 재호출이 사라졌다. 대상 변경·과거 checkpoint·실제 컨트롤 값과 적용값 변화에 대한 재검증도 함께 검사했다.

## 검증·배포 상태

정확한 검사 수·전체 검사 실패·APK 해시·배포 여부는 [기계 판독 근거](./evidence/2026-11-09-agent-instability.json)에 기록한다. 관련 검사와 전체 검사를 중복 합산하지 않는다.

- Android JVM 검사에서는 카카오 SDK의 실서비스 초기화만 빌드 속성으로 제외했다. 설치용 APK는 원래 로컬 설정을 유지해 별도로 빌드했다.
- 백엔드 전체 검사에서 나온 실패는 숨기지 않고, 수정 전 런타임을 로드한 대조 검사 및 동일 사례 단독 실행 결과와 구분한다.
- 수정 APK 설치와 설치 해시 일치를 확인했다. 실제 클릭 수집기와 네이티브 관찰 모두 설정 홈·디스플레이를 `com.android.settings / allowed`로 판정했다. 설정값 조절은 하지 않았고 기존 접근성 연결을 유지했다. 최초 오류 순간의 재현과 음성 입력부터 실제 설정 변경까지의 전체 검증은 완료하지 않았다.
- AI-Agent 코드 변경은 서버 배포가 필요하다. 로컬 소스 수정·검사·APK 빌드를 운영 서버 반영으로 표현하지 않는다.
- 이번 결과를 모든 작업·기기·복구 경로의 안정화 완료로 해석하지 않는다.
