# 다음 실제 앱 검증 — NOT_RUN

이 문서는 다음 단계의 준비 계획이다. 실제 앱·참여자 검증은 이번 변경에서 실행하지 않았다. 합성 화면의 정상 연결 점검이나 단위 검사를 B의 기본 활성화 근거로 사용하지 않는다.

첫 단계는 계정 없는 임시 에뮬레이터의 **실제 Android Settings 앱 6과제 × A/B 1반복 = 12회 정상 조건 점검**이다. 다음 공개 Intent 상수는 SDK에서 확인했지만, 설치 이미지의 화면·GUI 경로·정답 지원 여부는 사전에 검증해야 한다.

| 목표 | 양성 대조용 Intent |
|---|---|
| 디스플레이 설정 | `ACTION_DISPLAY_SETTINGS` |
| 소리 설정 | `ACTION_SOUND_SETTINGS` |
| 접근성 설정 | `ACTION_ACCESSIBILITY_SETTINGS` |
| 블루투스 설정 | `ACTION_BLUETOOTH_SETTINGS` |
| 날짜·시간 설정 | `ACTION_DATE_SETTINGS` |
| 언어 설정 | `ACTION_LOCALE_SETTINGS` |

Intent는 정답 대조용이다. 측정 중 에이전트에 목적 화면 직행 수단으로 제공하지 않는다. 각 과제는 GUI로도 같은 목적 화면에 도달하는지 확인한 후 잠근다. 기존 Samsung 시계 패키지·한국어 고정 메뉴·삼성 전용 완료 조건을 재사용하지 않는다.

모델 호출 전 언어와 Settings 홈·스크롤·키보드 시작 상태를 고정하고, 시작 메뉴는 음성, 실제 목적 제목과 고유 컨트롤은 양성인지 독립 UiAutomation 판정으로 확인한다. A/B 시작 지문이 다르거나 정답이 관찰되지 않으면 준비 실패로 기록한다. 성능 결과를 보고 쉬운 과제로 교체하지 않는다. 접근성 서비스가 있는 격리 application ID의 debug 변형을 사용한다.

정상 흐름과 계측이 확인되면 동일 6과제를 정상·첫 TAP 무효·5.5초 native dispatch 지연으로 확장한 36회를 사전에 고정한다. Dispatch 지연은 앱 렌더링 지연과 구분한다. A도 늦게 도착한 결과를 관찰하며, 폴링을 새 화면 이벤트로 세지 않는다.

주 지표는 독립 목적 화면의 안정적인 확인 **및** 앱의 완료 증거 검증 통과다. 단순 도달은 보조 지표다. 실제 시간은 모델·실행·복구·최종 확인을 모두 포함하고, 실패에도 동일한 사전 예산 페널티를 부여한다.

분류된 모델·공급자 실패는 제품 성능 결과에 포함한다. 누락된 요청·연결되지 않는 기록·불명확한 정답·비대칭 초기 상태는 측정 타당성 문제로 구분한다. 기존 실험의 사전 판정 기준을 소급 변경하지 않는다.

거짓 완료·원치 않는 값 변경·승인 없는 조작·계측 누락은 즉시 보류한다. 정상 검증 후 실제 장애에 노출된 대응 조건에서 B의 복구가 확인되면 다음 검증 단계로 진행할 수 있다. Settings 한 앱의 12회/36회만으로 기본 B 적용 GO나 범용성을 선언하지 않는다. 미사용 앱·다른 기기의 재현과 중장년층의 대기 이해·반복 클릭·완료 확신 평가가 별도로 필요하다.
