# 계획 요청 경계와 완료 조건 오류 보완

**공통 요청 경로는 보완했지만 B 기본 적용은 아직 NO-GO다.** 관련 Backend 검사 283개, Android 검사 151개와 Lint를 통과했다. 실제 Gemini·합성 화면 연결 점검 12회에서는 23개 요청과 23개 서버 기록이 직접 결합됐고, 공급자 대기 한도 초과 7건과 미완성 응답 1건이 남았다. 시간 초과 감소나 실제 앱의 성능 개선을 입증한 결과는 아니다.

## 완료 조건 오류가 정상 조작까지 막지 않도록 분리

모든 절의 형태·개인정보·대상·앱·상태 바인딩을 먼저 엄격하게 검사한다. 이후 공개 대상의 네이티브 플래그/역할 불일치 또는 선택된 앱들에 걸쳐 동시에 관찰할 수 없는 최종 조건의 타입 오류만 **완료 후보 전체 보류**로 처리한다. 잘못된 절이나 상태를 제거하지 않는다.

다음 조작이 별도로 유효하면 기존 승인·실행·네이티브 검증을 유지한다. 잘못된 다음 조작, 개인정보, 미선택 앱, 가공 대상, 잠긴 완료 조건 변경과 그 밖의 스키마 오류는 계속 거절한다. 이 보류를 위해 모델을 다시 호출하지 않는다. `completion_grounding=deferred_invalid_contract`와 제한된 검증 필드를 남겨 정상 복구와 치명적인 계획 실패를 구분한다.

## 모델이 다시 출력할 필요가 없는 내용 축소

- 이미 정해진 계획은 서버가 보관하고, 후속 조작 응답에서 단계 제목을 반복 출력하지 않게 했다.
- 결과 확인 전용 요청은 `completion_checks`만 반환한다. 서버가 기존 계획과 동작 없는 기본값을 제공한다.
- 구형 전체 응답도 기존 계획·진행·결과 전용 동작 제한을 그대로 검증한다. 축약 응답을 이용해 진행을 바꿀 수 없다.
- 실패 이력의 불투명한 지문 문자열은 모델 입력에서 서버가 계산한 `same_screen`으로 바꾼다. 실제 지문 안전 검사는 유지한다.
- 최대 출력 2048 토큰과 최대 8개 완료 절은 유지했다. 축약 때문에 유효한 복합 목표의 허용 용량을 줄이지 않았다.

## 단일 공급자 호출의 작업 경계

생산 경로의 HTTP 작업은 전용 `spawn` 프로세스에서 한 번 수행한다. Backend worker당 최대 2개 슬롯을 사용하고 모델 재시도는 하지 않는다. 응답은 16KiB로 제한하며 프로세스의 시작 신호와 응답을 작은 IPC 프레임으로 전달한다. 시간 초과 시 종료·회수 후에만 슬롯을 반환한다. 원문 예외·토큰은 기록하지 않는다.

설정한 로컬 예산은 시작·정리 시간을 포함해 9초이며 0.4초를 정리에 예약한다. 기존의 연결 2초·읽기 8초·청크 뒤 10초 검사와 다른 정책이다. 부모의 기한 감시는 작업 프로세스 시작이 반환한 뒤 작동하므로 OS 프로세스 시작 자체가 막히는 상황까지 무조건 9초를 보장한다고 주장하지 않는다. 종료는 로컬 작업과 소켓을 정리하며 이미 공급자가 받아 처리한 원격 작업을 취소한다는 뜻은 아니다.

앱은 큐·인증에 쓴 시간을 뺀 작업 예산을 헤더로 전달하고 응답 여유를 남긴다. 서버는 기존 상위 기한과 해당 헤더 중 짧은 쪽을 사용하며 공급자 작업은 최대 9초로 제한한다. 헤더는 연결·업로드 전의 상대 시간 추정이므로 전체 네트워크 전송 종료의 보장은 아니다. 기존 앱 요청 watchdog은 유지한다. 너무 적은 남은 시간으로 서버의 최소 예산보다 작은 헤더를 보내는 경우는 로컬에서 거절한다.

호출 시작 전 거절은 `not_started`, 시작 신호를 확인한 시도는 `observed`, 시작 신호 없는 중간 실패는 `unknown`으로 구분한다. 불명확한 호출을 0회로 바꾸지 않는다.

## 검증

| 검사 | 결과 |
|---|---|
| Backend 관련 검사 | 283개 통과. 작업 종료·회수·용량 회복, 개인정보 검사, 조작/완료 조건 분리, 축약 응답, 예산 전파 포함 |
| Android 검사 | 151개 통과, 실패·오류·건너뜀 0. 통제 72회 행렬 검사 1개 포함 |
| Android Lint | 통과 |
| 통제 검증 | 모델 호출 없이 72회. 기존 표현·안전·거짓 완료 방어 확인 |
| 실제 Gemini 연결 점검 | 정상 6과제 × A/B 1반복 = 12회, 실제 앱 시험이 아닌 합성 화면 |
| 직접 요청 대조 | 23/23, `DIRECT_JOIN_RECONCILED`, 누락·중복·호출 불명확 0 |
| 남은 오류 | 공급자 대기 한도 초과 7회, 미완성 응답 1회. 원인을 분류해 보존 |

연결 점검에서 목적 상태 도달은 A/B 각 6/6, 앱의 완료 검증 제시는 A 2회·B 1회였다. 단순 도달과 검증 완료를 구분하며 B의 우수성 근거로 쓰지 않는다. 23개 서버 처리 시간의 최대는 약 8.635초였지만 다른 OS·부하·네트워크까지 보장하는 상한 실증은 아니다. 런타임 에피소드 합계는 약 127.39초이고 Gradle 전체 빌드/시험 시간은 별도로 기록했다. 빌드·시험 준비 시간을 앱이나 모델의 속도로 해석하지 않는다.

이 점검은 일부 정상 조건의 연결 확인이며 전체 성능 행렬이 아니다. 모델·예산·입력 형식이 바뀌었고 공급자 변동도 있으므로 이전 점검과의 단순 전후 차이를 효과 크기로 계산하지 않는다. 시간 초과 건수는 줄었다고 확인하지 못했다. 아직 실제 앱·다른 기기·중장년층의 이해도는 미검증이다. FE 배치·버튼과 기본 CURRENT 정책은 유지했다.
