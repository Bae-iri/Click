# 소리 모드 태스크 확장

기존 89개 설정 요청 중 무음 켜기·끄기, 진동 켜기·끄기를 실제 모드 확인 경로로 확장했다.
카탈로그는 2.3.1이며 전체 요청 수를 늘리지는 않는다. 변경 상태 확인 경로는 54개, 직접
진행 안내는 35개다. 화면 자동 꺼짐 시간처럼 원하는 값이 필요한 요청은 기존 직접 진행
계약을 유지한다. 값 입력을 임의로 추측하지 않는다.

기존 다크 모드 전용 선택 검증기를 선언된 N개 모드에 재사용하도록 바꿨다.
리소스·제목·실제 계층·전체 선택지의 유일성·영역 분리와 독립 시스템 값이 필요하다.
Jev의 판단 보류를 규칙 선택으로 바꾸지 않는다. 일반 메뉴 탐색에는 radio를 허가하지 않으며
명시된 모드 선택 전환에서만 해당 후보를 허용한다.

Android는 유한한 소리 모드 enum을 읽고 무음·진동 작업에만 내보낸다. 기존 서버는
OpenAPI 협상에서 새 필드를 제외한다. 사용자의 기존 실행 graph는 고정하며 신규 작업은
별도 1.1.0 버전으로 등록한다. 운영 반영에는 서버와 앱 업데이트가 모두 필요하다.

검증은 배포 후보 기준 Backend 2,173개, AI-Agent 410개, Android JVM 548개를
통과했다. 기존 진행 중인 graph 1.0 참조 유지, 새 graph 1.1.0 선택, 확인 거절,
누락·중복·겹침 후보, 출처 없는 시스템 값, 오래된 관측·다른 클릭의 성공 거부를 포함한다.
공유 성공 계약 생성물 검사도 통과했다. 작업 트리 APK 별도 검사에서는 Android 633개를 통과했다.

SM_N981N 실기기에서 세 모드의 기본 Settings 버튼과 독립 모드 enum을 읽는 검사 1개를
통과했다. 해당 개인정보 필터 결과를 서버 경로에 입력했을 때, 무음·진동 켜기는 정확한
버튼의 확인 대기, 끄기는 소리 모드의 ALREADY_SET으로 분기했다. 실기기 소리 모드는
변경하지 않았다. 모드 변경 후 완료 검증은 합성 네이티브 관측을 사용한 HTTP 회귀로
확인했으며 실제 Jev API 품질 평가를 수행한 것은 아니다. 실기기 접근성 상태를 복원했다.

최신 develop의 대상 노출 개선을 유지하도록 재배치한 후 영향받는 Android 167개도 통과했다.
작업 트리 APK는 연결된 휴대폰에 설치했다. 운영 서버는 develop 자동 배포 완료 후 새 경로를 제공한다.
