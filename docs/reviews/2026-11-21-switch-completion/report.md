# 안드로이드 스위치 완료 판정 실험

API 37 AOSP 에뮬레이터의 디스플레이 설정에서 실제 **Dark theme** 스위치를 눌렀다. 각 상태에서 클릭의 접근성 수집기로 450ms 이상 떨어진 두 화면을 읽고, 스위치 값과 안드로이드에 적용된 테마를 대조했다. 측정 후 원래 꺼짐 상태로 복구했다.

같은 스위치의 기기 관측값으로 일반 앱의 `result_only` 요청을 구성해 `jev-1.14.0`을 네 번 호출했다. 켜짐 화면에는 직전 탭의 꺼짐 측정값도 연결했다. Jev에는 요청, 공개 설정 이름, 패키지와 상태값을 보냈다.

| 적용된 테마 | 요청 | Jev 응답 | 클릭 판정 | Jev 경로 소요 시간 |
| --- | --- | --- | --- | ---: |
| 꺼짐 | 끄기 | 완료 후보 | 완료 근거 있음 | 228ms |
| 꺼짐 | 켜기 | 근거 부족 | 보류 | 219ms |
| 켜짐 | 끄기 | 근거 부족 | 보류 | 245ms |
| 켜짐 | 켜기 | 완료 후보 | 완료 근거 있음 | 187ms |

시간은 각 요청이 서버의 Jev 완료 경로에 머문 시간이다. 사용자의 발화에서 안내가 끝나기까지의 시간은 측정 범위 밖이다. 모의 모델이 네 경우 모두 완료를 골라도 클릭은 값이 반대인 두 건을 보류했다.

이전 버전 `77934af`에 기록했던 ‘다크 모드’와 ‘알림’의 켜기·끄기 요청도 같은 입력으로 재생했다. 제목만 맞고 스위치는 반대인 네 건의 오판이 4건에서 0건으로 줄었다. 별도의 보관함 화면에서는 누를 수 있는 배경 안의 실제 안드로이드 제목을 완료 근거로 유지했고, 같은 위치의 일반 메뉴 글자는 제외했다.

기기 측정은 `AppSwitchCompletionDeviceTest`, 완료 확인창은 `AppTaskEvidenceLifecycleTest`, Jev가 다른 값을 선택하는 경우는 `test_app_task_jev_completion.py`에서 재현할 수 있다.
