# 반복 사용 중 기억 회수가 꺼지는 결함 수정

24회 코호트 종료 뒤 별도로 적용한 변경이다. 종료된 속도 결과의 소스·원자료·배정·판정을 변경하거나 새 수정의 성과로 재해석하지 않는다. 수정 커밋과 파일 해시는 [검증 기록](memory-reuse-followup.json)에 있다.

기존 코드는 같은 동작을 재사용할 때 `target_visible` 근거가 `screen_changed` 근거로 쌓여, 양쪽 묶음에 독립 성공이2개씩 생기면 서로 다른 후보로 간주했다. 실제 분석기를 통과한 회귀 검사에서 성공적인 재사용2회 뒤 `needs_data`로 바뀌는 문제를 재현했다.

수정은 각 원래 묶음의 성공2건·실패 이후 증거·도착 순서 기준을 그대로 통과시킨 다음, 원래 목적 화면 키와 내보내는 동작이 모두 같은 후보만 하나로 취급한다. 신선한 action UUID만 비교에서 제외하고 진행 권한은 AND로 합친다. 기대값·패키지·목적 화면·대상이 다르면 계속 경쟁 후보로 남긴다. 한 묶음의 성공1건과 다른 묶음의 성공1건을 합쳐 자격을 만들지 않는다.

[기존 코드 재현](memory-reuse-baseline-tests.log)은 신규8개 중3개 실패·5개 통과였다. [수정 후 검사](memory-reuse-final-tests.log)는 기존 AppTask·학습 검사와 신규 회귀를 포함해132개 모두 통과했다. 실제 분석기로 재사용7회를 연속 검증했고, 중복 task·실패/늦은 증거·서로 다른 목적 화면·기대값·진행 권한도 검사했다. 모델 호출은0회다.

이 변경은 기억을 재사용할 수 있던 경로가 스스로 꺼지는 결함을 고친다. 실제 단말의 전체 시간이나 청구 비용 감소를 새로 측정한 결과는 아니다. 운영 A/CURRENT, 첫 단계 기억 실험 옵션의 기본false, native 완료 기준과 기본 Gemini 완료 공급자는 유지한다.
