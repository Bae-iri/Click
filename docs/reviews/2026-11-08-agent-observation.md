# 공통 에이전트 관찰·개인정보·복구 개선

와이파이 태스크만 허용하는 예외를 추가하지 않았다. Android HTTP 경계, 공통 접근성 수집기, AI1의 모든 선택기, Jev 입력 구성, 제한된 진단 로그를 함께 수정했다.

- 이미지 마스킹 증거와 네이티브 텍스트의 허용 목록 검사를 분리했다. 이미지가 포함될 때는 여전히 마스킹 증거가 필요하다.
- 문구 없는 네이티브 체크 컨트롤도 Android HTTP 경계와 Jev 최소화 경계에서 유지한다. 실제 기기에서 기존 경계가 제목만 남기고 스위치를 제거하던 문제를 확인했다.
- 네이티브 `isShowingHintText()`로 입력 안내 문구를 실제 검색어와 구분한다. 실제 입력값과 비밀번호는 전송하지 않고 입력 단계는 계속 중단한다.
- 정책의 리소스 식별자로 확인되는 네트워크·연결 기기·계정 등 개인 항목은 행과 하위 노드를 제거한다. 허용 목록과 우연히 같은 이름도 화면 제목·조작 대상으로 쓰지 않는다.
- 계정·인증 화면과 자격 증명 입력 차단은 Jev뿐 아니라 로컬 규칙 선택기에도 적용한다. 이미지/OCR이 이를 우회하지 않는다.
- 화면 미인식, 지원하지 않는 앱, 실제 입력, 보호 대상 화면을 별도 원인으로 기록한다. 알 수 없는 화면을 개인정보 발견으로 안내하지 않는다. 구버전 서버의 모호한 차단 메시지도 앱에서 중립적으로 표시한다.
- 기기 잠금은 `KeyguardManager`가 실제 잠김을 보고할 때만 안내한다. 확인되지 않은 팝업을 닫으라는 메시지를 만들지 않는다.
- Jev에는 검증된 목표의 on/off와 네이티브 체크 상태를 제공한다. `selected`나 누락 값을 false로 추정하지 않는다. 최종 변경 검증은 계속 원래 대상과 조작 이후의 네이티브 관찰을 요구한다.
- 공개 `/version`에 정책·어휘 해시만 추가했다. 계정, 화면 문구, API 키를 진단 정보에 넣지 않는다.

## 검증

같은 JSON 사례를 Android와 Python에서 검사한다. 와이파이·블루투스·밝기·글자 크기·음량에 걸쳐 개인 항목과 제목의 혼동, 설명 문구, 빈 검색창, 실제 검색어, 비밀번호, 인증 제목을 구분한다. 실제 provider 페이로드와 선택 후보에서도 개인 행이 제외되는지 검사한다.

연결된 Samsung 기기의 와이파이 화면은 수정 전후 모두 네이티브 개인정보 필터를 통과했다. 관찰 당시 입력창과 비밀번호 필드는 0개이고 스위치는 1개였다. 따라서 사용자에게 표시된 문구만으로 실제 개인정보나 팝업이 있었다고 결론 낼 수 없다. 와이파이 스위치와 네트워크 연결은 변경하지 않았다.

기존 접근성 서비스의 사용자 허용 상태를 그대로 복원하는 선택적 재연결 뒤 실제 앱 서비스 스냅샷도 읽었다. 새 접근성 서비스를 추가하거나 권한을 늘리지 않았다. 이 검사를 실제 음성 요청부터 운영 서버 완료까지의 성공으로 해석하지 않는다. 진단 당시 운영 서버에는 새 `observation_contract` 필드가 없었다. 새 서버 측 공통 정책을 사용하려면 Backend와 AI-Agent 배포가 필요하다.

최종 실기기 확인에서 실제 앱 서비스의 체크 컨트롤은 수집 1개·전송 1개였고, 로컬 Backend/AI1에 동일 관찰을 연결해 `ALREADY_SET / WAITING_RESULT / observe_only`를 확인했다. 이전에는 수집 1개·전송 0개였다. 운영 서버를 통한 전체 음성 요청 성공과는 구분한다.
