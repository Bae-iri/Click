# 완료 우선 A 정상 탐색 6회 결과

**A에서 공동 성공5/6·API 시도12회·실패 포함 평균12.761초를 관측했다.** 목적 상태에 안정적으로 도달한5회에서는 이후 추가 native 조작이0건이었다. 완료 후 재탐색을 줄일 수 있는 개선 후보지만, 목표당 한 번의 자료로 범용성이나 특정 코드의 인과 효과를 확정하지 않는다. B는 실행하지 않았고 기본 사용 경로는 A/CURRENT다.

## 출처와 평가 기준

실제 실행 소스는 **`a89168d8e5f5f8b89009d70d4bd0a2d421a4e349`**, 모델은 `gemini-3.8-flash`다. [동결 기록](source-freeze.json)은 2026-11-21 10:42:02 KST에 소스57개·APK·준비 자료4개를 facade 시작 전에 고정했고 모델 시도는0회였다. [종료 기록](cohort-closure.json)은10:48:38 KST에 소스·준비 자료 불변과 drain idle을 확인했다. 이전 코호트 원자료는 수정하지 않았다.

Settings·Clock·Files의 기존 여섯 목표를 A·정상 조건에서 한 번씩 실행했다. 공동 성공은30초 안에 독립 oracle의 목적 상태700ms 안정, 현재 runtime의 fresh native 두 프레임 검증, 조작 후750ms 대기와 pending native0·false verified0이 함께 성립한 경우다. 실패 포함 시간은 성공 시 공동 성공 시각, 나머지는30초다. 모델의 자기 선언이나 메뉴 표시를 완료로 세지 않는다.

## 구현한 기능과 실제 사용된 경로

완료 우선 `goal_first`는 **기존 계획 호출 안에서** 최종 목표를 먼저 평가한다. 현재 목표가 만족됐다는 응답은 계획이 남아 있어도 새 조작·진행 변경 없이 완료 후보만 제공하고, 기기는 기존 native 두 프레임으로 다시 검증한다. 모델 응답을 기다리는 동안 이미 아는 로컬 완료 조건이 충족되면 그 증거부터 확인하며, 이후 늦은 응답으로 탐색을 재개하지 않는다. 완료가 검증되면 사용자 결과 확인을 기다려 pending 계획으로 자동 재탐색하지 않는다. FE에 새 버튼이나 레이아웃을 추가하지 않았다.

실제 기기 구성요소 검사에서 **선택된 Timer가 클릭 불가여서 기본 관찰에서 빠지는 결함**도 발견해 수정했다. 선택된 native 탭은 읽기 전용 상태 증거로 내보내며, 클릭 권한을 추가하지 않는다. 개인정보·가시성·앱·native 창·화면 경계 필터는 유지했다.

[모델 없는 native 구성요소 검사](native-component.json)9개가 모두 통과했다. 실제 여섯 목적 화면의 pending 계획에서 scripted 응답1회·추가 native 조작0·두 프레임 검증을 확인했고, 메뉴 drawer·오래된 관찰·보호 화면은 완료로 인정하지 않았다. 이는 이미 도착한 상태의 연동 검사이며 실제 탐색 성공률과 합산하지 않는다. Android 관련547개 검사, Backend483개 검사와 빌드·lint도 통과했다([검증 기록](unit-verification.json)).

**실제 공급자6회에는 `goal_first/satisfied` 응답이 없었다.** 총12개 요청 중 goal_first9회는 not_satisfied8회·공급자 실패1회였고, 나머지3회는 result_only였다. Clock 두 목표는 첫 계획이 미리 제공한 상태 조건을 선택 후 로컬에서 검증해 각각 API1회로 끝났다. Display·Recent·Documents는 별도 result_only 요청에서 완료 후보를 얻었다. 따라서5/6 성과를 goal_first의 조기 중단 분기만의 효과라고 주장하지 않는다.

## 남은 시간 병목

- 로컬 두 화면 증거 확인: 성공5회 중앙값 **419ms**, 범위405~442ms.
- 전체12개 요청의 모델 경계 대기: 중앙값 **3,467ms**, 합계48,731ms.
- 마지막 result_only3회 대기: **3,288·3,303·5,428ms**, 합계12,019ms.
- loopback에서 client work_ms−model_wait_ms 차이: 중앙값 **7ms**, 범위5~16ms. 큐 대기 합계는1ms였다.

여전히 완료 후보를 뒤늦게 얻는 수초의 비용이 남는다. 위 모델 경계 대기는 worker·HTTP·공급자 처리 등을 포함하며 순수 Gemini 연산 시간을 분리한 측정이 아니다. loopback 잔여7ms도 실제 모바일 네트워크 전체 지연을 나타내지 않는다. Clock의 첫 native 검증이 독립 안정 도달보다133·206ms 먼저 찍힌 것은 native≥350ms와 oracle700ms의 기준 차이이며, 시간을 수정하지 않았다.

## 판정과 후속 실험

이 결과는 **A의 완료 처리에 대한 좁은 검증**이다. 단일 accountless Android17 에뮬레이터·세 앱·목표별1회·scripted approval이며 중장년층 참여자는 없다. B 재도입이나 모든 기기·앱의 도입 GO 근거가 아니다. 더 많은 반복에서도 성공과 안전을 유지하면서 전체 실패 포함 시간과 실제 시도를 함께 낮추는지 확인해야 한다.

이후 JeV를 terminal 완료 후보 선택에 제한적으로 사용하는 옵션과 [신규24회 통합 시간 비교 프로토콜](../../../experiments/metacontroller/goal-first-integrated-timing-protocol-v1.md)은 **다른 소스와 별도 결과**다. 이번6회는 모두 Gemini이며 JeV 효과나 새24회 성과로 합치지 않는다. 초기 Gemini 탐색을 유지하고, 안전한 단일 화면/탭 목표의 terminal 선택 경로만 비교하도록 사전 설계했다. 후속 소스·준비·일정 동결 전 유료 시행을 시작하지 않으며, 아직 관측하지 않은 속도 개선을 이 보고서의 성과로 세지 않는다.
