# MetaController와 기억 재사용의 통합 충돌 검사

## 확인한 충돌과 수정

`e4f5580`에서 기기 AI2 회수 응답의 `retained_experience` 빠른 경로가
현재 MetaController의 차단 목록을 확인하지 않고 `propose()`를 호출했다.
`propose()`는 안전하게 해당 동작을 막았지만, 빠른 경로가 바로 반환하면서
다른 동작을 찾는 플래너 호출도 사라졌다. 동작이 잘못 실행되는 문제가 아니라
복구가 막히는 문제다. 실패 기록은 한 건이므로 `memory.repeated()`의 두 번 실패
기준으로는 이 경우를 걸러내지 못했다.

회수된 동작을 쓰기 전에 기존 `previouslyRejected()`를 적용해, 이번 회기 MC 차단과
회수된 거절 증거에 걸리는 기억은 건너뛰고 다음 경로/플래너로 진행하도록 수정했다.
서버 AI2 빠른 경로와 기기 경로 캐시에는 이미 유사한 차단 검사가 있었다.
제품의 기본 정책, 기억 활성화 여부와 사용자 승인 규칙은 바꾸지 않았다.

## 모델 없는 통합 실행

기존 closed-loop 하네스에 기억 켬/끔을 추가했다. 운영 Android Controller·Verifier·MCv2를
Robolectric에서 호출하고 플래너와 회수된 과거 동작만 통제 fixture로 제공한다.
학습·DB·실제 모델의 효과를 측정한 결과가 아니다. 여섯 합성 과제 × 세 조건 ×
두 반복 × 네 비교군을 수정 전후 각각 144회 실행했다.

| 무반응 조건 | 수정 전 목적 도달 | 수정 후 목적 도달 |
|---|---:|---:|
| A / 기억 끔 | 0/12 | 0/12 |
| A / 기억 켬 | 0/12 | 0/12 |
| B / 기억 끔 | 12/12 | 12/12 |
| B / 기억 켬 | 0/12 | 12/12 |

정상 조건은 모든 군이 전후 12/12, 지연 조건은 A 두 군 10/12와 B 두 군 12/12로
변화가 없었다. 거짓 완료 제시와 실행 안전 위반은 전후 전체 모두 0건이다.
이는 제한된 fixture의 기능 적합성 결과이며 일반 앱 성능을 뜻하지 않는다.
`blockedRememberedActionFallsThroughToRecoveryPlanner` 회귀 검사는 기억 동작을
건너뛴 뒤 실제 플래너 재호출과 독립 목적 도달을 함께 확인한다.

원시 결과: [수정 전](before/episodes.jsonl), [수정 후](after/episodes.jsonl),
[집계](controlled-summary.json). 실행 조건: [프로토콜](protocol.md), [소스 해시](source-freeze.json).

## 실기기 실행 결과

SM-N981N / Android 13, Gemini 3.8 Flash, 운영 AppTaskService·AI2 분석/grounding·
기기 경로 저장소로 40회 완료했다. DB 저장만 기존 실험 파사드의 비교군별 메모리 저장소로
대체했다. 두 과제(디스플레이·알림) × 네 비교군 × 학습 두 번+평가 세 조건이다.
학습 16회와 평가 24회를 합쳐 성능을 계산하지 않는다. 시작 준비 실패는 0/40이다.
B는 이번 develop의 MCv2이며, 이전 MC-v0와 버전을 혼동하지 않는다.

### 평가 회기의 독립 목표 도달

각 칸은 두 과제 각 한 회, 분모 2다. 학습 회기는 네 군 모두 4/4 도달했다.

| 정책 | 기억 | 정상 | 무반응 | 5.5초 지연 |
|---|---|---:|---:|---:|
| A / CURRENT | 끔 | 2/2 | 0/2 | 2/2 |
| A / CURRENT | 켬 | 2/2 | 0/2 | 2/2 |
| B / META | 끔 | 2/2 | 0/2 | 2/2 |
| B / META | 켬 | 1/2 | 0/2 | 2/2 |

B+기억 켬의 정상 조건 실패는 공급자 오류로 `unavailable`이 반환됐고 제안·터치가
0회였던 회기다. 이를 기억의 악영향으로 해석하지 않는다. B+기억 끔 무반응 조건에서도
한 회기는 공급자 오류 등으로 첫 동작 자체가 제안되지 않아 오류 주입에 노출되지 않았다.
무반응 배정 8회 중 실제 오류 주입은 7회다. 원래 배정 분모에서 빼지 않았다.
노출된 B 회기 3회에서는 재관찰이 각각 한 번 발생했지만 독립 목표에 도달하지 못했다.
지연 조건의 예약된 실제 터치는 8/8 수락됐다.

### 기억이 실제로 사용됐는가

**기억 출처 동작 제안은 0/40회다. 통합 효과나 실기기에서의 충돌 해소를 검증했다고
주장할 수 없다.** 기억 켬의 사용자 확인 작업은 CURRENT 8개, META 7개이며 AI2가
길이 1의 경로를 만든 작업은 각각 5개였다. 학습·수집 자체가 전혀 없었던 것은 아니다.

정확 일치 회수 로그에서 동작 후보가 존재한 기록은 CURRENT 5건, META 4건이었다.
이 9건은 모두 `completion_known=false`였다. 현재 기기와 서버의 기억 빠른 경로는
완료 조건이 결속된 뒤에만 사용할 수 있다. 이번 한 동작 과제에서는 첫 계획 이후 곧바로
목적 화면/결과 증거 탐색으로 넘어가 기억 동작을 실행할 기회를 확보하지 못했다.
후보가 없었던 나머지 회수의 원인까지 이 게이트 하나로 설명하지는 않는다.

따라서 이번 실제 기기 비교는 기억 동작의 상호작용을 충분히 노출한 실험이 아니다.
다음에는 첫 단계 기억 사용 또는 2~4단계 과제를 별도 프로토콜로 검증해야 한다.
이 한계를 알고도 성공한 학습 기록을 인위적으로 추가하거나 완료 조건을 미리 주입하지 않았다.

### 완료 증거·호출과 해석 한계

기기의 네이티브 `verified` 제시는 0/40이었다. 목표 도달은 독립 UiAutomation 정답이며,
사용자 확인은 700ms 안정된 정답을 본 모의 사용자만 수행했다. 거짓 verified도 0건이지만
verified 제시 자체가 없어서 완료 판정 안전성의 근거로 확대하지 않는다.

| 전체 학습+평가, 기억 두 군 합산 | CURRENT | META |
|---|---:|---:|
| 파사드에 기록된 모델 호출 | 36 | 38 |
| 그중 공급자 오류 | 4 | 3 |
| 기기 패널 diagnostic에서 관찰한 호출 | 20 | 23 |

파사드 74건은 등록된 회기의 종료 시점까지 서버에서 실제 처리한 호출이며,
기기 diagnostic은 패널에 전달된 응답만 세므로 서로 다른 계측 범위다. 이를 하나로
합산하지 않는다. 두 서버의 health drain을 확인하고 최종 로그를 집계했다. 실제 청구서와
독립 공급자 대조는 수행하지 않아 완전한 청구 비용을 확정하지 않는다.
CURRENT→META 순차 실행, 고정된 평가 순서, 기기 한 대·과제 두 개·조건당 한 번이므로
속도·비용·일반 성능의 인과 효과를 주장하지 않는다. 실패와 공급자 오류는 모두 보존했다.

[실기기 집계](device-summary.json), [CURRENT 원자료](live-current/episodes.jsonl),
[META 원자료](live-meta/episodes.jsonl), 각 폴더의 `facade-logs/`를 함께 확인한다.
두 실행은 각각 20개 예정 키를 모두 포함하며 누락·중복 키가 없다.

## 반영과 검증

- 기억이 현재 차단된 동작을 재제안하며 재계획을 삼키는 경로 수정은 반영한다.
- 운영 A 기본값과 기억 기본 적용 상태는 유지한다. B를 켜지 않는다.
- 실행 중 원격에 추가된 [A 유지·B 폐기 결정문](../2026-11-21-native-settings-ab-decision.md)은
  문서 변경뿐이어서 실행 소스와 차이가 없으며 최종 브랜치에 함께 받았다.
- Android 관련 검사 149개, Backend 기억·복구 검사 56개 통과. 두 격리 APK 빌드 및
  실기기 준비 검사 통과. 모델 없는 통합 행렬은 수정 전후 각각 144회 완료했다.
- 실험 종료 시 기존 `com.clueclick.app.devtest` 접근성 서비스 복원을 확인했고 USB reverse를 정리했다.
- 기존 폰의 클릭 테스트 앱은 교체하지 않았다. 새 실험 전용 앱에서 실행했다.
