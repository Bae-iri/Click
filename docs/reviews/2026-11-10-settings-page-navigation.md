# 하이라이트와 다른 설정 페이지에 들어갔을 때의 복구

## 재현 원인

사용자가 안내 대상과 다른 메뉴를 열었을 때, 앱은 이전 안내 좌표가 오래되었다는 판단은 했지만 실제 페이지 이동과 재관측 실패를 구분하지 못했다. native 관측이 바뀌어도 RECOVERY에서는 일반 관측 전송이 차단됐고, 도움/사과 안내 역시 해당 상태를 먼저 확인해 새로운 화면을 다시 판단하지 않았다. 서버 primary도 waiting_for_user를 화면 판단 전에 반환하므로 새 페이지를 보고도 과거 대기를 반복할 수 있었다.

다른 설정의 제목과 항목은 기존 목표별 서버 관측 범위에서 제거되므로, 예를 들어 글자 크기 작업 도중 블루투스 페이지를 보내 목표를 다시 찾으려는 방식만으로는 경로를 복구하기 어렵다. 개인 화면이나 다른 설정의 조작 범위를 넓히는 대신, 이 경우는 기기 안에서 복구한다.

## 변경 동작

1. 새 native 스냅샷의 독립 페이지 제목을 이전 관측과 비교한다. 동일 페이지의 스크롤·목록·숫자·창 번호만 바뀌면 페이지 이동으로 취급하지 않는다.
2. 기존 목표의 검토된 어휘 범위에 속하는 페이지면 이전 하이라이트·동의·복구 안내를 폐기하고 현재 화면에서 재안내한다. 재시도 버튼이 필요하지 않다.
3. 다른 설정 페이지면 해당 화면을 추가 전송하지 않고 로컬 뒤로가기 안내를 표시한다. 실제 OS 뒤로가기는 사용자 활성화 후에만 실행한다. 사용자가 직접 올바른 페이지로 이동하면 기존 목표로 관측을 재개한다.
4. 사과/재시도 상태에서도 실제 페이지 이동은 관측 허용 상태로 전환할 수 있다. 명시적 일시정지·중단·완료·결과 질문·개인 항목 선택을 맡긴 수동 진행은 화면 이동만으로 재시작하지 않는다.
5. 네트워크 응답 도중 페이지가 바뀌면 이전 응답의 세션 버전은 수용하되 오래된 안내는 표시하지 않는다. 최신 이동은 하나로 합쳐 다시 관측한다. 응답 유실 시 안내를 바꾸지 않고 버전을 동기화한다.
6. 정상적으로 안내 대상을 누른 탭 증거, 실제 뒤로가기 이벤트, 진행 중 값 변경 증거는 보존한다. 재관측이 동의나 완료 증거를 대신하지 않는다. 탐색 예산과 실패 횟수는 환불하지 않는다.

서버 `observe_page_navigation`도 관측 ID/시간·독립 native 제목·앱 범위를 확인해 실제 페이지가 바뀌었으면 오래된 대기를 해제한다. 정상적인 전진/단계 건너뛰기는 기존 검증기를 유지하며, 화면 제목이 같거나 native 제목이 없는 관측 및 소진된 실행 예산은 대기를 해제하지 않는다.

## 구현 위치

- Android: SettingsPageNavigation, TaskExecutionController.pageChanged, ClickOverlayService.handleSettingsPageChange / continueAfterPageChange / synchronizePageNavigation, NavigationRecovery.offPathPage.
- 런타임: primary.observe_page_navigation, engine의 관측 완료 후 재배치 단계.
- 회귀 검사: Android 실제 service/gateway callback과 SettingsPageNavigationTest, Backend test_observed_page_navigation.

## 배포 범위

검증 수치·APK/소스 해시는 옆의 기계 판독 증거에 기록한다. 앱은 새로 빌드/설치해야 하며, 서버가 독립적으로 페이지 이동을 인식하는 보강은 Backend/AI-Agent 재배포가 필요하다. 앱의 로컬 뒤로가기와 기존 manual_override를 이용한 재관측은 기존 명령 계약을 유지한다. 휴대폰에서 실제 설정값을 바꾸거나 운영 모델을 호출하는 종단 검증은 하지 않는다.
