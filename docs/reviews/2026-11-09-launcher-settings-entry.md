# 런처에서 설정 아이콘 찾기 및 진입 수정

사용자가 확정한 동작은 **설정 아이콘이 보이면 바로 하이라이트 → 없으면 런처 페이지 탐색 → 끝까지 못 찾으면 ‘설정 열기’ 버튼**이다. ‘설정 열기’는 사용자가 눌러 Android 설정 앱을 여는 복구 동작이다.

## 원인과 수정

- 삼성 런처 `com.android.launcher3.PagedView`를 가로 페이지로 인식하지 못했다. `isScrollable=false`인 경우도 페이지 컨테이너로 인식하며, 앱 위젯 내부 목록은 후보에서 제외한다. 일반 `apps_and_widgets` 래퍼까지 제외하지 않는다.
- 런처의 일반 앞으로/뒤로 스크롤 액션 대신 명시적인 좌우 액션 또는 실제 페이지 영역 안의 가로 제스처를 사용한다. 좌우 액션이 실패해도 일반 스크롤로 돌아가지 않는다.
- 접근성 창/노드 경로가 바뀔 때 탐색이 초기화되던 문제를 고쳤다. 같은 페이지 반복·진행 없음·끝 도달 또는 최대 8번 이동에서 ‘설정 열기’를 표시한다. 설정 앱 내부 목록 탐색의 기준은 유지한다.
- 아이콘 격자의 행·열 인덱스를 페이지 번호로 취급하지 않는다. 레이아웃 애니메이션의 픽셀 좌표나 시계 위젯 변화도 새 페이지의 증거로 삼지 않는다.
- 서버가 선택을 보류하거나 설정 열기를 반환해도, 기기에서 명확한 설정 아이콘을 찾으면 실제 클릭 가능한 영역에 하이라이트를 표시한다. 이는 사용자가 누르는 앱 진입 안내이며, 모델의 선택 결과를 만들거나 아이콘을 자동으로 누르지 않는다.

## 검증

초기 추가 회귀 사례 8개가 수정 전 실패했다. 후속 검사에서 비스크롤 PagedView와 일반 위젯 래퍼 사례를 추가했다. 최종 Android JVM 테스트 **574개 통과, 실패·오류·건너뜀 0개**. 관련 검사 182개에는 보이는 아이콘 우선 하이라이트, 위젯 갱신 중 안내 유지, 컨테이너 경로 변경 시 탐색 종료, 반복/변동 화면의 탐색 제한, 가로 액션 실패 후 일반 스크롤 금지를 포함한다.

첫 수정본의 실기기 검사에서는 컨테이너가 FrameLayout/UNKNOWN으로 잡혀 방향 검사가 실패했다. 제스처 실행 전에 중단했고, 비스크롤 PagedView와 래퍼 조건을 보완한 뒤 재검사했다.

최종 삼성 SM-N981N 실기기 결과:

- 실제 런처 `PagedView`가 **HORIZONTAL**로 인식됐다.
- 설정 아이콘이 없는 페이지에서 가로 이동 **1회** 후 실제 페이지 내용이 변경됐다.
- 이동 후 설정 아이콘 **1개**가 클릭 가능한 대상으로 인식됐다.
- 아이콘 자동 클릭 0회, 설정 값 변경 0회. 로컬 기기 검사 3개 통과.
- 앱을 데이터 유지 방식으로 설치하고, 설치 APK 해시와 빌드 APK 해시가 일치함을 확인했다. 검사 종료 후 기존 접근성 연결을 복구했으며 bound/enabled, crashed 서비스 없음 상태를 확인했다.

보이는 아이콘의 실제 오버레이 하이라이트와 최종 복구는 서비스 테스트로 검증했다. 실기기 검사는 옆 페이지 이동과 대상 인식까지이며, 전체 글자 크기 조절 작업을 실행한 결과는 아니다. 화면·음성 데이터를 서버에 전송하지 않았고, 진단 중 공개 `/version` 조회만 수행했다. 이번 수정에 서버 재배포는 포함되지 않는다.
