# 배경화면 변경 버튼 하이라이트 누락 원인

배경화면 목표는 `mode=assisted`다. 현재 graph는 설정 앱 진입 → 배경화면 설정 페이지 진입 → `MANUAL_HANDOFF`뿐이며, 페이지 안의 **배경화면 변경** 버튼을 찾는 전환이 없다.

`manual_handoff()`는 배경화면 페이지 제목을 확인하면 직접 진행 전환을 선택한다. 런타임은 `command_type=highlight`를 반환하지만 실제 `action_type=observe_only`, `target_node_id=null`, `target_bounds=null`로 만든다. 앱의 `presentManualSettingsHandoff()`는 `hideGuideOverlay()`를 호출한다. 따라서 화면을 알아보더라도 마지막 버튼의 하이라이트가 나올 수 없는 구조다.

배경화면 변경 버튼이 실제로 있는 합성 관측으로 이 응답을 로컬에서 재현했다. 이는 운영 모델 응답이나 실제 휴대폰 화면을 재생한 실험은 아니다. 현재 공통 계약의 배경화면 경로도 `S0_UNKNOWN`, `S1_SETTINGS_HOME`만 가지고 있으며 해당 버튼 단계는 없다. 어휘에는 ‘배경화면 변경’이 이미 들어 있으므로 단순히 어휘를 더 넣거나 임계값을 낮추는 것으로 해결되지 않는다.

실행 로그에는 설정 메뉴를 누른 시점까지의 wallpaper 선택 메타데이터가 남아 있었다. 원래 실패 순간의 마지막 화면은 포착하지 못했다. 이후 확인된 실제 `WallpaperSettingsActivity`를 열었지만 검사 시 기기가 잠겼고 active root는 NotificationShade였다. 이를 배경화면 앱 패키지 문제로 확정하지 않는다.

필요한 동작은 **배경화면 설정 진입 → 배경화면 변경 버튼 안내 → 개인 사진·배경화면 선택부터 직접 진행**이다. 이를 위한 실제 버튼 전환과 관측 조건을 graph/공통 계약에 추가하고, 개인 선택 화면 진입 뒤에만 하이라이트 종료·관측 중단이 일어나도록 해야 한다. 별도 앱으로 넘어가는 기기는 확인한 화면/메뉴만 제한적으로 지원해야 하며 사진 앱 전체를 통째로 허용해서는 안 된다.

이번 요청은 원인 조사로 처리했고 runtime 코드는 변경하지 않았다. 배경화면을 선택하거나 적용하지 않았고 원본 화면·사진·입력값을 외부에 보내지 않았다.
