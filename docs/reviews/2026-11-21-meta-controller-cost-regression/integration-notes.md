# 실행 전 사용자 변경 통합

첫 모델 없는 준비 검사는 MCv2 코드 `78a4270`과 동일한 runtime 수정으로 수행했다. 이후 원격 `develop`의 `fe30ea5`와 `91f662d`를 확인해 `f1d8bfc`로 통합했다. 사용자 변경은 앱 바/툴바의 수동 제목을 공개 heading으로 관찰하고, 읽을 수 있는 화면에서 모호한 predicted completion을 버려 목적 화면 제목으로 다시 묶는 동작이다. Controller 충돌은 이 동작과 기존 native window·fresh frame 확인을 모두 보존해 해결했다.

유료 모델 호출과 source freeze는 통합 이전에 시작하지 않았다. 통합 뒤 관련 단위 검사·빌드·lint를 재실행하고 새 APK를 설치해 여섯 목표 준비와 native guard, 빈 조건 전체 일정 생성을 다시 수행한다. 통합 전 준비 원문은 `pre-integration-preparation`에 보관하며 최종 결과의 준비 통과 자료를 대체하지 않는다. 실행 전에 고정된 최종 source-freeze가 실제 실행 소스를 가리킨다.

MCv1과의 차이에는 MCv2뿐 아니라 이 공통 완료/관찰 수정과 공급자 응답 차이도 포함되므로 특정 변경의 인과 효과로 주장하지 않는다. 무반응 조건, 앱·목표·일정·관찰 예산·안전 기준은 그대로다.
