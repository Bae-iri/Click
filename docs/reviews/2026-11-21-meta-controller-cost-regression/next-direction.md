# 범용성·속도·비용의 다음 우선순위

현재 선택은 **공통 native 완료 확인과 화면 안정화 + 비용이 제한된 선택적 MetaController**다. 앱별 성공 스크립트나 별도 reflection 모델을 늘리는 구조는 이 비교에서 이득이 입증되지 않았다. 로컬 증거를 먼저 확인하고, 새 계획이 필요할 때만 기존 모델을 호출하며, 근거 없는 복구 반복은 멈추는 경로를 우선한다.

1. **복구로 목표를 실제 달성하는지부터 검증한다.** MCv1 정상 성공 차이는 공급자 실패 차이도 섞였다. 무반응 양팔 성공 0건을 개선했다고 부를 수 없다. MCv2 비용 감소가 확인돼도, 장애에 양팔이 실제 노출된 쌍에서 B만 성공하는 결과와 전체/앱별 성공 비열화가 필요하다. 성공을 희생한 저비용 중단은 별도 상충이다. 이 무반응 주입은 첫 TAP을 무효로 만들고 같은 조작의 무근거 반복을 막는다. 목표에 따라 대체 경로가 부족하므로, 후속 사전 설계에서는 복구 가능한 대체 경로와 적절한 중단이 필요한 경우를 구분하고 새 native 근거·명시적 사용자 의사가 있는 제한된 재시도 정책을 별도로 평가해야 한다. 이번 결과를 본 뒤 재시도 권한이나 성공 지표를 바꾸지는 않는다.
2. **목적 상태를 초기 계획부터 검증 가능한 형태로 유지한다.** 목적 페이지 제목·선택된 탭 등 공개 native 속성을 goal에 묶고, 메뉴 라벨·앱 실행·스크롤 검증을 목표 달성으로 대체하지 않는다. 이미 있는 후보가 충분하면 추가 result_only 모델을 거치지 않고 두 fresh frame으로 확인한다. 후보가 불충분할 때만 제한된 읽기 전용 요청을 사용한다. 외부 oracle을 제품 플래너에 주입하거나 앱별 정답 경로를 넣지 않는다.
3. **고정 대기 시간보다 관찰의 새 정보를 사용한다.** 실제 transition이 있으면 먼저 최신 상태를 읽고, 같은 조작을 다시 실행하지 않는다. 지금의 bounded 안정화/8초 lease가 긴 작업과 느린 기기에 미치는 영향을 새 반복 실험에서 따로 측정한다. 마감시간만 줄여 실패를 싸게 만드는 최적화로 평가하지 않는다.
4. **호출 수와 성공당 비용을 함께 측정한다.** provider deadline을 포함한 실제 시도, 모델 대기 시간, token usage 미확인을 유지한다. 토큰이 확인되지 않은 요청을 0으로 처리하지 않는다. 현 자료만으로 금액을 추정하지 않으며, 필요하면 실제 청구 자료와 연결한다. 모델 종류·앱 범위·성공 기준을 함께 바꾸지 않는 다음 비교가 효과 분리에 유리하다.
5. **넓은 채택은 반복·새 앱·기기로 판단한다.** 현재 목표별 1회와 세 앱만으로 범용성이나 중장년층 사용성을 입증하지 않는다. 다음 단계는 앱별 규칙을 추가하지 않은 상태에서 새로운 앱·다단계 탐색·실제 지연을 반복하고, 성공·실패 포함 시간·API 시도를 함께 비교하는 것이다. UI는 기존 행동 승인과 화면 확인 흐름을 유지하고 불필요한 버튼을 추가하지 않는다.

새로운 재시도 권한이나 모델 증설을 기본값으로 도입하지 않았다. 사용자에게 다시 승인받는 기능 자체가 필요한지는 실제 막힌 사례와 사용성 근거로 판단해야 한다. 이 문서의 미구현 방향을 이번 실험에서 검증한 기능이나 성과로 세지 않는다. 최종 go/no-go는 이번 결과 README와 사전 프로토콜의 범위를 따른다.
