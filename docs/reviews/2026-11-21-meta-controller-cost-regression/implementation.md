# MCv2 비용 제약 변경

직전 [MCv1 실제 앱 비교](../2026-11-20-native-public-apps-b2/README.md)에서는 B의 공동 성공이 A보다 2건 많았지만 실제 모델 시도가 47회 대 29회였다. 무반응 조건은 양쪽 공동 성공 0/6인데 A 6회·B 17회였다. 실패 뒤 복구 context 요청은 한도를 적용했지만, 뒤따른 일반 요청은 context가 지워지면 한도를 피했다. 또 스크롤·앱 열기 동작의 native VERIFIED만으로 경로 기록을 초기화했다. 이 동작 검증은 하위 목표 달성 증거가 아니다.

MCv2는 미해결 실패 상태를 즉시 동작 context와 분리한다. 그 상태의 일반 next_action 요청도 같은 현재 경로당 한 번, 작업 전체 복구 계획 예약 3회 제한을 사용한다. 예약은 화면 안정화 뒤 실제 요청 구성 직전에 하고, 그 예약 번호를 최신 observation에 연결한 recovery context로 전달한다. 중간 스크롤이나 앱 열기가 검증돼도 기존 실패의 실제 action 참조와 예산은 유지한다. 실패 원인 context가 사라져 플래너가 일반 요청으로 오해하는 경로도 함께 줄인다.

경로 제한의 초기화는 서로 다른 최신 공개 관찰에서 요구한 native 상태가 새로 성립하고 불변 계획의 하위 목표가 바뀌었을 때, 사용자가 대상을 바꿨을 때, 기존 화면 확인 기능을 명시적으로 요청했을 때만 허용한다. task 전체 3회 예약 한도와 거절된 실제 조작 기록은 보존한다. 자동 화면 관찰·이벤트·내부 refresh는 초기화하지 않는다. 새 버튼·레이아웃·문구는 추가하지 않았다.

현재 화면을 증거로 확인하는 로컬 완료 경로와 읽기 전용 result_only 후보 요청은 일반 복구 호출 제약에서 제외했다. 이 변경은 완료 기준을 완화하거나 동일한 실패 TAP을 자동 재시도할 권한을 주지 않는다. 과도한 제한은 필요한 탐색도 멈출 수 있으므로, 비용과 성공을 별도로 보고한다. 슬롯 예약 수는 실제 공급자 시도 수나 청구액이 아니다.

기존 공통 개선인 최신 화면에 대한 읽기 전용 완료 후보 회수, 2개 native 프레임의 완료 증거, 변화 직후 bounded 화면 안정화는 유지한다. mc_v0/mc_v1 서버 계약도 읽을 수 있으며 새 META 실행은 mc_v2로 명시한다. 원래 MCv1의 분석을 새 진단 허용 코드로 재실행했을 때 요청 감사와 요약 JSON은 모두 동일했다.

이 회귀 검증은 새 suffix의 결과 경로와 실제 정책 provenance를 기록하고 전체 36회 중 사전 선택한 무반응 12회만 실행한다. 나머지 24회는 NOT_RUN이다. 모델·앱·관찰 예산·안전 기준을 유지하며, 출처·APK·준비·전체 일정을 새 모델 호출 전에 동결한다. 정확한 테스트 수와 빌드 결과는 [unit-verification.json](unit-verification.json), 실행 후 결과는 README와 원자료를 따른다. 소스 코드 검사만으로 실제 비용 감소를 주장하지 않는다.
