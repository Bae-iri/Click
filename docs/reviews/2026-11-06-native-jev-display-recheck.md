# 2026-11-06 실기기 디스플레이 안내 재측정

## 판정

현재 설치 앱이 호출하는 Render 서버에서 **첫 안내 뒤 같은 화면을 재관측하면 안내 대상이 사라지는 현상을 재현했다.** 안내 유지 판정은 FAIL이다. 테스트 APK의 진단 실행 완료를 제품 동작 성공으로 계산하지 않는다.

이번 실행에서는 로컬 Backend/AI-Agent 수정본을 서버에 배포하지 않았다. 서버 revision도 확인되지 않았다. 서버 응답에는 새 진단 필드와 안내 유지 표시가 없으므로, 이번 결과를 수정본의 실기기 통과 결과로 사용할 수 없다.

## 실행 조건

- 기기: Samsung SM-N981N, Android 13.
- 설치 앱의 서버 주소: `https://click-db.onrender.com`.
- 실제 Android 설정 화면을 접근성 서비스로 매번 새로 읽고 앱의 `SettingsScreenPrivacy` 필터를 적용했다. 합성 화면이 아니다.
- 사용자에게 전송 항목·목적지를 안내하고 최대 6회 전송 승인을 받은 뒤 화면 요청 5회를 수행했다. 실제 Jev 호출은 5회였다.
- 원본 이미지·계정 문구·입력값은 보내지 않았다. 인증 정보는 앱 내부의 기존 인증 경로를 사용했으며 로그로 추출하지 않았다.
- 현재 설치 앱을 교체하거나 앱 데이터를 초기화하지 않고 테스트 APK만 갱신했다.

## 결과

| 회차 | 최종 신뢰도 | API 응답 시간 | 응답 상태 | 실제 안내 대상 |
| --- | ---: | ---: | --- | --- |
| 1 | 0.94 | 586 ms | selected | 디스플레이 |
| 2 | 0.79 | 441 ms | low_confidence | 없음 |
| 3 | 0.77 | 438 ms | low_confidence | 없음 |
| 4 | 0.77 | 485 ms | low_confidence | 없음 |
| 5 | 0.79 | 605 ms | low_confidence | 없음 |

다섯 관측 모두 실제 네이티브 화면의 내용이 같았다. UI 후보는 매번 하나이고 통과 기준은 0.8이었다. 서버가 반환한 `confidence`는 최종값이다. 이 서버 응답에는 `raw_confidence`, `choice`, `choice_count`가 없어 2~5회 모델이 선택한 항목과 원본 confidence를 확정하지 않는다.

마지막 응답이 유효한 터치를 안내하지 않아 디스플레이를 실제로 누르지 않았다. 따라서 실제 경로 이동·글자 크기 변경·완료 성공을 주장하지 않는다. 테스트 세션은 취소됐고 글자 배율은 시작과 종료 모두 1.1이었다.

## 기기 내부 검사

- 접근성 서비스 재연결과 창 안정화를 기다린 후, 포커스를 가진 안내 오버레이 뒤의 설정·홈 화면 수집 검사 통과: 0.948초.
- 실제 목록을 한 번 스크롤하여 보이는 디스플레이 항목을 찾고 로컬 개인정보 필터 검사 통과: 3.905초.
- 해당 로컬 검사에서 허용된 문구는 설정·연결·소리 및 진동·알림·디스플레이·배경화면 및 스타일이었다. 필터 결과는 15개 노드였다.
- 위 두 기기 내부 검사는 Jev 모델 정확도나 수정된 서버 실행 경로를 평가한 결과가 아니다.

## 후속 조건

Backend와 AI-Agent 수정본을 같은 검증 서버에 반영하고 서버의 코드·graph·모델 설정을 식별한 뒤 재측정해야 한다. 첫 선택 이후 동일한 유효 화면에서 `called=false`, `retained=true`와 같은 안내가 유지되는지, 신뢰도 미달 반복의 복구 한도와 명시적 재시도가 작동하는지 확인한다.
