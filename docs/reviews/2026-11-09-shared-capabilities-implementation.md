# 공통 설정 기능 계약 및 다섯 항목 수정 결과

사용자가 지정한 다섯 항목을 구현했다. Android 앱 설치와 로컬 전체 검사는 완료했다. **Backend·AI 변경은 운영 서버 재배포가 필요하며 이번 작업에서 배포하지 않았다.**

## 변경

| 항목 | 결과 |
| --- | --- |
| 공통 기능 계약 | 승인 graph에서 `settings_capabilities.json` 생성. 110개 goal, 승인된 메뉴 이름 193개, 화면 상태·별칭·안전 조건·탐색 한도 공유 |
| 화면 상태 불일치 | Android와 Backend가 같은 계약으로 목록 이동 단계를 판단. `S_CATEGORY`, `S_INTERMEDIATE` 및 이전 상태 이름 지원 |
| 기존 메뉴 중심 자동 클릭 | 현재 확정 goal/단계의 확장 메뉴까지 허용. private identity, 잘못된 단계, 값 변경 컨트롤은 계속 차단 |
| 실행 계약의 해시 누락 | `source_digest()`와 runtime `code_hash`에 공유 실행 JSON 포함. 공개 `/version`과 runtime metadata에 계약 SHA-256 제공 |
| 탐색 예산 초기화 | session/episode에 이동 수·시간 한도 누적. 창 ID·노드 경로·페이지 단계 이동·홈 복구·자동 모드 변경으로 환불하지 않음 |

삼성 실기기 확인 중 블루투스·Wi-Fi 메뉴 행에 별도 스위치가 들어 있는 구조를 확인했다. 단순 메뉴 이름 허용만으로는 기존 안전 정책에 막혔다. 실제 native 제목·현재 페이지·goal/단계가 맞고 스위치와 영역이 겹치지 않을 때 **제목 영역만 제스처로 누르는 경로**를 추가했다. 스위치나 행 전체의 ACTION_CLICK을 사용하지 않는다. 겹침·다른 화면·다른 목표는 거부한다.

계약 JSON이 바뀌면 Gradle이 동일 JSON에서 Android 정책 데이터를 다시 생성한다. 컴퓨터의 JVM 검사와 실제 앱이 같은 바이트의 계약을 사용함을 검사했다. CI에서는 승인 graph와 생성 계약이 어긋나면 실패한다.

탐색 한도는 런처 8회/45초, 설정 목록 32회/120초다. 진행 없음·방문 반복·끝 확인 시에는 더 일찍 종료한다. 서비스 프로세스를 종료한 뒤 예산을 영구 복원하는 기능까지 추가한 것은 아니다.

## 검증

- 최종 Android JVM 전체: **598개 통과**, 실패·오류·건너뜀 0개.
- 최종 Backend 전체: **2,071개 통과**.
- 최종 AI-Agent 전체: **393개 통과**.
- 생성 계약 최신성, 실행 JSON 다섯 종류의 해시 반영, public identity에 민감값이 없는지 검증했다.
- 실제 오버레이의 확장 메뉴 자동 native 호출, 새 상태의 스크롤 복구, 계약 불일치 시 수동 안내, 창·노드 경로 40번 변경에도 32회 상한 유지 검사가 통과했다.
- native 동작 검사는 스위치와 분리된 실제 제목 좌표로 제스처가 나가며, 스위치와 제목이 겹치면 실행이 없는지 확인했다.
- Samsung SM-N981N 실기기 읽기 전용 검사에서 **블루투스·Wi-Fi 모두 제목 영역을 허용 대상으로 인식**했다. 스위치 조작 대상이 아님을 확인했다. 설정값 변경·기기명/화면 외부 전송은 하지 않았다.
- 설치 APK 해시 일치와 기존 접근성 서비스 bound/enabled, crashed 서비스 없음 상태를 확인했다.

이는 지정된 결함 수정 및 native 대상 검증 결과다. 현재 운영 Jev와 새 Backend를 함께 배포한 뒤 설정 작업을 처음부터 끝까지 실행한 결과는 아니다.

- 공개 서버에는 아직 새 `capability_contract`가 없었다. 서버 재배포 후 앱과 계약 해시를 대조해야 한다.
- 새 서버가 다른 계약 해시를 광고하면 앱은 자동 탭을 중단하고 직접 진행으로 전환한다. 이전 서버가 선택 필드를 생략하면 앱에 포함된 승인 경로로 호환 동작한다.

기존 DB graph를 같은 버전으로 덮어쓰는 수정은 하지 않았다. 별도 감사 항목인 DB graph 버전/활성화 관리는 별도 범위다.
