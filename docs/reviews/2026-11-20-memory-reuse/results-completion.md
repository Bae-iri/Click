# 완료 판정 비교 결과 — develop(B) vs 312ff36 결속 규칙(C)

프로토콜: [protocol-completion.md](protocol-completion.md). 같은 기기·모델·기억(정확 일치), 정답이 검증된 7과제 × 4회기 × 2비교군 = 회차당 56회. 서버 완료 판정만 다르다.

## 결론

- **서버 완료 판정은 우열 판단 불가.** 3회차에서 자동 완료 인정 B 5 / C 4, 거짓 완료 0 / 0. 차이는 과제 하나(설정 알림)의 1회뿐이다. C를 쓸 근거가 없으므로 **develop의 판정(B)을 유지한다.** B는 완료 조건 확정도 더 많았다(22 / 13).
- **효과는 두 비교군 공통의 기기 수정에서 나왔다.** 설정 과제의 자동 인정이 1회차 0/15에서 3회차 9/14로 올랐다(분모는 목표에 실제로 도달한 회차)(설정 2과제, 두 비교군 합산). 거짓 완료는 계속 0이다.

## 회차별 결과 (유튜브 제외 5과제, 비교군당 20회)

| 회차 | 바뀐 것 | B 자동 인정 | C 자동 인정 | 거짓 완료 |
|---|---|---:|---:|---|
| 1 ([raw-completion](raw-completion)) | 없음 (develop 그대로) | 0 | 0 | 0 / 0 |
| 2 ([raw-completion-v2](raw-completion-v2)) | 기기: 페이지 제목 노출, 애매한 예측 조건 해제 | 0 (+유튜브 구독 4) | 0 (+유튜브 구독 3) | 0 / 0 |
| 3 ([raw-completion-v3](raw-completion-v3)) | 하네스: 정답 성립 뒤 최대 8초 동안 기기 인정 대기 | 5 | 4 | 0 / 0 |

3회차 세부: 목표 도달 B 19/20, C 17/20. 인정까지 걸린 시간 중앙값 B 5.8초, C 4.2초. 기억 출처 제안은 양쪽 0.

## 원인과 기기 수정

1. **1회차 0회의 원인.** 기기 규칙(`AppTaskCompletion.unsafeForGoal`)은 목적지 안의 누를 수 있는 메뉴를 도착 증거로 받지 않는다(친구 설계, 유지). 그런데 페이지 제목은 화면 정보에 없었다. 플래너는 "밝기", "앱 알림" 같은 메뉴를 골랐고([raw-completion-probe](raw-completion-probe)), 기기는 "판단 불가"로 끝났다.
2. **기기 수정 (develop 반영).**
   - `AppTaskObservation.pageTitle`: 앱바·툴바(`action_bar`, `toolbar`, `app_bar`) 안에서 조상에 누를 수 있는 노드가 없는 텍스트를 제목 노드로 내보낸다. 기존 제목 한도 6개와 개인정보 필터를 그대로 쓴다. 본문 텍스트는 계속 내보내지 않는다.
   - `AppTaskController.observeResult`: 읽을 수 있는 화면에서 "판단 불가"가 나온 예측 완료 조건(같은 라벨이 둘인 경우 등)은 버린다. 그러면 도착 화면에서 결과 확인 단계가 제목으로 다시 정할 수 있다.
3. **2회차 설정 0회의 원인.** 서버는 도착 후 "디스플레이", "알림" 제목을 정확히 묶었다([raw-completion-probe2](raw-completion-probe2)). 그러나 모의 사용자가 정답 유지 0.7초 직후 확인을 눌러, 3~4초 걸리는 도착 후 결속보다 먼저 끝났다. 측정 방식의 문제였으므로 3회차에서 대기 시간을 넣었다.

## 남은 문제

- **크롬·시계 자동 인정 0.** 시계는 완료 조건이 "타이머" 버튼으로 묶여 거절된다. 크롬은 도착 화면이 보호 화면으로 처리되는 경우가 많다.
- **기억 재사용 0.** 확인된 경로가 대부분 1단계라 회수 조건을 넘지 못한다.
- **유튜브 준비 실패.** 1·3회차에 16회 모두 준비 단계에서 실패했다. 시작 화면이 홈이 아니었다(1회차는 이전 수동 테스트의 검색 화면).

## 실험 도구

- `serve_memory_experiment.py --completion-comparison`: B=develop, C=312ff36 결속 규칙. 서버 단계 잠금 안에서만 모듈 함수를 바꾼다. 묶인 완료 조건의 공개 라벨, 역할, 리소스를 기록한다.
- `MemoryDeviceExperimentTest -e verifyWaitMs N`: 정답 성립 뒤 기기 자체 인정을 최대 N ms 기다린다. 기본값 0은 이전 실험과 같다.
- [raw-completion-probe2a](raw-completion-probe2a): 2회 확인 실행 중 완료 조건이 묶이지 않은 첫 시도. 참고용이다.
