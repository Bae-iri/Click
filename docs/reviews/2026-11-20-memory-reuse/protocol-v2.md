# 2차 실행 프로토콜 — 완료 판정·경로 증거 수정 후 (본 실행 전 고정)

1차 실행과 같은 기기, 모델, 12과제, 미러 요청, 정답, 비교군(A/B/C), 6회기, 25초 예산을 쓴다. 바뀐 것은 아래 제품 수정과 로그 항목뿐이다.

## 제품 수정

1. **완료 조건 결속 규칙(GoalContract).** 모델이 제안한 완료 조건 전체가 결속하는 화면에서 이미 성립하면 결속하지 않는다(`completion_rejected=satisfied_at_binding`). 프롬프트에도 지금 보이는 라벨이나 누를 대상을 완료 조건으로 쓰지 말라는 문장을 추가했다. 결속하지 않으면 기기는 VERIFIED 결과 확인을 제시하지 않는다.
2. **경로 키 v2.** 경험 이벤트, 경로 접두사, 기억 동작의 도착 화면 확인에 상호작용 컨트롤과 그 네이티브 상태만으로 만든 키를 쓴다. 완료·기대 라벨 때문에 추가되는 정적 텍스트와 스크롤 viewport 해시를 제외한다. 실행 중 화면 변화 판정(`learningKey`)은 바꾸지 않았다. 정책 해시가 바뀌어 1차 기억은 재사용되지 않는다.
3. **사용자 확인 결과에 의한 마지막 동작 인정.** 관측된 마지막 동작의 검증이 미확인이어도, 사용자가 그 동작이 만든 화면(경로 키 일치, 화면 변화 있음)에서 결과를 확인하면 경로의 성공 단계로 인정한다. AI2 분석(`effect_evidence=user_confirmed_result`)과 기기 경로 캐시 양쪽에 적용한다. 거절된 동작, 관측되지 않은 동작, 마지막이 아닌 동작은 인정하지 않는다.

## 추가 기록

- 플래너 호출마다 완료 조건 결속 여부와 거절 사유
- 확인된 결과마다 AI2 분석 상태, 경로 단계 수, 단계별 증거 출처

## 주 지표와 판정

- 잘못된 VERIFIED 제시: 1차 63/216 대비 감소해야 완료 판정 수정 GO
- 확인된 작업 중 경로 조건 통과 비율: 1차 2/21 대비 증가, 같은 목표에서 경로 2개 이상 형성 여부
- 기억 출처 제안 수와 그 회기의 독립 성공
- 독립 성공률(전체, 그리고 MetaController 정답 양성 대조가 확인된 7과제: settings_display, settings_notifications, clock_timer, chrome_menu, chrome_new_tab, youtube_subscriptions, youtube_search)

1차와 2차는 같은 날 순차 실행이며 무작위 배정이 아니다. 실행 간 차이에는 시간대·제공자 지연 변동이 섞일 수 있다.
