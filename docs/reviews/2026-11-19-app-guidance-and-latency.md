# 앱 범위 확장·응답 지연 점검

2026-11-19, 한국 시간 기준. 화면 변경, 연결 상태, 실제 모델 호출 성공을 별도로 확인했다.

## 이번에 적용한 변경

- 입력 메뉴의 세 버튼은 최소 높이 52→48dp, 위아래 안쪽 여백 8→4dp, 버튼 간격 8→4dp로 줄였다. 아이콘은 36→32dp로 줄이고 제목과 버튼 사이에는 12dp를 둔다. 큰 글씨에서는 내용 높이에 맞춰 커진다.
- 줄인 안내 말풍선의 배경은 `0xE6FFFFFF`로 바꿨다. 배경만 약 90% 불투명도로 표시하고 글자에 투명도를 곱하지 않는다.
- 설정·정부24·쿠팡 경로와 별도로 **앱 허용 목록이 없는 화면 안내**를 추가했다. `/api/v1/agent/app-guide/step`은 특정 패키지, 앱별 그래프, 정해진 메뉴 이름을 요구하지 않는다.
- 기존 실행 경로가 없거나 요청을 카탈로그에 연결하지 못하면 앱에서 공통 화면 안내를 제안한다. 사용자가 동의한 뒤 현재 앱의 보이는 버튼·메뉴 이름으로 다음 위치를 찾는다. 서버는 새 경로를 OpenAPI로 알리고 앱은 이를 확인한 경우에만 진입한다.
- 공통 안내는 한 화면에서 항목 하나만 고른다. 앱은 제출한 화면의 노드 ID·좌표·관측 ID와 응답을 대조한다. 사용자가 직접 누르고, 바뀐 화면에서 다음 위치를 찾는다. 없는 좌표나 완료 판정을 모델이 만들 수 없다.
- 화면 이벤트는 300ms 동안 모아 처리하고 같은 화면은 다시 호출하지 않는다. 응답 중 앱·화면이 바뀌면 이전 응답을 버린다. 중지·일시정지 후 늦게 도착한 결과도 표시하지 않는다.
- 공통 안내는 입력 내용·비밀번호 화면을 내보내지 않고, 개인 연락처·대화 영역 등을 제외한 컨트롤 이름을 최대 60개 사용한다. 화면 이미지 업로드는 추가하지 않았다. 입력·인증·결제·최종 제출 등은 사용자가 직접 진행한다.
- 기존 Gemini 진단의 HTTP 200 판정을 보강했다. 빈 응답, 잘린 생성, 생각 토큰만 있는 응답, 잘못된 JSON, 중복 JSON 키를 성공으로 기록하지 않는다.
- 정부24 플래너는 과부하·인증·할당량 등 정제된 제공자 오류와 전송 타임아웃을 구분해 남긴다. 원본 오류 문장이나 요청 내용은 기록하지 않는다.

## 구조에 대한 피드백

1. **앱별 기능을 계속 추가하는 방식으로는 범용성이 생기지 않는다.** 카탈로그와 승인 그래프는 검증된 작업의 빠른 경로로 두고, 나머지는 공통 관측→항목 선택→사용자 조작→재관측 경로로 처리해야 한다. 이번에 이 두 경로를 연결했다.
2. **모든 화면 이동 전에 완성된 계획을 기다리게 하면 첫 안내가 늦어진다.** 새 공통 경로는 다음 컨트롤 하나만 선택하고 8초 읽기 예산을 사용한다. 전체 계획 생성과 짧은 항목 선택은 별도 지표로 측정해야 한다. 기존 정부24 25초 경로의 지연을 해결했다고 주장하지 않는다.
3. **관측과 검증을 여러 번 하는 것 자체가 실패는 아니다.** 실제 호출 여부, 화면 변화, 사용자 대기, 네트워크 시간을 나눠야 한다. 이번 경로는 동일 화면 호출을 합치고 오래된 응답을 버린다. 설정 경로에도 이미 선택 유지 기능이 있으므로 중복 캐시를 더 붙이기보다 무효화 원인을 측정해야 한다.
4. **모델 이름보다 실행 인터페이스가 중요하다.** 공개 UI 모델을 가져와도 Android의 현재 노드와 연결하지 못하면 틀린 위치를 누른다. 컨트롤 ID에 근거한 응답, 현재 화면 검증, 사용자의 조작 이후 결과 확인이 공통 계약이어야 한다.
5. **학습 경로 재사용은 이미 구현돼 있다.** `settings_graphs.py`와 `settings_experiment.py`의 경로 재사용은 기본 비활성화이며 기기 범위·그래프·런타임 코드 해시·모델이 일치해야 한다. 이를 없는 기능처럼 다시 만들면 안 된다. 운영 활성화·적중률부터 측정하고, 이후 전체 코드 해시 대신 호환 계약을 기준으로 재사용할 수 있는지 검토한다.
6. **‘아무 앱이나 안내’와 ‘모든 작업을 끝까지 자동 실행’은 구분해야 한다.** 이번 확장은 접근성으로 보이는 컨트롤의 수동 안내다. 접근성 정보가 없는 캔버스·게임·보호 화면이나 복잡한 입력 작업까지 검증된 것은 아니다. 완료는 모델의 선언 대신 사용자 확인 또는 실제 상태 증거로 판단해야 한다.

## Gemini 확인 방법

저장소 루트에서 실행한다. 비밀번호나 키 값을 명령줄에 넣지 않는다.

```sh
PYTHONPATH=Backend:AI-Agent/src python3 Backend/scripts/diagnose_gemini.py --env-file Backend/.env --timeout 12
python3 Backend/scripts/check_gov24_planner.py --env-file Backend/.env
```

첫 명령의 `success=true`, `schema_valid=true`, 실제 `served_model`을 확인한다. 두 번째 명령은 앱의 정부24 계획 생성 자체를 검사한다. 첫 명령 성공을 두 번째 경로의 성공으로 대체하면 안 된다.

앱의 새 공통 경로는 `ClickAppGuide` 태그에 모델, 실제 호출 여부, 지연, 상태, 정제된 이유·HTTP 상태를 남긴다. 키·입력문·화면 원문은 로그에 추가하지 않는다. APK 변경은 앱 업데이트가 필요하고 새 서버 경로는 백엔드 배포가 필요하다.

## 검증 범위

- Android 전체 단위 검사 1,057건 통과. 마지막 중지·일시정지 보완 이후 관련 검사 271건 재검증 통과, 앱·계측 APK 빌드 통과.
- 백엔드 전체 검사에서 3,252건 통과·1건 건너뜀. 실패 6건은 sandbox의 forkserver 로컬 소켓 제한으로 발생했으며, 해당 프로세스 검사와 새 API 검사를 권한이 허용된 환경에서 다시 실행해 45건 모두 통과했다.
- 입력 메뉴·접힌 말풍선·큰 글씨 실기기 UI 검사 3건 통과.
- 공통 경로의 임의 앱 패키지, 민감 화면 제외, 없는 좌표 거절, 동일 화면 호출 유지, 다른 앱으로 이동한 뒤 옛 응답 폐기, 취소·일시정지 후 응답 폐기를 검사한다.
- API 생성·인증 의존성, 모델의 미지원 선택·완료 선언·추가 필드 거절, 과부하 진단을 검사한다.
- 통제된 테스트와 공개 버튼 예시의 실제 Gemini 호출은 실제 여러 앱의 종단 성공률을 대신하지 않는다.
