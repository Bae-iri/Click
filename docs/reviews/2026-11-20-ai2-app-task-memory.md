# AI-Agent 2와 앱 공통 실행 경험 연결

앱이 같은 요청에서 무엇을 시도했고 어디서 막혔는지 서버에 보관하고, AI-Agent 2의 분석을 다음 요청에서 다시 사용하도록 연결했다. 앱을 재시작하거나 Backend 서비스 객체를 새로 만들어도 유지되는 DB 기반 기억이다. Codex/ChatGPT 대화 기억을 저장하거나 Gemini의 가중치를 학습하는 기능과는 구분한다.

## 실제 연결 경로

```text
현재 화면·동작 확인 → 기기의 실행 결과 검사
  → 사용자별 암호화 업로드 대기열
  → POST /api/v1/agent/app-guide/task/events
  → encrypted runtime_events(kind=app_task)
  → 별도 프로세스의 AI-Agent 2 workflows/app_tasks.py
  → 원천 기록과 연결된 분석 receipt·app_task_experience 후보
  → POST /task/memory 및 AppTaskService 조회
  → 확인한 방법 재제안 또는 Gemini 계획의 성공·실패 참고 정보
  → 현재 대상 재검사·사용자 확인·네이티브 실행·결과 재검증
```

앱을 직접 조작하는 도구나 완료 판정 권한을 AI-Agent 2에 부여하지 않는다. 메모리가 제안한 동작도 새 화면의 실제 대상에 다시 연결하고 한 단계마다 확인한다. 명확히 재사용할 수 있으면 Gemini 호출 없이 제안을 반환한다. 자료가 부족하거나 방법이 여러 개면 기존 계획기로 돌아간다.

## 무엇을 기억하고 다시 쓰는가

- 앱 패키지·앱 버전·Android API, 목표·하위 단계·현재 화면·대상의 구조 해시, 동작 종류, 관측된 변화와 명시적 결과 확인을 기록한다.
- 입력값·음성 원문·화면 문구·스크린샷·좌표는 개선용 이벤트에 넣지 않는다. 검색 입력의 정확한 값 검사는 기기에서 수행하고, 그 값이나 검사용 해시는 업로드하지 않는다. 목표 문장과 구조를 구분하기 위한 별도 해시만 사용한다.
- 서버가 받은 순서와 기기의 관측 시각을 함께 사용한다. 과거 오프라인 성공 기록이 나중에 올라와도 더 최근의 거절·미확인 기록을 지우는 근거가 되지 않는다.
- 앱 버전·목표·현재 화면과 진행 맥락을 대조한다. 단계 계획이 있으면 하위 단계가 같아야 하며, 없으면 실제 수행한 동작의 해시 경로가 일치해야 한다. 같은 화면으로 돌아온 상황을 새 작업의 첫 화면으로 혼동하지 않는다.
- 서로 다른 두 작업에서 모든 조작이 연결되고 사용자가 최종 결과를 확인한 경로만 재제안 근거가 된다. 버튼 호출 성공이나 화면 변화만 있는 작업은 기술적 관측과 일반 전략 참고에만 쓰며 완료된 경로의 독립 지지로 계산하지 않는다.
- 거절·미확인은 성공과 분리한다. 이후 새로 확인된 두 작업이 있으면 회복할 수 있다. 독립 검수 정답이나 정확도 확률로 승격하지 않는다.
- 다른 앱에는 `누르기·공개 검색 입력·스크롤·뒤로·앱 열기`의 확인된 도구 종류와 재관측 같은 일반 전략만 전달한다. 이전 앱의 선택자를 새 앱에 추측 적용하지 않는다.

## 기억의 범위와 수명

| 범위 | 저장 위치 | 수명·삭제 |
| --- | --- | --- |
| 현재 작업 단계와 수행 경로 | 기기의 기존 암호화 저장소 | 기존 체크포인트를 24시간 내 이어감 |
| 전송 대기 경험 | 같은 사용자별 암호화 저장소 | 최대 24시간·256개, 오래된 작업 단위로 제거 |
| 개선용 원천 기록 | 기존 encrypted runtime_events | 최대 7일, 상위 세션 삭제·기존 보존 작업에 따라 먼저 삭제될 수 있음 |
| AI-Agent 2 분석과 후보 | 기존 encrypted receipt·graph_proposals | 가장 먼저 만료되는 원천과 함께 만료, 원천 삭제 후 재사용 금지 |

영구 기억이나 다른 사용자에게 공유하는 학습 정답 저장소는 아니다. 재사용은 로그인한 같은 사용자 범위로 한정한다. 설치한 전체 앱 목록도 보내지 않는다.

## 동의·오프라인·호환성

기존 **메뉴 → 클릭 개선 참여**의 `model_training` 동의를 사용한다. 서버가 현재 동의와 세대 ID를 확인하기 전에는 새 경험을 수집하지 않는다. 앱 열기 전에 비공개 내용 없는 상태에서 동의 메타데이터를 조회할 수 있다. 조작 시작 시각을 별도로 검사하여 나중에 동의가 도착해도 이전 조작을 소급 수집하지 않는다. 철회하면 현재 기기의 전송 대기열과 서버 분석·후보를 제거하고 다시 사용하지 않는다. 재동의 시에는 새로운 경험 ID와 순서로 시작하며, 예전 세대 기록을 소급 학습하지 않는다.

기록 전송은 화면 계획 요청과 다른 실행 큐를 사용한다. 전송 실패로 안내를 막지 않고 다음 연결에 재시도한다. 안내창 종료 뒤에도 이미 시작한 제한된 기록 전송은 마무리하며, UI 콜백은 폐기한다. 계정이 바뀌거나 로그아웃하면 이전 사용자 대기열을 읽고 쓰지 않는다.

새 `/task/memory`, `/task/events`, `/task/result` 경로가 모두 광고될 때만 이 연결을 켠다. 구버전 v2 서버에는 새 `environment`·`path_prefix` 필드도 보내지 않아 엄격한 이전 요청 스키마와 호환한다.

## 사용자 결과 확인과 요청 큐 종료

일반 앱 안내에서 단순 종료는 기존처럼 `USER_ABORTED`로 처리한다. **더 보기 → 결과를 확인했어요**를 별도로 선택했을 때만 `/task/result`로 사용자 결과 확인을 먼저 전달한다. “안내 끝내기”를 목표 달성으로 바꾸지 않는다. 결과 확인 API가 없는 서버에는 이 별도 선택지를 표시하지 않는다.

이 제어 API는 학습 동의와 독립적이다. 그래프·episode가 고정되지 않은 소유 세션만 종료하며 활성 lease·다른 실행기·취소·만료 세션을 덮어쓰지 않는다. 결과는 `USER_REPORTED_RESOLVED`, 기술 판정은 `UNVERIFIABLE`로 남긴다. 서버 확인에 실패하면 로컬에서 완료를 주장하지 않고 진행 내용을 보관한다. 같은 결과 요청은 중복 완료되지 않는다.

## 운영과 배포

새 DB 테이블이나 migration은 필요하지 않다. 기존 암호화·외래 키 cascade·동의 잠금을 사용한다. 이벤트 순서는 기존 실행기와 충돌하지 않는 별도 범위를 사용하며 기존 runtime session version은 기록 수집으로 변경하지 않는다.

Backend에서 `python scripts/agent2.py learn-app-tasks --limit 100`으로 재처리할 수 있다. 통합 `process`에도 포함한다. 기본 자동 작업은 응답 이후와 60초 주기이며, 자격 증명은 프로세스 인자가 아닌 기존 환경 전달 방식을 사용한다. 실행 프로세스가 AI-Agent 2 분석 코드를 직접 import하지 않는다.

이 연결을 실제 사용자 앱에서 사용하려면 새 Backend API 배포가 필요하다. APK만 업데이트하면 기존 서버의 미광고 기능은 호출하지 않는다. 이전에 확인한 GitHub Actions 계정 결제·지출 한도에 따른 배포 차단은 별도 상태다.

## 검증

검증은 별도 checkout의 임시 SQLite·제어된 provider·합성 기록으로 수행했다. 실제 사용자 데이터셋이나 독립 정확도 평가를 구성한 것은 아니다.

- AI-Agent 전체 546개 통과 후 최종 앱 경험 분석 10개 재검증.
- Backend 기존 분석·동의·큐·암호화·탐색 학습 회귀 155개 통과. 최신 요청 수정 API와 통합한 최종 공통 작업·AI-Agent 2 연결 회귀 89개 통과.
- Android 전체 1,117개 통과 후 최신 앱 열기·검색·안내 화면 변경과 통합한 관련 회귀 376개 통과. 최종 OpenAPI 계약 검사도 통과했다. Debug·Release 전체 Lint 오류는 0개다.
- 실제 인증·요청 큐 생성 → 기록 수집 → 별도 프로세스의 AI-Agent 2 → DB 분석 → 새 서비스 객체에서 재사용을 검증했다.
- 동의 철회·재동의·계정 교체·삭제·다른 상위 세션의 원천 삭제·만료·중복·순서 누락·이전 오프라인 기록·실패 후 회복·진행 단계 혼동을 반례로 검사했다.

- Galaxy Note20(Android 13)에서 최종 앱의 안내 패널·큰 글꼴·입력·화면 검사 3개와 설정·Chrome·YouTube의 공통 앱 열기·뒤로 이동·스크롤·누르기 검사 1개를 통과했다. 피드 갱신으로 오래된 관측이 거절되면 새 관측으로 재시도하며, 실행이 수락된 동작은 중복 재시도하지 않는다.

서버 경험 재사용은 위의 임시 DB·제어된 provider 검사이며 운영 서버에 배포되었다는 의미는 아니다. 확인한 운영 버전은 `011e9f1f13abb93af8f18dd30e6874cf2d36da21`이며, 새 경험·기억·결과 확인 API는 아직 광고하지 않는다.
