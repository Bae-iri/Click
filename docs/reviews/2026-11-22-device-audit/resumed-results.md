# 재배포 후 실기기 검사 완료

2026-11-22, Galaxy Note20(SM-N981N, Android 13) 1대. 운영 API 배포 `bcd7ac97d7750df80a7b8d1dac54216ca6b7426a`를 확인하고 중단된 검사를 이어서 완료했다. 검사 시작·종료의 `/version` 응답은 동일했다. 추가 배포나 Render 대시보드 조작은 없었다.

## 결과

**이 표는 그래프 없이 범용 앱 안내로 실행한 실험이다.** 앱 10과제와 설정 이동 20과제, 각각 2회로 총 60회다. 기존 README의 그래프 기반 설정 52회와 합쳐서 제품 전체 성공률로 표시하면 안 된다.

| 지표 | 이전 60회 | 재배포 후 60회 |
|---|---:|---:|
| 독립 기기 판정 + 제품 완료 확인 | 11/60 (18.3%) | **9/60 (15.0%)** |
| 범용 앱 10종 × 2회 완료 성공 | 5/20 | 5/20 |
| 그래프 없는 설정 이동 20종 × 2회 완료 성공 | 6/40 | 4/40 |
| 시행 중 목표 화면 도달 관찰 | 26/60 | 31/60 |
| 종료 시점 목표 화면 유지 | 별도 JSON 참고 | 29/60 |
| 거짓 완료 | 2/60 | **0/60** |
| 첫 동작 제안 시간 중앙값 | 4.87초 (45회) | 4.64초 (44회) |
| 첫 동작 제안 시간 p95 | 7.35초 | 6.24초 |
| 성공 시행의 완료 확인 시간 중앙값 | 14.94초 (11회) | 12.36초 (9회) |

완료율 개선은 확인되지 않았다. 거짓 완료는 이번 표본에서 관찰되지 않았지만, 이를 일반적인 거짓 완료 확률 0% 또는 정확도 100%로 해석하면 안 된다. 도착 관찰 수에는 잠시 도착했다가 다른 화면으로 이동한 시행도 포함한다. 종료 시점 유지 수는 별도로 기록했다.

첫 동작 제안 시간은 `AppTaskController` 시작부터 제안 콜백까지다. 사용자의 요청 입력부터 실제 오버레이가 그려지는 시간은 아니다. 제안이 없었던 16회는 속도 통계에서만 제외했고, 성공률 분모에는 모두 포함했다. 따라서 이 속도를 슬라이드의 ‘요청 입력 → 첫 유효 안내’에 대입하지 않는다. 첫 버튼 정답 여부도 이번 하네스가 별도로 측정하지 않아 정확도 수치를 만들지 않았다.

## 남은 문제

51회 실패 중 최종 상태는 직접 조작 요청(`needs_input`) 45회, 계획 중(`planning`) 2회, 화면 대기(`awaiting_screen`) 2회, 모델·계획 사용 불가(`unavailable`) 1회, 동작 제안(`proposed`) 1회였다. 종료 방식은 명시적 도움 요청 실패 35회, 시간 상한 실패 16회다. 이전 부분 시행은 도움 요청 후에도 75초를 기다렸으므로 종료 방식과 실패까지의 시간은 전후 직접 비교하지 않는다.

- 앱 과제는 20회 중 19회에서 목표 도착을 관찰했지만 5회만 완료 확인까지 통과했다. 스톱워치·타이머·Shorts·구독 등은 실제 화면 도착 이후 제품의 완료 확인이 이어지지 않았다. **도착 뒤 검증 경로가 우선 보완 대상**이다.
- 설정 이동은 40회 중 12회에서 목표 도착을 관찰했고 완료 확인은 4회였다. 다음 메뉴를 계획하지 못하거나 직접 조작을 요청하는 문제가 주로 남았다. 이 실험은 그래프를 사용하지 않았으므로 지원 그래프 경로의 성공률로 해석하지 않는다.
- 실제 Wi-Fi 시행의 Qwen 응답은 `plan_validation / reason_code=subgoals`로 거부됐다. 낮은 신뢰도나 형식 오류를 성공으로 바꾸지 않고 실패로 남겼다. 해결하려면 해당 실제 요청·응답을 추가 수집해 출력 계약과 완료 판정을 분리 재현해야 한다. 회귀 테스트 통과만으로 이 실기기 문제를 해결했다고 주장하지 않는다.

이번에는 배포된 동작을 측정했으며, 제품 코드나 신뢰도 기준을 변경하지 않았다. 테스트 도구에는 재개 번호·완료 표시·경과 시간과, 사람이 필요한 안정 상태 또는 모델 실패 상태에서 실패로 종료하는 처리를 보완했다. 성공하려면 독립 네이티브 목표 판정과 제품 완료 확인이 모두 필요하다는 기준은 유지했다. 승인은 스크립트가 대신했으며 사람 대상 사용성 실험은 아니다. 안전한 메뉴 이동만 허용하는 하네스 제약도 있어, 모델이 제안한 모든 동작을 실행하는 조건은 아니다.

## 검증과 정리

- 서버 전체 회귀 검사 **4,209개 통과, 1개 건너뜀**. 기존 사용자 작업 중인 `test_decision_robustness.py`, `test_decisions_comparison.py` 두 파일은 제외했다. 이 숫자는 실기기 성공률의 분모가 아니다.
- 관련 선행 회귀 검사 210개 통과. 전체 검사와 중복이므로 합산하지 않는다.
- 검사 APK 빌드와 임시 계정 정리 검사 통과. 계정 이름과 ID가 감사용 임시 계정인지 확인한 뒤 삭제했다.
- 글자 배율 1.3, 자동 밝기 모드 1, 원래 사용자 앱의 접근성 서비스 복원을 확인했다. 화면 유지 설정은 원래 값 7로 복원하고 USB 중계를 제거했다. 사용자 원래 앱의 데이터는 삭제하지 않았다.
- 캡처와 검사 충돌로 중단된 시행은 제외하고 같은 `(과제, 반복)`을 다시 실행했다. 최종 60개 조합이 정확히 한 번씩 존재함을 확인했다.
