# 블루투스 빈 목록 및 검색 갱신 안내

블루투스 화면에서 연결할 기기가 없거나 검색 목록이 바뀔 때 안내가 멈출 수 있는 문제를 수정했다.

## 원인

`renderGuide()`는 직접 진행 안내를 수신하면 최신 화면 검증보다 먼저 `manualSettingsHandoff=true`로 화면 관측을 중단했다. 응답 대기 중 검색 목록이 갱신돼 전체 화면 지문이 바뀌면 안내를 버리고 새 화면을 기다렸지만, 관측 중단 상태 때문에 새 안내를 받지 못할 수 있었다. 블루투스 연결 설명에도 기기가 표시되지 않을 때의 절차가 없었다.

실제 기기에서 설정 진입 직후에는 제목·스위치가 없는 로딩 관측도 확인했다. 이 관측을 ‘연결할 기기 없음’으로 간주하지 않는다. 로딩 후 제목과 실제 스위치 checked가 정상적으로 읽힌 것을 별도로 확인했다.

## 변경

- 실제 관측의 앱·접근성 창·화면 크기가 같고, 현재 작업에 승인된 독립적인 페이지 제목이 유지되면 기기 목록 변화가 읽기 전용 안내를 무효화하지 않는다. 목록 안의 기기/메뉴 이름, 다른 페이지·창·앱, 개인 입력은 이 예외로 통과하지 않는다.
- 화면 검증을 통과한 이후에만 직접 진행 안내를 표시하고 후속 화면 전송을 중단한다. 유효하지 않은 응답은 다음 관측을 막지 않는다.
- 직접 진행 안내는 자동 진행 표시와 하이라이트를 끄고, 서버 계약이 지원하는 ‘완료 확인’을 제공한다. 연결 성공을 자동 판정하지 않는다.
- 블루투스 안내: “연결할 기기가 보이지 않으면 기기의 전원과 페어링 모드를 켜고, 휴대폰 가까이에 둔 뒤 검색될 때까지 잠시 기다려주세요. 기기가 나타나면 직접 선택하고, 양쪽 기기의 연결 코드가 같은지 확인한 뒤 페어링하세요.”
- 설명은 공통 실행 계약과 앱 자산에 반영돼 기존 서버의 직접 진행 응답에서도 새 문구가 표시된다.

## 검증 및 한계

- Android 회귀 사례 4개에서 기존 안내 중단을 재현했다. 수정 후 관련 **179개 통과**, 전체 **582개 통과**, 실패·오류·건너뜀 0개.
- AI-Agent 전체 **393개 통과**. 관련 Backend **261개 통과**, 이후 실제 삼성 구조를 포함한 Bluetooth 검사 **7개 통과**.
- 실제 Samsung SM-N981N의 블루투스 화면에서 앱 접근성 관측과 독립 native 관측 모두 privacy=allowed, 제목과 checked 스위치 1개를 확인했다. 기기 식별 문구를 저장하지 않은 구조를 로컬 Backend에 재생해 직접 진행 안내와 이미 켜진 상태의 인식을 검증했다.
- 기기 전원·블루투스 스위치를 바꾸거나 페어링하지 않았다. 실제 앱에서 운영 서버를 거쳐 연결 작업 전체를 수행한 검사는 아니다. 안내의 동적 갱신·표시는 서비스 회귀 검사로 확인했다.
- 원본 화면·기기명·음성은 외부로 전송하지 않았다. 진단의 공개 `/version` 조회만 수행했다. 서버 재배포는 하지 않았다.
- 수정 APK를 데이터 유지 방식으로 설치하고, 설치 해시 일치와 기존 접근성 연결 복구를 확인했다.
