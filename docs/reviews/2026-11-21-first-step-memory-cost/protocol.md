# A 정책에서 첫 단계 기억과 호출 비용: 실행 전 프로토콜

CURRENT 정책 고정. 이전 통합 충돌 수정 8b480bb 기반. SM-N981N / Android 13.
두 기존 공개 설정 탐색 과제: settings_display, settings_notifications.

세 군: A 기억 끔, B 기존 정확 일치 기억, C 정확 일치 기억 + 평가에서만 첫 단계 회수 허용.
C의 목표 정규화는 꺼서 B와 동일한 exact 회수 규칙을 사용한다. 학습은 세 군 모두 기존 코드.
과제·비교군마다 학습 4회 + 동일 원래 목표 평가 3회 = 총 42회 (학습24, 평가18).
기억은 군별 별도 owner/store를 사용한다. 순서는 기존 회전/역전 방식을 사용하며 무작위가 아니다.
오류 주입 없이 정상 조건만 비교한다. 회기 예산 25초, 목표 도달 후 검증 대기 1.5초.

실험 옵션 C: 최초 동작 전 현재 관찰에 grounding된 recall을 최대 2초 기다린다.
후보가 없거나 실패/지연이면 원래 planner로 복귀한다. 기존 rejected/repeated 방어,
실행 직전 fresh-frame policy, 매 동작 사용자 승인, 네이티브 동작 검증은 유지한다.
완료 조건을 미리 만들거나 과제 정답을 주입하지 않는다. 회수된 동작은 과제 진행을 자동 인정하지 않는다.
기존 production 생성자와 운영 기본값은 바꾸지 않는다.

독립 UiAutomation 정답이 700ms 유지되어야 모의 사용자가 확인한다. 이전과 같은 정답 사용.
일차 지표: 평가군별 전체 모델 호출·보고된 입력/출력/생각 토큰·기억 출처 승인·목표 도달.
학습 비용은 별도 집계하고 초기 비용 회수 여부도 확인한다. 요청별 모델 오류·누락 usage를 보존한다.
실제 청구 금액을 확정하지 않고 원시 호출/토큰을 비교한다. 목표 실패를 분모에서 제거하지 않는다.
각 군 평가 6회뿐이며 일반화나 통계적 효과를 주장하지 않는다. 성공한 학습 기억을 인위적으로 보충하지 않는다.
후보가 충분히 학습되지 않았다면 그 자체를 제한으로 보고한다. 결과를 보고 이 일정에서 조건을 바꾸지 않는다.
