# 와이파이 켜기·끄기 실행

2026-11-07. `settings.wifi.enable` / `settings.wifi.disable`를 승인 실행 그래프에 연결했다.
두 요청은 화면 열기와 별개로 사용자의 시작·변경 확인, 실제 스위치 안내, 변경 후 검증을 수행한다.
`settings.wifi.connect`와 SSID 선택·비밀번호 입력은 실행 지원에 포함하지 않는다.

## 처리

1. 요청을 켜기/끄기로 확정하고 `SET-wifi-enable` / `SET-wifi-disable` 그래프를 선택한다.
2. 설정 → 연결/네트워크 및 인터넷 → Wi-Fi 경로를 안내한다. 보이는 Wi-Fi 메뉴는 직접 선택할 수 있다.
3. Wi-Fi/Internet의 네이티브 제목, 정확한 Wi-Fi 라벨 또는 전용 페이지의 유일한 master switch를 확인한다.
4. 변경 확인 후 사용자가 스위치를 직접 누른다. Wi-Fi를 끄는 확인에는 인터넷 연결이 끊길 수 있음을 알린다.
5. 같은 스위치의 `checked` 변경, 귀속 가능한 탭, 새 관측, `WifiManager.getWifiState()`의 안정 상태가 모두 일치해야 `CHANGED`로 판정한다.
6. 이미 원하는 상태면 다시 누르지 않고 `ALREADY_SET`으로 결과를 확인한다. 조작 이벤트 없이 원하는 상태를 관측한 경우에도 변경에 귀속시키지 않는다.

전환 중은 완료로 처리하지 않는다. 다른 스위치, 모바일 데이터, OCR, selected 플래그, 미지/누락 값,
예전 관측이나 잘못된 탭만으로 완료하지 않는다. 스위치와 시스템 상태가 다르면 추가 탭을 지시하지 않는다.
Jev의 판단 보류도 로컬 스위치 선택으로 덮어쓰지 않는다.

## Android 데이터

`ACCESS_WIFI_STATE` 일반 권한으로 Wi-Fi 어댑터 상태 0~4만 읽는다.
SSID, BSSID, MAC, 스캔 목록, 비밀번호, 위치 권한은 추가하지 않는다.
`extras.checked`는 실제 checkable 노드에서 얻은 boolean만 전달한다. 누락은 false로 바꾸지 않는다.
전송 필터는 `wifi_state`와 고정된 출처 문자열, checked boolean만 추가로 허용한다.

Wi-Fi 켜짐은 네트워크 연결이나 인터넷 접속 성공을 뜻하지 않는다.
Backend와 통신해야 하므로 Wi-Fi를 끈 뒤 모바일 데이터 등 통신 경로가 없으면 서버의 결과 확인이 지연되거나 실패할 수 있다.
통신 실패를 성공으로 표시하거나 Wi-Fi를 자동으로 되돌리지 않는다.

## 검증과 반영

합성 HTTP 실행, 잘못된 증거·다른 스위치·전환 상태·이미 원하는 상태, 네이티브 checked 수집과 전송 필터를 검사한다.
실제 단말의 메뉴 구조, Wi-Fi 라디오 변경 및 전환 후 네트워크 경로는 실기기 검증 대상이다.
Backend와 APK를 함께 갱신해야 한다. 실행 그래프는 1.0.0의 새 불변 버전이며 기존 초안 본문과 세션을 덮어쓰지 않는다.
이 변경으로 운영 배포나 기기 설치를 수행한 것은 아니다.
