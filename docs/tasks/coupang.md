# 쿠팡 71개 목표 실행 안내

카탈로그 v2.4.0은 기존 Agent1의 접근성 관측·강조 안내·사용자 확인·실행 이벤트·세션 복원과 Backend의 승인 graph 선택·버전 고정을 재사용한다. `commerce_execution.json`의 71개 작업을 Backend에서 graph로 생성한다. 공개 GitHub 경로 데이터는 필요하지 않다. 이 파일의 메뉴와 경로는 작성한 seed이며 실제 쿠팡 앱의 전 버전에서 검증한 경로는 아니다.

## 제공하는 범위

| 방식 | 목표 수 | 동작과 결과 |
| --- | ---: | --- |
| 화면 이동 | 8 | 장바구니·주문목록·찜·쿠폰함·카테고리·고객센터·최근 검색어·와우 혜택 화면으로 안내한다. 독립된 화면 제목을 확인하면 `OPENED / commerce_page_visible`로 기록한다. 같은 이름의 메뉴 버튼을 화면 도착으로 취급하지 않는다. |
| 확인 후 조작 | 1 | 상품 상세에서 장바구니 담기 대상을 강조한다. 화면·대상에 연결된 Backend 확인을 받은 뒤 안내하며, 실제 클릭과 이후 새 관측의 반영 문구가 연결돼야 기술 성공이다. |
| 직접 진행 안내 | 62 | 기능별 화면을 찾고 단계별로 무엇을 확인·선택·입력할지 안내한다. 상품·주문·후기·주소·결제수단의 특정 대상 선택, 검색어·개인정보 입력, 거래 확정은 사용자가 쿠팡 화면에서 진행한다. `UNVERIFIABLE`과 사용자 결과 응답을 구분한다. |

전체 목록과 위험도는 [목표 카탈로그](../goal-type-keyword-catalog.md)에 있다. 71개가 모두 자동 조작·기술 성공 검증을 제공한다는 뜻은 아니다. 실제 앱 버전별 전수 검증은 남아 있다.

## 화면 판단과 안내

1. 휴대폰은 현재 목표가 쿠팡일 때만 `commerce` 화면 정책을 사용한다. `com.coupang.mobile`과 검토된 런처만 허용한다. 홈·앱 서랍에서 현재 window에 보이는 쿠팡 아이콘이 하나면 기기 안에서 강조한다. 현재 페이지에 아이콘이 없으면 설정 앱 찾기와 같은 제한된 페이지 탐색으로 옆 페이지를 확인하고, 끝에서는 반대 방향도 탐색한다. 쿠팡 아이콘을 찾으면 넘기기를 멈추고 강조한다. 탐색을 마쳐도 찾지 못하거나 시작 위치가 다른 앱이면 쿠팡 열기 버튼을 제공한다. 홈 화면을 서버에 보내거나 설정 아이콘을 찾지 않으며, 사용자가 쿠팡을 열면 확인한 목표를 이어간다.
2. 상품명·주문번호·수령인·주소·카드·계좌·검색 기록·입력 내용은 전송하지 않는다. 허용한 메뉴 제목·역할·계층·기기 안 대상 좌표만 Backend에 전달한다. 로그인 화면의 제목은 관측할 수 있지만 입력 필드 내용은 제거한다.
3. Agent1이 실제 관측된 노드와 전달 graph의 허용된 경로를 묶어 후보를 만든다. Jev는 목표·목적지와 최소화된 메뉴 정보에서 다음 대상을 고른다. 외부 API에는 실제 노드 ID·패키지·좌표·사용자 원문을 보내지 않는다.
4. 후보 중복, 여러 window, 비활성·화면 밖 항목, 낮은 confidence, 잘못된 응답은 실행 대상으로 바꾸지 않는다. 같은 화면의 미실행 안내는 동일한 대상임을 재검증해 재사용하며, 반복 보류는 제한한다. 사용자가 목록을 스크롤하거나 특정 대상을 직접 선택하면 새 관측으로 이어간다.
5. 직접 진행 단계에 도착하면 `manual_handoff`로 화면 전송과 자동 안내를 멈춘다. 사용자는 기능별 설명을 보고 진행한 뒤 결과 확인을 누른다. 이 버튼의 요청에는 화면이 포함되지 않는다.

쿠팡에서는 Click의 자동 터치를 사용하지 않는다. 제공하는 조작은 사용자가 강조 표시를 보고 직접 누르는 안내다. OCR·스크린샷 경로는 이번 쿠팡 지원에 포함하지 않는다. 네이티브 접근성 정보가 부족하면 추측 대신 직접 이동하도록 안내한다.

## 장바구니 담기 결과 확인

상품 상세 화면의 제목 또는 서로 다른 상품 상세 조작 두 종류를 확인한 뒤 단일 장바구니 담기 버튼만 후보로 허용한다. 사용자가 현재 상품·옵션·수량을 확인하고 변경 확인에 응답해야 한다. 확인은 기존 Backend의 한 번만 쓸 수 있는 화면·대상·버전 계약을 따른다.

기술 성공에는 기존 가이드에 연결된 실제 클릭 이벤트, 클릭 이후의 새 observation ID·시각, 이전에 없던 허용된 반영 문구가 필요하다. 모델의 선택이나 confidence만으로 완료하지 않는다. 연결된 클릭 없이 반영 문구가 보이거나 결과 관측이 끝내 없으면 재클릭을 안내하지 않고 직접 확인으로 전환한다. 이는 모델이 상품명을 읽어 요청한 상품의 정확성을 검증했다는 뜻이 아니다. 상품 대상은 사용자가 확인한다.

## 정의와 배포

- `AI-Agent/goal_catalog/commerce_execution.json`: 기능별 목적 화면·경로·직접 진행 설명·반영 문구.
- `Backend/app/task_graphs/commerce.py`: 불변 `CP-* : 1.0.0` graph 생성. 기존 설정 graph의 본문·버전은 변경하지 않는다.
- `AI-Agent/src/ai_agent/runtime/commerce.py`: Agent1의 쿠팡 처리, 확인·관측 연결·완료 경계.
- `Backend/app/services/commerce_jev.py`: 기존 Jev 전송 설정을 이용한 화면 후보 선택.
- `AI-Agent/goal_catalog/screen_privacy_policy.json`: FE와 Backend가 적용하는 화면 정책.

Backend와 Android 앱을 함께 업데이트한다. 앱은 서버 OpenAPI의 지원 목표를 확인하므로 구버전 서버에 쿠팡 실행을 보내지 않는다. 새 Backend는 기존 카탈로그 버전의 설정 목표를 계속 허용하며, 쿠팡 목표는 2.4.0을 요구한다. 서버 시작은 기존 graph를 변경하지 않고 쿠팡 release만 새로 등록한다. 원격 배포는 별도다.

## 확인 방법

Backend 디렉터리에서 다음을 실행한다. 기본 명령은 외부 모델을 호출하지 않는다.

```powershell
python -X utf8 scripts/check_coupang_flow.py
python -X utf8 scripts/check_coupang_flow.py --env-file .env --live
python -X utf8 scripts/agent2.py audit
```

`--live`만 기존 Jev 설정으로 가상의 메뉴 선택 3회를 호출한다. 실제 사용자·계정·기기를 사용하지 않으며 결과의 `source_kind=synthetic`, `device_execution=NOT_RUN`을 유지한다. 이 연결 점검은 실제 쿠팡 앱의 성공률이 아니다. `audit`의 현재 기대값은 승인·선택 가능 목표 181개와 빈 누락·예상 밖 목표 목록이다. 기존 운영 DB를 사용한다면 감사 명령은 읽기만 수행한다.

실기기 검수에서는 앱 버전·언어·시작 화면을 고정하고, 각 기능의 목적 화면·대상 선택·직접 진행 설명·로그인 경계·취소·화면 변경·중복 대상·결과 미확인을 확인해야 한다. 메뉴 이름이 바뀌면 유한한 정책과 graph를 함께 검토해 새 release로 반영한다.
