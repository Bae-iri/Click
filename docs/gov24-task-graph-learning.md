# 정부24 작업 그래프 생성과 AI-Agent2 경로 개선

주민등록등본 발급 안내 화면까지의 실제 공개 메뉴 이동에서 상태·전이 그래프를 만든다.
`주민등록등본 발급해줘`, `주민등록 등본 발급`도 지원 범위를 설명한 뒤 같은 화면 안내로 연결한다.
생성 그래프의 완료는 `resident_service_visible`이며 신청서 입력·인증·발급 제출을 뜻하지 않는다.
다른 민원은 해당 공개 화면의 의미·완료 조건을 등록하고 실제 관측으로 검증한 뒤 확장한다.

## 동작

1. 현재 공개 화면과 실제 사용자 탭의 guide/observation/node/time 연결을 기록한다.
2. 안내 종료 뒤 응답의 background 작업으로 기존 Agent2 별도 프로세스를 호출한다.
   같은 작업자가 기본 60초 간격으로 누락된 정부24 세션도 재처리한다.
3. 현재 동의 이후의 연속된 관측·서버 코드·정책·유효기간을 확인한다.
4. 각 화면 변화가 실제 성공한 메뉴 이동으로 연결되고 등본 발급 안내 화면 도착이 검증된 경우만
   `gov24-task-graph.v1` 상태·전이 본문을 `graph_proposals`에 암호화 저장한다.
5. 다음 안내에서는 현재 보이는 고유 메뉴와 출발 화면 signature에 맞는 검증된 그래프를 후보로 사용한다.
   기존 성공률 정책으로 최소 3회 시도·70% 성공률을 충족한 고유 후보를 고른다.
   성공률·시도 수가 같으면 선택을 보류하며 미확인 결과도 분모에 포함한다.

`selection_policy=ai2_gov24_task_graph`, `selected_graph_hash`가 실제 선택 이벤트에 남는다.
증거 부족 시 `NEEDS_DATA`로 보류하고 기존 공개 메뉴 안내를 유지한다. 모델이 새 화면·좌표를 추측하지 않는다.
생성 그래프는 현재 화면에 없는 메뉴를 실행시키거나 인증·신청서 경계를 넘는 권한이 없다.
후보마다 개발자 승인을 요구하지 않는다. 생성된 경로와 현재 화면 검증은 분리한다.

## 동의·보존

기존 `model_training` 동의와 7일 원천 이벤트 보존기간을 따른다.
동의 철회·새 동의·회원 삭제·원천 만료 시 receipt와 생성 그래프도 삭제·제외된다.
prefix가 빠졌거나 원천 payload가 바뀌면 후보로 재사용하지 않는다.
그래프에는 허용된 메뉴의 의미 ID와 화면 signature만 남기며, 개인정보·원문 화면·좌표·입력 내용은 포함하지 않는다.

별도 DB 스키마 변경 없이 기존 graph proposal/receipt 테이블을 사용한다.
공유 작업자는 `CLICK_AI2_BROWSE_GRAPH_ENABLED=1`에서 동작하고,
정부24 실행은 `CLICK_GOV24_GUIDE_ENABLED=1`과 앱의 `gov24_civil` 기능 선언이 필요하다.

## 조회

서버와 같은 DB·암호화 키를 사용하는 환경에서 실행한다.

```text
python scripts/agent2.py learn-gov24 --limit 100
python scripts/agent2.py list-gov24-graphs
python scripts/agent2_monitor.py --target gov24 --env-file <서버 환경 파일>
```

목록에는 작업 ID·그래프 hash·상태/전이 수·완료 범위만 출력한다.
모니터의 `검증된 공개 작업 그래프`와 `AI2 작업 그래프 선택`으로 생성과 실제 사용을 구분한다.
자동 테스트는 합성 HTTP 관측·별도 worker 프로세스와 공유 DB를 검증한다.
아버지 폰에서 새로 관측한 경로가 생성됐는지는 서버 반영 후 실제 테스트와 모니터로 확인해야 한다.
