# CLICK 실패 분류와 복구 계약

구현일: 2026-11-10

## 원칙

화면 환경은 작업 그래프와 독립적으로 관측한다. 처리 순서는 **환경 관측 → 목표와의 경로 적합성 → 대상 선택 → 실행 → 결과 검증**이다. 작업 그래프의 `S0_UNKNOWN`은 그래프 상태를 결정하지 못했다는 뜻이며, 홈 화면·다른 앱·설정 첫 페이지라는 뜻이 아니다.

환경 근거는 실제 접근성 루트의 패키지, 독립 제목, 구조 리소스, 일치하는 창 이벤트, 창 종류, 키보드, 잠금·접근성 연결이다. 설정 앱이 열려 있다는 사실만으로 설정 첫 페이지로 분류하지 않는다. VPN처럼 하위 화면에서 시작하거나 제목이 단순히 ‘설정’이어도 네이티브 하위 Activity 근거를 사용한다. 런처 패키지만 알면 `LAUNCHER`이며, 홈·앱 서랍·최근 앱은 구조가 확인된 경우에만 구별한다.

화면 환경은 작업 성공의 근거가 아니다. 같은 페이지, 같은 대상, 실제 설정값 변화는 별도 계약으로 유지한다. 블루투스 전원 ON과 기기 연결 성공도 다르다. 관측 불가나 모델의 높은 확신을 성공으로 바꾸지 않는다.

| 대상 없음·모호함 / `TARGET_NOT_FOUND`, `TARGET_AMBIGUOUS`, `STATE_UNKNOWN` | 근거가 부족한 좌표를 만들지 않는다. 직접 원하는 항목으로 이동하도록 안내한다. | 새 대상·페이지 근거 확보 |
| 모델 보류 / `LOW_CONFIDENCE`, `MODEL_ABSTAINED` | 모델 보류와 화면 미수집을 구분한다. 실제 항목이 보이면 스크롤로 밀어내지 않고 직접 선택 도움을 제공한다. | 사용자 이동 뒤 새 관측 |

| 실행 거절·예산 소진 / `ACTION_DISPATCH_FAILED`, `ACTION_BUDGET_EXHAUSTED` | 자동 실행을 중단하고 직접 조작으로 전환한다. 환경 복귀로 실행·탐색 예산을 돌려주지 않는다. | 직접 조작 뒤 결과 확인 또는 명시적 재시도 |
| 변경 결과 불명 / `ACTION_RESULT_UNOBSERVABLE`, `ACTION_EVENT_MISSING` | 같은 조작을 다시 실행하지 않고 결과 확인을 제안한다. 사용자 확인과 기술적 성공을 구분한다. | 작업별 성공 증거 또는 사용자 결과 응답 |
| 이미 설정됨·한계 / `ALREADY_SET`, `LIMIT_REACHED` | 기존 설정값·컨트롤 범위 계약에 따라 결과로 처리한다. 더 조절하려고 반복하지 않는다. | 결과 확인·종료 |
| 사용자 승인 거절 / `USER_DECLINED` | 정상적인 사용자 선택이다. `CANCELLED`로 종료하며 사과·실패 그림·자동 재시도·실패 집계를 하지 않는다. 실행 대기·승인·하이라이트를 지운다. | ‘끝내기’ 후 다음 작업을 새로 확인 |
| 결과가 불편함 / `needs_help` | 조작 승인 거절과 다른 응답이다. `WAITING_ADJUSTMENT`에서 불편한 점과 조절 방향을 확인한다. | 새 조절 방향을 사용자가 확인 |
| 민감 정보 / `SENSITIVE_INPUT`, `SENSITIVE_SCREEN` | 보호 경계를 우선한다. 입력·사진·계정 내용을 내보내지 않고 직접 진행하도록 한다. 일반적인 탐색 실패 사과를 붙이지 않는다. | 보호 구간 종료 또는 명시적 허용 절차 |
| 화면 처리 오류 / `VISION_MASKING_FAILED`, `VISION_CAPTURE_FAILED`, `VISION_OCR_FAILED` | 실제 `vision_failure` 코드를 유지한다. 같은 요청에 `rejected`가 있어도 사용자 거절로 분류하지 않는다. 마스킹 실패는 분석 차단, 캡처·OCR 오류는 기존 제한된 복구 절차를 따른다. | 보호 확인 또는 새 화면에서 제한된 재시도 |
| 오래된 응답·작업 교체 / `STALE_RESPONSE`, `TASK_REPLACED` | generation·요청 순서·세션·episode로 오래된 콜백과 조작을 버린다. 환경 이탈 중 도착한 기존 하이라이트를 다시 표시하지 않는다. | 현재 작업에 해당하는 새 응답 |
| 앱·서버 계약 불일치 / `CONTRACT_MISMATCH` | 기존 버전·스키마 검증에서 중단한다. 새 환경 정책은 그 검증을 우회하지 않는다. | 호환되는 앱·서버 배포 |
| 등록된 외부 선택기 / `MANUAL_EXTERNAL_CHOICE` | 배경화면·벨소리 등 작업별 등록 앱만 수동 선택으로 연결한다. 캘린더 같은 임의 앱은 예외가 아니다. | 완료 확인을 통한 결과 응답 |

분류표는 공통 실패 의미와 복구 경로를 정의한다. 화면 탐색·동의·성공 검증의 구체적인 제한은 기존 실행 계약을 계속 사용한다. 정책 항목이 있다는 이유로 자동 조작 권한이 생기지 않는다.

## 상태·비동기 처리

- 환경 차단은 `TaskExecutionController`의 RECOVERY로 진입한다. 목표·episode·누적 예산을 유지한다. 정상 화면 관측은 OBSERVING으로 복귀시킨다.
- 사용자의 명시적 일시정지, 수동 결과 대기, 결과·추가 조정 화면은 환경 이벤트가 임의로 재시작하지 않는다.
- 일시정지한 상태에서 다른 앱에 있다가 ‘재개’를 누르면 먼저 복귀를 안내한다. 안전한 작업 화면을 확인한 뒤 서버의 `resume_task`를 진행한다.
- 요청 처리 중 화면이 바뀌면 세션 버전 응답은 반영하되 이전 화면의 하이라이트·승인·자동 실행은 복원하지 않는다. 최신 화면을 모아서 다음 관측을 진행한다.
- 물리 뒤로가기 뒤 캘린더 문구만 바뀌었다면 작업 복귀로 인정하지 않는다. 복귀하지 못해도 홈 이동 버튼을 추가하지 않는다. 기존 설정 열기를 유지하며 실제 설정 화면을 새로 관측한다.
- 기존 설정 페이지 이동 처리도 유지한다. 정상 경로에서 사용자가 다음 단계로 직접 이동하면 새 화면에서 이어간다. 건너뛴 클릭을 성공으로 만들지 않는다.

## 정상 시스템 화면 예외

밝기 설정에서 열리는 AOSP SystemUI 조절창은 일반 알림 패널과 다르다. 공통 정책에 등록된 패키지·컨테이너 ID·슬라이더 ID·부모 관계·단일 컨트롤·유효한 수치 범위를 모두 확인한 경우에만 `CONTROL_SURFACE`다. 현재 허용 작업은 `brightness`다.

이 예외는 네이티브 슬라이더와 그 조상만 내보낸다. 같은 SystemUI 창의 알림 내용은 제외한다. 텍스트가 없는 슬라이더도 원본 접근성 부모 구조로 검증하며, 정규화된 노드나 모델 답변만으로 예외를 만들지 않는다. 이미 확인한 조절 방향을 재사용하지만 SystemUI 자동 터치 범위를 늘리지 않는다.

## 공통 계약과 수정 위치

- `AI-Agent/goal_catalog/screen_environment_policy.json`: 환경·복구 코드, 유한 패키지·구조 목록. Android 빌드 시 동일 파일에서 코드를 생성한다.
- `AI-Agent/tests/fixtures/screen_environment_cases.json`: Android와 서버가 함께 실행하는 환경 판정 사례.
- Android `data/snapshot/ScreenEnvironment`, `NativeWindowContext`, `NativeControlSurface`: 서버 전송 전 로컬 환경 판정.
- Android `service/accessibility/NativeWindowContextReader`: 일치하는 실제 창 이벤트·입력기 근거 수집.
- Android `service/overlay/ClickOverlayService`, `TaskExecutionController`, `SettingsPageNavigation`: 복귀 UI, 생명주기, 응답·동작 무효화.
- `AI-Agent/src/ai_agent/runtime/environment.py`: 모델 호출 전 독립 환경 판정과 경로 적합성.
- `AI-Agent/src/ai_agent/runtime/screen_privacy.py`, Android `SettingsScreenPrivacy`, Backend `screen_jev.py`: 네트워크 경계의 유한 데이터 검증.
- Backend `schemas/agent_turn.py`, `clients/runtime_agent.py`: 유한 `window_context` 전달. 임의 Activity 이름·화면 제목을 이 필드에 넣을 수 없다.

서버 소스 해시는 `AI-Agent/goal_catalog` 전체를 포함하므로 이 환경 정책도 배포 동일성 확인 대상이다. 앱·서버 변경을 함께 반영해야 전체 계약이 적용된다. 기존 APK나 운영 서버가 자동으로 바뀌는 것은 아니다.

## 검증 범위

합성 화면과 기존 네이티브 고정 fixture로 판정, 잘못된 앱/페이지 복귀, 정상 선택창 유지, 민감 정보 차단, 오래된 응답, 예산 보존, 블루투스 빈 목록, 밝기 컨트롤을 검사한다. 실제 제조사 화면 전체를 인식한다고 보장하는 검사는 아니다. 알 수 없는 패키지·OEM 컨트롤은 안전한 수동 안내로 남겨 두고 새 등록과 검증 사례를 추가해야 한다.

이번 작업의 최종 검사 수·APK 해시·배포 여부는 `docs/reviews/2026-11-10-environment-recovery.md`(저장소 정리로 삭제됨, 커밋 `44d73f48` 이전 git 기록 참고)와 해당 evidence JSON에 기록한다. 기기 설치·실기기 검증은 사용자 요청에 따라 나중에 진행한다.


## 공통 실행 상태 계약: 2026-11-11

`AI-Agent/goal_catalog/execution_state_contract.json`이 상태·단계·에피소드 교체 조건의 공통 원본이다. Python runtime이 직접 읽고 Android 빌드는 같은 파일에서 `ExecutionStateData`를 생성한다. 준비·시작·관측·승인·정지·재개·취소·결과·추가 조절 및 세션 조회에 `execution-state.v1`을 적용한다.

- 요청 `execution_context`: 세션, 에피소드, 기대 버전, 요청 ID, 판단에 사용한 관측 ID를 묶는다. API와 AI runtime은 자기 입력과 일치하는지 확인한 뒤 처리한다. runtime 부모는 반환된 응답·checkpoint의 세션, 요청, graph 작업 범위를 확인한 뒤에만 저장한다.
- 응답 `execution_state`: 위 식별자와 확정 목표, graph hash, 단계, 안내 ID, pending attempt, 검증 attempt를 함께 반환한다. 응답은 저장한 턴의 목표·graph·에피소드를 사용한다. 뒤이은 DB 조회에서 더 최신 작업을 섞지 않는다.
- 세션 조회의 `source=snapshot`은 상태 확인 전용이다. 안내 조작을 포함할 수 없으며 native 실행 권한을 만들지 않는다. 이전 버전 응답과 승인되지 않은 에피소드 변경은 앱이 거절한다.
- Android `TaskExecutionController`가 세션·버전·에피소드·확정 목표·시작 여부·서버 상태·로컬 실행 단계·요청 token을 소유한다. `ClickOverlayService`는 제어 이벤트를 전달하고 관측 증거와 UI를 연결하며, 이 작업 필드의 별도 복사본을 두지 않는다. 준비 후보와 화면 표시 데이터는 확정 작업 상태와 구분한다.
- native 조작 직전에 현재 서버 상태의 안내·attempt·판단 기준 관측을 검사하고, 별도로 새 네이티브 화면에서 대상이 그대로인지 확인한다. 판단 기준 관측과 실행 직전 관측은 서로 다른 샘플일 수 있으며 기기 journal에 두 ID의 연결을 기록한다. 새 샘플의 ID를 이전 ID로 덮어쓰지 않는다.
- 검증 대기인 attempt는 `VERIFYING`으로 표시하여 같은 안내가 남아 있어도 자동 조작을 다시 시작하지 않는다. 일시정지·복구·수동 대기 같은 로컬 차단은 서버 상태 동기화만으로 해제되지 않는다.
- 계약 불일치는 네트워크 재시도로 분류하지 않는다. 안내·승인·자동 실행을 제거하고 작업을 중단하며 앱·서버 업데이트를 안내한다. 재연결 outbox에도 원래 요청과 같은 검사를 적용한다.

새 앱은 호환되는 실행 계약을 광고하는 서버만 사용하고 `X-Click-Execution-State: execution-state.v1`을 보낸다. 서버는 이 헤더를 사용한 요청에서 context 누락·알 수 없는 계약을 거절한다. Render 설정에는 `CLICK_REQUIRE_EXECUTION_CONTEXT=1`을 추가하여 헤더를 생략한 구형 실행 요청도 거절하도록 했다. 로컬 회귀에서 기존 소비자를 검사할 때에는 환경변수 기본값 0을 사용한다. 읽기 전용 세션 조회와 사용자 중단용 `/sessions/{id}/cancel`은 복구·중단 경로로 유지한다.

서버 코드·이 환경변수·새 APK를 함께 적용해야 운영 흐름에 반영된다. 운영 서버 배포는 사용자가 직접 수행하기로 했으며, 로컬 코드·자동 테스트·기기 검증과 구분해 기록한다. 기기 journal 검사는 별도 암호화 테스트 저장소와 합성 이벤트를 사용하며 서버에 전송하지 않는다. 이 검사를 실제 목표의 기술적 완료나 사용자 만족으로 기록하지 않는다.

### 설치 전 배포 일치 확인

새 계약이 없는 서버에 새 APK를 먼저 설치하면 작업이 시작되지 않는다. 이 경우는 `SERVER_UPGRADE_REQUIRED`이며 작업 기록 손상으로 표시하지 않는다. 세션 복원과 outbox 재전송도 서버 기능을 먼저 확인한다. 미지원 기능 응답은 캐시에 남기지 않으므로 서버 배포 후 명시적 재시도가 새 계약을 다시 읽는다.

새 APK에는 실제 `BuildConfig.CLICK_API_BASE_URL`과 같은 주소를 `assets/click_release_identity.json`에 담는다. 설치 도구 `Frontend/scripts/install_verified_debug.py`는 이 주소가 검사하는 서버와 일치하고 요청·응답·세션 조회 모두 같은 실행 계약을 제공하는지 확인한 뒤에만 `adb install -r`을 수행한다. `--check-only`로 기기를 변경하지 않고 검사할 수 있다. 다른 Render 서비스의 계약을 읽어 현재 APK의 설치를 승인할 수 없다.

운영 적용 순서는 현재 소스의 서버 배포 → 실제 앱 대상 URL의 계약 확인 → 검증된 APK 설치다. 서버 배포 전에는 직전 호환 앱을 사용한다. 2026-11-11 설치 순서 오류와 복원 결과는 `docs/reviews/2026-11-11-rollout-compatibility.json`(저장소 정리로 삭제됨, 커밋 `44d73f48` 이전 git 기록 참고)에 별도로 남긴다. 기존 통합 검증 기록은 해당 시점의 결과이며 현재 설치 버전은 최신 복원 기록을 확인한다.


### 순차 작업 플로팅 UI

플로팅 UI에는 대기 요청 목록·개수·번호를 표시하지 않는다. 처음 확인 화면에서는 현재 작업과 뒤따르는 작업을 자연스러운 한 문장으로 설명한다. 예: “글자 크기를 높이고 디스플레이 밝기를 높이겠습니다.” 내부 요청 순서와 서버 저장은 유지한다.

첫 작업의 완료 화면은 사용자가 ‘끝내기’를 누를 때까지 유지한다. 이 버튼은 현재 작업의 종료를 처리하고, 다음 작업은 별도 준비·확인을 거친다. 밝기 작업이라면 “디스플레이 밝기를 높일까요?”를 표시하며 사용자가 ‘안내 시작하기’를 눌러야 시작한다. 이전 작업의 승인·에피소드·관측을 재사용하지 않는다.

진행 중 ‘끝내기’는 현재 안내만 중단하고 다음 확인 화면으로 연결한다. 검증되지 않은 변경을 성공으로 기록하지 않는다. 음성 ‘멈춰’와 전체 클릭 종료는 기존 전체 중단 동작을 유지한다. 자동 실패 후에도 후속 작업은 사용자의 끝내기 동작을 기다린다. 중복 누름과 늦은 완료 응답은 다음 작업을 두 번 시작하지 않는다.

해당 변경의 검사·렌더링·APK·기기 적용 여부는 `docs/reviews/2026-11-11-sequential-task-ui.json`(저장소 정리로 삭제됨, 커밋 `44d73f48` 이전 git 기록 참고)을 확인한다.


### 사용자 선택과 실패 분리: 2026-11-11

‘밝기를 높일까요?’의 ‘아니요’는 `USER_CHOICE / USER_DECLINED`이며 기술적 실패도 성공도 아니다. `task-termination.v1` 레코드에는 category, code, scope, message, retryable, counts_as_failure를 기록한다. `CANCELLED + cancelled / observe_only`로 응답하고 대상 좌표·proposed_action·사용자 조작 요구를 제거한다. 앱의 일반 BLOCKED 화면보다 먼저 이 정상 종료를 처리한다. 기본 안내는 ‘밝기를 바꾸지 않고 안내를 마칠게요.’이며, 이전 변경이 검증된 추가 조절 거절은 ‘추가로 조절하지 않고 안내를 마칠게요.’로 구분한다. 이전 기술적 변경 증거를 지우거나 거절을 성공으로 만들지 않는다.

AI runtime은 승인 거절을 화면 신선도·모델·검증·실패 예산 처리보다 먼저 처리한다. Backend는 runtime 결과와 무관하게 거절의 실행 권한을 다시 제거하고, 저장된 checkpoint와 SafetyConfirmation도 제거한다. 동일 요청 재전송은 같은 정상 종료 응답을 반환하며 새 승인은 거절한다. 세션 조회의 task_outcome에도 종료 사유를 유지하여 연결 복구 후 실패 화면으로 바뀌지 않게 한다.

일반 승인 거절과 화면 분석 동의 거절은 scope만 다르고 모두 정상 선택이다. `vision_failure`가 동반된 기기 캡처·OCR·마스킹 오류는 별도 기술 경로를 유지한다. 작업 결과 질문의 ‘아니요’는 `needs_help → WAITING_ADJUSTMENT`이며 승인 거절로 바꾸지 않는다.

정상 거절 화면에는 사과·실패 캐릭터·성공 표시·재시도 버튼이 없다. 사용자가 ‘끝내기’를 누르면 현재 요청만 취소하고 다음 작업 준비 질문을 보여 준다. 새 목표는 별도 확인이 필요하다. 중복 끝내기는 한 번만 처리한다. 음성 전체 중단은 기존 전체 중단 의미를 유지한다.

새 앱은 큐의 `/cancel`과 `reason=USER_DECLINED|USER_ABORTED`를 사용한다. 기존 앱이 `/fail`로 USER_ABORTED를 보내도 결과는 CANCELLED다. 공개 응답은 termination_reason, counts_as_failure=false, failure_code=null로 구별한다. 기존 DB의 failure_code 열은 정상 취소 사유의 내부 저장에도 재사용하므로 원시 DB 집계는 반드시 status=FAILED를 기준으로 해야 한다. DB 스키마 변경은 없다.

원인을 알 수 없는 중단과 연결·계약 오류에는 ‘찾지 못했다’는 사과를 자동으로 붙이지 않는다. 대상 탐색 오류를 명시적으로 처리하는 recoveryApology 경로는 유지한다. 이 변경은 모든 오류가 클릭의 책임인지 자동 판단하는 기능을 추가하지 않는다. 사용자의 의사·환경 문제·보호 차단·결과 불명·실제 처리 오류는 서로 다른 사실로 기록한다.

검증 수와 APK 및 운영 적용 여부는 `docs/reviews/2026-11-11-user-declined.json`(저장소 정리로 삭제됨, 커밋 `44d73f48` 이전 git 기록 참고)에 기록한다. Render 배포와 새 앱 설치 전에는 기기에 반영된 것으로 간주하지 않는다.


### 클릭 앱 재진입 시 플로팅 종료: 2026-11-11

클릭 앱의 Activity가 다시 활성화되면 외부 화면용 플로팅 안내를 종료한다. HomeActivity뿐 아니라 메뉴·보관함·로그인·도움말 등 앱 진입 경로에 같은 규칙을 적용한다. Application에 등록한 AppOverlayLifecycle의 onActivityResumed가 단일 종료 신호를 전달한다. 플로팅 창은 Activity가 아니므로, 클릭과 같은 패키지에서 발생한 접근성 이벤트만으로 종료하지 않는다. Android 런처로 나가는 동작도 이 신호를 발생시키지 않는다.

기존 HomeActivity.onResume의 COLLAPSE 방송은 제거한다. 접힌 아이콘만 남기는 대신 기존 shutdownClick 경로에서 안내·확인·피드백 창, 음성, 승인·조작·재관측 대기를 즉시 정리하고 플로팅을 숨긴다. 서버 큐 정리는 기존 취소 경로로 보내며, 네트워크와 무관하게 최대 5초 뒤 서비스를 정리한다. 종료된 generation의 응답과 예약된 입력 패널 열기 작업은 안내를 다시 띄울 수 없다. 종료 처리 중 새 서비스 명령도 실행하지 않는다.

이번 변경의 앱 빌드·검사 수·기기 적용 여부는 `docs/reviews/2026-11-11-floating-app-entry.json`(저장소 정리로 삭제됨, 커밋 `44d73f48` 이전 git 기록 참고)에 기록한다.


### 동작하지 않는 복구 버튼 제거: 2026-11-11

‘돌아가기/뒤로가기 → 홈으로 이동’ 플로팅 복구 UI와 시스템 내비게이션 하이라이트를 제거했다. 작업에 필요한 기존 ‘설정 열기’ 하나로 실제 Settings.ACTION_SETTINGS를 실행한다. 버튼 클릭을 이동 성공으로 취급하지 않고 설정 패키지를 새로 관측한다. 실행 불가·이동 미확인·서버 처리 중·같은 화면의 문구 변화·중복 누름·작업 교체를 별도로 검증한다. 클릭 전에 버튼만 비활성화하여 무응답 상태로 남기지 않는다.
