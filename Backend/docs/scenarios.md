# 기능별 처리 시나리오

현재 HTTP 필드·상태는 API 명세를 따른다. 아래 최종 인수 기준에는 아직 구현되지 않은 보강 항목도 포함한다.

| ID / 기능 | 정상 흐름 | 예외 흐름 | 최종 인수 기준 |
|---|---|---|---|
| SC01 / F04,F06 | 최초 목표·화면 → 목표 분류 → 현재 화면의 안내 반환 | 목표 없음·관찰 없음·좌표 오류 → 요청 거절. 미지원·모호한 목표 → 안전한 설명·재질문 | 지원 task별 fixture에서 유효한 guide, 모호한 요청에서 임의 대상 실행 없음 |
| SC02 / F05,F07 | 동일 session의 새 request → 사용자 행동과 새 화면 비교 → 다음 안내 | 잘못된 화면 → 재계획, 변화 없음 → 제한된 재시도 | 이벤트만으로 완료하지 않고 관찰된 변화로 완료 |
| SC03 / F08 | confirmation 표시 → 승인 + fresh tree → 조건 재검증 → 안내 | 거절·만료·다른 guide 승인·변경된 화면 → 해당 승인 사용 거절 | 승인 대상·소유자·유효시간 검증, 승인 재사용 없음 |
| SC04 / F05 | 응답 유실 → 동일 ID·본문 재전송 → 기존 응답 | ID 같고 본문 다름 → 409, 다른 사용자 → 접근 거절 | 중복 처리 없음, 멀티프로세스와 동시 요청에서도 동일 |
| SC05 / F09 | tree로 대상 못 찾음 → 동의·마스킹된 OCR/vision → 재매칭 | 동의 없음·마스킹 실패·provider 장애 → 전송 차단 또는 안전한 fallback | 외부 호출 spy로 동의·마스킹 실패 시 호출 0회 |
| SC06 / F02,F03 | 사용자 생성 → 개인화 동의 → 이벤트 → 프로필·안내 조정 | 미동의·철회 후 이벤트 → 403, 타인 사용자 ID → 접근 거절 | 본인만 접근, 동의 철회 후 캐시를 포함해 개인화 미적용 |
| SC07 / F02,F09 | 본인 삭제 → 프로필·동의·이벤트·세션·캐시 제거 | 타인 삭제 → 거절, 저장 실패 → 전체 rollback | 잔여 개인정보 없음; 현재 DB 4개 테이블 외 캐시 삭제는 미구현 |
| SC08 / F05,F10 | 본인 세션 조회·취소·이력 확인 | 없는 세션·타인 세션·종료 후 추가 turn → 규약에 따라 거절 | 재시작 후 복구, 취소 후 후속 처리 없음; API 구현 예정 |
| SC09 / F01,F12 | 서버 실행 → health 200, DB 준비 → ready 200 | DB 연결 불가·테이블 누락 → ready 503, health 200 | 오류에 접속 문자열·비밀값 노출 없음 |

## 기존 시범 자산 활용

글자 크기 증가 시나리오는 화면 변화 검증과 회귀 테스트의 참고 자산이다. 처음 화면에서 디스플레이 메뉴를 안내하고, 글자 크기 컨트롤에 도달한 후 이전 값보다 증가했음을 관찰해야 완료한다. 구현된 세부 흐름은 [기존 task 문서](../../docs/tasks/font-size-increase.md)를 따른다.

쿠팡·정부24는 실제 지원할 task와 민감 단계 경계를 확정한 뒤 같은 SC01~SC05 형식으로 fixture를 추가한다. 화면·task 정보가 없는 상황에서 임의의 성공 경로를 만들지 않는다.
