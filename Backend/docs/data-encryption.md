# 사용자 데이터의 암호화 저장

## 무엇을 보호하는가

비밀번호는 기존 scrypt 단방향 해시를 유지합니다. 로그인 토큰은 해시만 저장합니다. 서버가 복호화할 필요가 없는 비밀번호를 복호화 가능한 암호문으로 바꾸지 않습니다.

이름·전화번호·이메일·대기 중 요청 내용은 저장 전에 인증된 암호문으로 바뀝니다. 세션의 목표·기기 정보·진행/복구 정보·결과 이력, 확인창 명령, 체크포인트, 응답 캐시, 실행 이벤트, AI2 분석 결과와 검수/제안 상세 JSON도 암호화합니다. 카카오 사용자 번호는 비밀 키 기반 검색 해시로만 보관합니다.

DB를 직접 조회하면 해당 내용은 암호문입니다. 서버는 정상적인 API 처리와 AI2 분석 때만 메모리에서 복호화합니다. 화면 원문이나 인증 정보를 추가 수집하는 변경은 없습니다.

외래 키 연결에 필요한 불투명 ID, 상태·작업 코드, 시각·만료일, 동의 여부, 공개 그래프 정의, 비밀번호/토큰의 단방향 해시는 검색 가능한 구조 정보로 유지합니다. DB 전체 파일·백업·네트워크 암호화는 별도 인프라 설정입니다. HTTPS 전송과 이 문서의 필드 암호화를 구분합니다.

## 키 설정

영구 DB에는 두 개의 독립된 비밀이 필요합니다.

- `DATA_ENCRYPTION_KEYS`: Fernet 키. 쉼표로 여러 키를 넣으면 첫 키로 쓰고 나머지 키로도 읽습니다.
- `DATA_LOOKUP_KEY`: 전화번호/이메일/카카오 검색에 사용하는 별도의 32바이트 URL-safe base64 키. 암호화 키 교체 중에도 유지합니다.

각 키는 독립적으로 생성해 Render의 비밀 환경변수나 운영 비밀 저장소에 넣습니다. 키를 Git, 채팅, 로그, 앱 APK나 DB에 넣지 않습니다. 실제 키를 담은 파일을 자동 생성하거나 커밋하지 않습니다. 로컬 `.env`도 Git 제외 대상입니다.

비밀 관리 도구가 없다면 신뢰할 수 있는 운영자 터미널에서 다음 명령을 각각 실행해 두 키를 생성할 수 있습니다. 출력은 비밀이므로 화면 공유·로그 수집을 피하고 즉시 운영 비밀 저장소로 옮깁니다.

```sh
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

키가 없거나 잘못됐으면 영구 저장소 시작을 거부합니다. DB의 비밀이 아닌 확인용 암호문과 검색 키 확인값으로, 다른 키를 실수로 설정한 경우도 사용자 요청 전에 막습니다. 읽을 수 없는 암호문이나 평문을 조용히 원문으로 반환하는 우회는 없습니다.

기본 인메모리 SQLite만 임시 키를 사용합니다. 테스트와 폐기하는 검증 스크립트도 별도의 임시 키를 씁니다. 이는 실제 영구 DB용 기본 키가 아닙니다.

## 기존 데이터 이전과 배포

암호화 마이그레이션은 `20261107_18`입니다. 새 키를 먼저 운영 환경에 설정하고, 기존 데이터를 쓰는 이전 서버를 중단한 유지보수 시간에 적용합니다. 새·이전 버전이 동시에 같은 DB에 쓰게 하지 않습니다.

기존 사용자가 있는 DB에서는 이전 서버/작업자의 쓰기를 중단한 뒤, 첫 이전 동안만 `DATA_ENCRYPTION_MAINTENANCE=1`을 설정해야 합니다. 이 표시가 없으면 DDL·데이터 변경 전에 중단하므로 자동 pre-deploy가 기존 서버가 읽지 못하는 암호문을 먼저 써 버리는 일을 방지합니다. 이전 완료 후에는 표시를 제거합니다. 표시 자체가 실행 중인 이전 서버를 정지시키지는 않습니다.

```sh
python -m alembic upgrade head
python scripts/encrypt_user_data.py
```

마이그레이션은 기존 값을 읽어 암호화하고 로그인용 검색 해시를 채웁니다. 비밀번호 해시는 바꾸지 않습니다. 암호화한 분석 JSON 안을 DB 쿼리로 읽지 않도록, 만료일만 별도 구조 컬럼에 보관합니다. 변환은 트랜잭션 안에서 수행되며 키가 없으면 변환 전에 중단합니다. 운영 원본 DB에는 로컬 테스트가 접근하지 않습니다.

확인 명령은 암호문을 인증·복호화해 읽을 수 있는지 검사하고 개수만 출력합니다. 평문이 남아 있으면 실패합니다. 암호화 이전 백업에도 개인정보가 있으므로 기존 백업의 보관·접근·암호화 정책을 별도로 적용해야 합니다. 애플리케이션 필드 암호화는 과거 백업을 소급 변경하지 않습니다.

암호문을 다시 평문으로 풀어 저장하는 downgrade는 제공하지 않습니다. 롤백이 필요하면 암호문을 이해하는 이전 호환 코드 또는 승인된 복구 절차를 사용합니다. 키를 잃으면 저장된 내용을 복구할 수 없으므로 비밀 저장소에서 별도 복구 정책을 마련합니다.

## 키 교체

1. `DATA_ENCRYPTION_KEYS`를 `새 키,기존 키`로 설정합니다. 검색 키는 유지합니다.
2. 기존 키로 읽을 수 있는 상태에서 다음 명령으로 저장된 암호문을 새 키로 다시 씁니다.
3. 검사와 서버 재시작이 끝나고, 관련 백업 복구 정책도 확인한 다음 기존 키를 제거합니다.

```sh
python scripts/encrypt_user_data.py --rotate
python scripts/encrypt_user_data.py
```

`DATA_LOOKUP_KEY`를 임의로 교체하면 로그인 검색이 달라지므로 별도의 재색인 이전 없이 변경하지 않습니다. 암호화 키와 검색 키를 서로 같은 값으로 설정하면 거부합니다.

사용 라이브러리는 [cryptography의 Fernet/MultiFernet](https://cryptography.io/en/stable/fernet/)이며, ORM 경계의 변환은 [SQLAlchemy TypeDecorator](https://docs.sqlalchemy.org/en/20/core/custom_types.html)를 사용합니다.
