# Safety Gate

현재 graph의 safety_level과 runtime confirmation 처리를 재사용한다. `safety/safety_gate.py`는 전이의 등급을 반환하는 규칙 기반 코드이며, 전 서비스의 보안 검증이 완성됐다는 뜻은 아니다.

| 행동 | 정책 | 앱·서버의 책임 |
|---|---|---|
| 일반 메뉴 탐색 | LOW_RISK 안내 | 서버는 존재하는 대상만 제시, 앱은 하이라이트 |
| 설정 변경 | graph에 따른 확인·안내 | 확인 필요 시 guide와 승인 결합, 탭·드래그는 사용자 수행 |
| 스크롤 | 기존 계약상 앱 접근성 실행 허용 | 대상·범위 검증, 실행 결과와 새 화면 보고 |
| 결제·송금·인증정보·개인정보 입력 | 자동 수행 금지 | 지원 안내와 민감 최종 행위를 분리 |
| 유효하지 않은 좌표·사라진 대상 | 새 화면 요구 | 추측 좌표로 실행하지 않음 |
| 동의 없는 외부 화면 분석 | 전송 차단 | 동의·마스킹 모두 검사 |

## 구현할 승인 계약

승인은 인증된 사용자·세션·guide ID·화면/전이 version·유효시간에 결합한다. 현재 요청에는 accepted/rejected만 있고 승인 토큰과 유효시간이 없으므로 강화가 필요하다. 승인 이후 화면이 달라지면 재검증한다. 이미 소비한 승인은 재사용하지 않는다.

## 검증 사례

- 동일 guide 승인 재사용 → 두 번째 적용 없음.
- 다른 사용자·세션의 승인 → 거절.
- 확인 대기 중 대상 화면 변화 → fresh observation 재검증.
- 금지 행위가 AI 출력으로 들어옴 → 사용자 승인 여부와 무관하게 자동 실행 차단.
- 허용되지 않은 명령 타입·좌표 → 앱으로 전달하기 전 거절.

이 사례는 후속 인수 기준이며 이번에 전부 구현·통과한 테스트 목록이 아니다.
