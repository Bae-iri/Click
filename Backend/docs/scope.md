# 기능 범위와 책임

아래 표는 1주 차 조사 기준이다. **F11 인증·F02 본인 접근·F04 입력 제한·F05 메모리 세션 소유권은 2주 차에 구현**했으며 최신 완료·미완료 구분은 [2주 차 결과](week2.md)를 따른다.

## 제품 기준

Click은 사용자의 목표와 현재 화면을 이해해 다음 행동을 안내하는 모바일 사용 지원 서비스다. 현재 README의 제품 대상은 Android 설정, 쿠팡, 정부24다. 실제 runtime 검증 범위는 글자 크기 증가 시범 흐름이며, 나머지 앱을 구현 완료로 간주하지 않는다.

탭·드래그는 사용자에게 안내한다. 기존 FE/BE 계약에서 스크롤은 접근성 서비스가 제한적으로 실행한다. 결제·송금, 비밀번호·인증번호·개인정보 자동 입력은 지원 범위에서 제외한다. 구매·서류 발급은 안내 대상이며 민감한 최종 행위의 자동 수행을 의미하지 않는다.

## 기능 목록

| ID | 기능 | 현재 상태 | 최종 완료 조건 |
|---|---|---|---|
| F01 | 서비스 상태 확인·개발 실행 | 기존 health + 이번 ready/실행 스크립트 | 실행 재현, DB 장애를 readiness로 식별 |
| F02 | 사용자·UI 프로필 | 기존 CRUD·개인화 구현 | 인증된 본인만 조회·수정·삭제, DB 재시작 후 유지 |
| F03 | 목적별 동의·행동 이벤트 | 기존 구현 | 철회 즉시 반영, 허용 메타데이터만 저장, 삭제 검증 |
| F04 | 목표·화면 요청 접수 | 기존 turn API | 입력 크기·형식·소유권 검증 후 처리 |
| F05 | 안내 세션·중복 요청 관리 | 기존 메모리 구현 | 재시작 복구, 동시 요청 직렬화, 변경된 본문 재사용 거절 |
| F06 | 목표 해석·화면 판별·UI 매칭 | 기존 시범 runtime | 확정된 모든 task에 대한 정상·미지원·모호한 요청 검증 |
| F07 | 안내·재관찰·완료 검증·재계획 | 기존 시범 runtime | 실제 상태 변화에 근거한 완료, 재시도 상한, 취소·만료 |
| F08 | 안전 검증 | 기존 graph 규칙 | 확인의 대상·유효시간·중복 사용 검증, 금지 행동 차단 |
| F09 | 개인정보·Vision | 부분 구현 | 서버에서 마스킹 강제, 동의 없는 외부 전송 차단, 삭제 정책 |
| F10 | 작업 이력·사용자 피드백 | 구현 예정 | 본인 이력만 조회, 원문 없이 최소 결과 저장 |
| F11 | 인증·접근 제어 | 구현 예정 | 토큰 검증·만료·타인 접근 거절. 현재 users 생성은 회원가입이 아님 |
| F12 | 운영·배포 | Compose에 PostgreSQL 정의 존재 | 모니터링·복구·부하 검증·배포 절차 재현 |

## 역할 구분

| 담당 | 소유하는 책임 | 다른 구성요소와의 계약 |
|---|---|---|
| Android | 권한·입력·화면 수집·오버레이·사용자 확인·스크롤 결과 | fresh tree와 행동 이벤트 전송, guide를 화면에 표시 |
| Backend | HTTP 검증·인증·세션·DB·멱등성·개인정보 경계·오류 응답 | runtime DTO 변환, 검증된 guide만 반환 |
| AI-Agent | 목표 typing·화면 분류·매칭·검증·재계획·guide 생성 | 유한한 명령 타입 반환, 추측으로 완료 처리하지 않음 |

## 설계를 진행하기 위한 결정안

- FastAPI/Pydantic/SQLAlchemy/Alembic을 유지한다. 기존 코드와 테스트를 재사용한다.
- 개발은 SQLite 파일 DB, 운영 후보는 기존 Compose의 PostgreSQL이다.
- 신규 앱 연동은 `/api/v1/agent/turn`으로 통일한다. 레거시 `/sessions`는 기존 호환용이다.
- 우선 단일 서버 프로세스로 개발한다. 세션 공유·동시성 구현 후에만 worker를 늘린다.
- 계정 인증은 별도 인증 주체와 사용자 매핑 계층으로 설계한다. 로그인 제공자는 아직 확정하지 않는다.

## 제품 결정이 필요한 사항

| 항목 | 작업용 제안 | 확정 시점·영향 |
|---|---|---|
| 앱별 지원 task | 설정 변경 / 상품 탐색·구매 안내 / 서류 탐색·발급 안내를 각각 목록화 | 2주 시작 전; AI graph 수와 앱 검증량 결정 |
| 인증 방식 | 기존 앱의 로컬 계정을 서버 인증으로 오인하지 않고 별도 설계 | F11 착수 전; 토큰 발급·사용자 매핑 |
| 개인정보 보존 기간 | 원본 화면·대화 저장 기본 해제, 결과 메타데이터만 보존 후보 | 영속화·외부 공개 전; 삭제 배치 및 동의 문구 |
| 서버 완성 평가 수치 | 아래 개발 계획의 인수 조건을 기반으로 목표 동시 사용자·응답시간 확정 | 부하 테스트 설계 전 |
| 배포 환경·예산·최종 마감 | 8주 계획을 기준으로 작업량 산정 | 배포 구성 및 주차 재배치 |

이 항목들은 제안 상태로 남겨두고 공통 서버 기반 개발은 진행할 수 있다. 확정되지 않은 task를 임의로 구현 완료 처리하지 않는다.
