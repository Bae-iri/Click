## 개인정보 처리 범위

1. HTTP 크기·스키마·인증 검사 후 runtime 진입 시 새 입력 객체로 정제한다.
2. 자연어 목표·Tree text/content_description·OCR/요소 text의 알려진 패턴을 마스킹한다. 입력 필드 내용은 패턴과 관계없이 버린다.
3. 원본 screenshot은 runtime에 보존하거나 외부에 보내지 않는다. 이미지 마스커를 설치한 것은 아니다. 검증할 수 없는 이미지 경로를 차단한 구현이다.
4. 외부 embedding에는 마스킹된 원문도 보내지 않는다. 코드에 등록된 graph 키워드·동의어에 해당하는 용어만 추출하여 전송한다. API 키가 없으면 기존 로컬 scorer를 사용한다.
5. 응답 debug와 trace는 구조적 진단만 남긴다. DB 응답 재전송에도 현재 필터를 적용한다. 기존 3주 차 DB 최소화·개인화 동의 확인은 유지한다.

정규식은 임의의 이름·주소·모든 개인정보를 탐지하는 보장이 아니다. 따라서 외부 텍스트 전송은 별도 용어 allowlist로 제한했다. 기기에서 만든 node/session/request ID와 생성된 안내 문구는 여전히 관리 대상이다. ID에 개인정보를 넣지 않는다. 내부 메모리의 목표 해석 결과까지 완전한 익명 데이터라고 간주하지 않는다.

`user_consented`는 현행 Vision 입력 계약의 동의 값이다. 인증 사용자·목적·정책 버전에 결합된 외부 이미지 처리 동의 체계는 아직 구축하지 않았으므로 이미지 외부 처리는 계속 비활성화한다.

## 앱 계약 변경

- `session_version` / `expected_version`, 같은 요청의 정확한 재전송 규칙은 3주 차와 동일하다.
- `step` / `total_steps`는 graph 기반 예상 진행 정도다. 실제 탭 횟수나 고정된 4단계가 아니다. 대체 경로·재계획에서 값이 달라질 수 있으며 0/0은 계산할 수 없는 목표다.
- `screenshot_base64`는 호환상 수신하지만 폐기한다. `redaction_applied=true`여도 이미지 외부 처리는 활성화되지 않는다. 접근성 정보 또는 동의된 온디바이스 OCR 요소를 보낸다.
- `metadata.debug`의 원본 label·provider 문자열·자유 텍스트가 제거된다. 앱은 `guide_command`로 표시하고 debug를 업무 로직에 사용하지 않는다.
- UI 이벤트 `screen_name`은 등록된 graph state ID 또는 null이다. 화면 제목·사용자 입력은 금지한다.
- UI 이벤트 `metadata`는 `step`, `duration_ms`, `attempt_count`(0~86400000 정수)와 `explanation_depth`(concise/normal/detailed)만 허용한다. 알 수 없는 키·중첩 값은 422다.

## 시간 제한·실패 처리

`AGENT_TURN_TIMEOUT_SECONDS=20`이며 양수이면서 lease 시간(기본 60초)보다 짧아야 한다. 시간 초과 시 `504 / AGENT_TIMEOUT`, 한 프로세스의 실행 슬롯 4개가 모두 사용 중이면 `503 / SERVICE_UNAVAILABLE`을 반환한다. 새 안내를 표시하지 않고 같은 ID·같은 본문으로 제한된 간격의 재시도를 한다. 세션 취소·만료 등 409/410은 기존 규칙을 따른다.

runtime은 격리된 메모리 상태에서 실행하고 DB 저장은 성공적으로 반환된 경우에만 요청 처리 측에서 수행한다. timeout 후 lease를 해제하므로 재시도할 수 있으며 늦은 결과는 저장되지 않는다. Python 스레드 자체를 강제 종료하지는 않는다. 늦은 작업이 실제 종료할 때까지 슬롯을 차지하고 추가 작업은 제한한다. provider 소켓 제한과 전체 응답 대기 제한을 함께 적용한다. DB·네트워크 전체 요청 시간을 강제로 제한하는 기능은 아니다.

embedding 응답은 256 KiB, 차원은 최대 8192의 유한 숫자 배열로 제한하며 잘못된 응답·차원 불일치·외부 장애는 로컬 fallback으로 처리한다. 임베딩 캐시는 runtime당 최대 128개다. 실제 외부 provider 호출은 이번 로컬 검증에서 사용하지 않았다.

## 보존·정리

trace는 메모리에서 최대 100건, 기본 900초다. 기록·조회 시 만료 항목을 제거하며 별도 타이머는 없다. 신규 turn은 요청마다 runtime을 생성하므로 정상 요청 간 trace를 공유하지 않는다. 로그 파일 회전·외부 수집기의 보존 정책은 운영 설정 대상이다.

UI 이벤트 개발용 보존 기본값은 24시간이다. 실제 DB를 명시한 Backend 디렉터리에서 다음 명령을 실행한다.

```powershell
python scripts/cleanup_ui_events.py --retention-seconds 86400
```

`DATABASE_URL`이 없으면 실행하지 않는다. 이벤트 상세만 지우며 누적 UI 프로필은 유지한다. 주기 실행과 최종 제품 보존 기간은 아직 확정하지 않았다. 사용자 탈퇴 시 관계 데이터 삭제는 기존 구현을 유지한다.

## 남은 통합 범위

- 신규 지원 앱/task는 팀이 목록을 정한 후 추가한다. 이번 작업은 기존 graph를 사용하는 공통 처리 기반이며 새로운 앱 지원 완료가 아니다.
- 실제 PostgreSQL·Docker·Android·클라우드 검증.
- 승인과 특정 안내 명령 결합, 개인정보 동의 철회·삭제의 전체 경로 통합 검증.
- 서버 이미지 마스킹을 도입하려면 별도 구현·검증 후 외부 처리 경로를 설계한다.
- 레거시 `/api/v1/sessions`의 영속화·시간 제한은 이번 범위에 포함하지 않는다. 신규 앱은 `/agent/turn`을 사용한다.
