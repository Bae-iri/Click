# 런처에서 앱 찾기

일반 앱 작업의 `open_app` 안내와 자동 앱 진입에서 같은 `LauncherAppSearch`를 사용합니다.
현재 앱을 바로 실행할 수 있는 기존 경로는 유지하며, 런처에서 탐색할 때 다음 순서로 진행합니다.

1. 현재 화면에 유일하게 확인되는 앱 아이콘을 선택합니다.
2. 없으면 앱스 버튼 또는 위쪽 스와이프로 앱 서랍을 한 번 엽니다.
3. 각 페이지에서 접근성 클래스·리소스·폴더 설명으로 확인한 폴더를 엽니다.
4. 열린 폴더의 접근성 트리를 다시 읽습니다. 배경 아이콘과 닫힌 폴더 미리보기는 제외합니다.
5. 대상이 없으면 폴더 내부의 관측된 목록을 넘겨 확인하고, 뒤로 나온 뒤 다른 폴더와 페이지를 탐색합니다.
6. 동일 화면 반복·조작 결과 미확인·최대 40회 동작·45초 제한에 도달하면 직접 열기 안내로 전환합니다.

자동 조작이 꺼져 있으면 실제 탭·스와이프 없이 강조와 안내만 제공합니다.
자동 조작이 켜진 경우 매 동작 직전에 전면 앱·창·현재 노드·위치·키보드·잠금을 확인합니다.
앱 진입 완료는 대상 패키지가 실제 전면에 나타났을 때만 처리합니다.

## 기기 확인 시나리오

- 홈에서 바로 보이는 앱, 다른 홈 페이지의 앱, 앱 서랍에만 있는 앱
- 앱 서랍의 다음 페이지와 홈/서랍의 폴더 내부 앱
- 대상이 없는 폴더에서 나와 다음 폴더 탐색
- 같은 이름의 앱 두 개, 읽히지 않는 폴더, 서랍 없는 런처
- 탐색 중 일시정지·취소·요청 교체, 키보드 표시와 잠금
- 자동 조작 해제 시 안내만 수행하고 사용자의 화면 변경을 기다리는지

단위 테스트와 APK 빌드가 실제 삼성·Pixel 등 각 기기의 동작 확인을 대신하지는 않습니다.
폴더 구조를 접근성으로 노출하지 않는 런처에서는 내부 앱을 추측하지 않고 직접 이동을 안내합니다.
